# AGENTS.md

OpenReadout is one Rust binary that reads raw lab-instrument files, prints what is in them as JSON, exports them to open formats, validates them, and serves the same operations as MCP tools.

## Rules that are not negotiable

1. **Clean room.** Read `docs/legal/clean-room-policy.md` first. Never fetch, read or cite a vendor SDK, header, DLL or non-public specification. GPL/LGPL readers (Bio-Formats, libCZI, pylibCZIrw, bioio-czi, bioio-lif, readlif) may only be run as black boxes; never read their source while writing a parser. BSD/MIT readers (czifile, liffile, nd2) may be read as documentation.
2. **Own vocabulary.** Every public field or enum variant in a format crate must be listed in that format's vocabulary table in `docs/formats/<fmt>.md` (`cargo xtask vocab-check`). Do not emit identifiers you remember from vendor code; derive names from the file and the docs here.
3. **Provenance log.** Before adding or changing parsing logic, append to `docs/provenance/<fmt>.md`: date, corpus file ids used, prior art consulted (URL and license), and what was inferred from what.
4. **Never rewrite raw data.** Every write goes to a new file, is read back and verified, then renamed into place.
5. **No network in the binary.** Only `xtask` may use HTTP (`cargo deny check`). The one exception is the opt-in `mcp-http` feature, which listens on loopback and never connects out; release builds leave it off.
6. **Safe Rust** in format crates (`#![forbid(unsafe_code)]`). A malformed file must give a clean error, never a panic: use checked arithmetic and bounds-checked slices.
7. **Sign every commit** with `git commit -s` (Developer Certificate of Origin).

## Where things are

- `crates/` holds one crate per format family plus `openreadout-core` (traits, byte sources, the normalized model, the JSON envelope, exit codes) and `openreadout-cli` (the binary). Read a crate's `MAINTAINING.md` before changing it.
- Readers read through `openreadout_core::source` (`Input`, `Fs`), never `std::fs`.
- `docs/` is maintainer material: format notes and vocabulary (`docs/formats/`), provenance logs, the clean-room policy, `maintaining.md` and `architecture.md`. User documentation is the website in `book/` (Astro + Starlight): the pages are Markdown in `book/src/`, the home page, format list and JSON reference are in `book/site/`; see `book/README.md`.
- `corpus/manifest.toml` lists the public test files; `corpus/oracle/` holds ground truth from independent readers, generated by the Python project in `oracle/`.
- `skills/openreadout/` is the agent skill; `crates/openreadout-cli/` embeds a copy (`cargo xtask skill-parity --fix`).
- Version bumps go through `scripts/bump-version.sh`; releases follow `docs/release-process.md`.

## Commands

```bash
cargo build && cargo nextest run
cargo clippy --all-targets -- -D warnings && cargo fmt --check
cargo xtask vocab-check
cargo xtask corpus fetch --tier smoke                  # public test files (about 1 GB)
cargo test -p openreadout-corpus-tests --features corpus --profile corpus   # compare readers with ground truth
cargo xtask snapshot review                            # after golden-output tests fail
cargo xtask schema gen                                 # after changing a JSON output type
```

`cargo xtask --help` lists the other maintenance tasks; `docs/maintaining.md` explains when to use them.

## Conventions

- JSON output keys are stable. Add fields freely; renaming or removing one needs a `schema_version` bump.
- Exit codes: 0 ok, 1 error, 2 usage, 3 unknown format, 4 corrupt, 5 I/O, 6 unsupported feature.
- `info` reads headers only and must stay fast on multi-gigabyte files.
- Tag each normalized field with its provenance: `Source::{Spec,VendorImpl,PriorArt,Inferred}`.
- Every error carries a `hint` an agent can act on.
- Commit messages are Angular style: `feat(czi): ...`, `fix(lif): ...`, `docs: ...`.
