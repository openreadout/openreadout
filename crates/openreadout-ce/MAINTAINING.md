# Maintaining `openreadout-ce`

Capillary and chip electrophoresis: Applied Biosystems ABIF (`abif`: `abif.rs`, `build.rs`, `fragment.rs`, `sizing.rs`, `ladders.rs`, `fastq.rs`), Agilent Bioanalyzer XML exports (`agilent-bioanalyzer-xml`, `bioanalyzer.rs`) and TapeStation exports (`agilent-tapestation`, `tapestation.rs`); `chip.rs` holds what the two Agilent readers share. Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Notes: [docs/formats/abif.md](../../docs/formats/abif.md), [docs/formats/agilent-electrophoresis.md](../../docs/formats/agilent-electrophoresis.md); provenance in `docs/provenance/` under the same names.

## Decode pipeline

1. **Detect** (`lib.rs`): `ABIF` and a version 1.xx–3.xx (`abif::looks_like`); a `Chipset` root (`bioanalyzer::looks_like`) or a `File` root with `ScreenTapes` (`tapestation::looks_like`), plain or gzip (`plain_head`).
2. **ABIF**: `abif::parse` reads the 128-byte header and the directory into `Item`s (name, number, element type, data bytes); values are typed on demand (`shorts`, `numbers`, `text`, `date`, `time`). `build::build` decides the run kind (base calls `PBAS` or not) and makes the dye sets (`dyes`, `dye_set`: raw `DATA` 1–4/105, analysed 9–12/205, bases from `FWO_`), the run monitors (`DATA` 5–8), the base-call tables (`calls_table`) and the experiment facts.
3. **Sizing** (fragment runs, `fragment::size_run`): the instrument's size map (`SMap` 2) and peak table (`Peak` 1–25, `instrument_peaks`) when present; else `sizing::size_with`/`best_of` (peak finding, `match_ladder` dynamic programme, Local Southern). Both run when the instrument sized, and `extra.sizing_check` records how far apart they are.
4. **Agilent**: `bioanalyzer::parse` (roxmltree) reads samples, peaks, the per-sample standard curve and the base64 `ProcessedSignal`; `tapestation::parse` reads the XML and the `_Electropherogram.csv` lanes and sizes each lane against its ScreenTape's ladder after marker alignment. Both build one trace per well with `chip::sized_trace`.

## Invariants and checks

- Every directory entry's data is bounds-checked against the file; a data size that disagrees with its element count is a warning, an entry past the end an error finding (`abif::parse`). Files that do not start with `ABIF`, or with a version above 3.xx, are refused (exit 4, exit 6).
- A sized axis rises strictly: the Local Southern sizes are checked (`rising`), the instrument's map is cut to its longest rising run (`sized_range`), and chip traces drop samples that land on the same size.
- Bioanalyzer signals must hold `NumberOfSamples` float32 values; TapeStation CSV rows must have one cell per lane (exit 4 otherwise).
- Arrays and inputs are bounded (`MAX_ENTRIES`, `MAX_ABIF`, `MAX_EXPORT`, `MAX_TEXT`, the DP's state count).

## Debugging a new file

- `openreadout info FILE --view full --json` → `vendor` holds every ABIF tag by key (`DATA9`, `SMPL1`, `Peak12`); `openreadout info FILE --view structure` lists the directory with offsets.
- For sizing: `openreadout table FILE --table K` on the `size standard` table shows matched fragments and leave-one-out residuals; `traces[0].extra.sizing_check` compares this reader's sizing with the instrument's.
- Unit tests: `abif::tests::build` writes an ABIF file from items; `sizing::tests::run` makes a synthetic ladder run; `tapestation::tests` a two-lane export. Corpus: `tests/corpus/abif_oracle` (Biopython) and `tests/corpus/chip_oracle`.

## Fragile spots

- The `Peak` columns and `SMap` are not in the 2006 specification; their meaning comes from matching a PeakScanner export (provenance log). Columns other than those named are left out.
- Without `StdF`, the size standard is a best fit among the ladders of the standard's dye; GS500 and GS350 share fragments, and a run missing many peaks can fit the wrong one (`quality` in the ladder table).
- Time items: some Data Collection versions write values above 99 in the hundredths byte, which is therefore ignored.
- TapeStation sizing follows the rules that fit the instrument's stored peak sizes (linear with two markers, the logarithm of size with only a lower one); a new assay may need another rule.
- The Agilent corpus files are Agilent's demo runs on the `hold` tier: CI does not fetch them, so their comparison runs only where they are on disk.
