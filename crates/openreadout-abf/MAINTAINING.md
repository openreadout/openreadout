# Maintaining `openreadout-abf`

Axon Binary Format (`abf`: ABF 1 and ABF 2) and Axon Text File (`atf`) electrophysiology recordings. Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout and vocabulary: [docs/formats/abf.md](../../docs/formats/abf.md); how each field was derived: [docs/provenance/abf.md](../../docs/provenance/abf.md) (pyABF documentation, MIT, and the corpus; the Axon SDK was never consulted).

## Decode pipeline

1. **Detect** (`lib.rs` `AbfReader::sniff`): the signature `ABF ` (ABF 1) or `ABF2`. ATF has its own reader (`atf.rs` `AtfReader`, `looks_like_atf`: an `ATF <version>` first line).
2. **Header** (`file.rs` `AbfFile::open`): the first bytes pick the generation, and **this is where versions branch**: `parse_abf1` reads the fixed 6 KB ABF 1 header (fields at fixed offsets; pre-1.6 files lack the telegraph and 20-entry epoch tables), `parse_abf2` reads the 512-byte fixed header and then the section map at offset 76 (16-byte entries: block, size, count) and decodes the protocol, ADC, DAC, epoch, strings, tag and synch-array sections. Both produce one normalized `AbfFile` (channels with their scaling chain, sweeps, epochs, tags, the string table). All field access goes through `openreadout_core::bytes::Block` (bounds-checked accessors returning `Option`).
3. **Sweeps** (`file.rs` `layout_sweeps`): fixed-length sweeps split the data evenly (samples = channels × sweeps × samples per sweep); event-driven variable-length recordings (operation mode 1) take their sweep lengths and start times from the synch array.
4. **Values** (`file.rs` `channel_scaling`, `dataset.rs` `read_trace`): int16 or float32 samples, interleaved by channel, scaled by the per-channel gain chain (ADC range, resolution, instrument scale factor, signal gain, telegraph gain, offsets). The order of the factors is `scaling_order`.
5. **Dataset** (`dataset.rs` `AbfDataset`): one trace per file; `info` from the header only, `read_trace` reads one sweep window.

## Invariants and checks

- Every header field read is bounds-checked (`openreadout_core::bytes::Block`); a field past the buffer is `None`, and the caller decides whether that is corrupt (exit 4) or absent.
- `check` verifies: signature, version, operation mode, sample format and interval; that samples = channels × sweeps × samples per sweep (or the synch-array lengths) and that the data region ends inside the file; that every channel's scaling factors are finite and non-zero; that tags fall inside the recording. ATF: header counts, a number in every data cell, a constant time step.
- Refused (exit 6): old pCLAMP/Axotape files without an `ABF ` signature (CLPX, FTCX); ATF files whose first column is not time (GenePix results go to `genepix-gpr`).

## Debugging a new file

- `openreadout check FILE --report` and `openreadout info FILE --view full --json` → `vendor` shows the decoded sections by their ABF names; `openreadout info FILE --view structure` lists the section map with offsets and sizes (ABF 2).
- A new ABF 2 version usually adds a section or grows an existing entry size: compare `ls` of the new file with a corpus file of the same acquisition mode (`corpus/snapshots/abf.jsonl` lists the corpus's versions).
- `tests/synthetic.rs` builds ABF 1 and ABF 2 files byte by byte from the layout in the format note (`slot`, `put_*` helpers): the quickest way to pin a new field or reproduce a layout without a corpus file.
- The oracle is pyABF (`oracle/gen.py`, dispatch on `.abf`/`.atf`); it reads the same headers independently.

## Fragile spots

- **Scaling order.** The gain chain is multiplied in the order `scaling_order` gives; telegraph gains and the "instrument scale factor" were matched against pyABF output, not a specification. A new amplifier or telegraph mode shows up as values off by a constant factor.
- **Variable-length sweeps** (mode 1) depend on the synch array's time unit (the protocol section's synch time unit); a file whose synch array disagrees with the data length is reported, not guessed.
- **Pre-1.6 ABF 1**: epoch tables and telegraphs are simply absent; do not infer them.
- **ATF values** are the decimal text written by Clampfit (already rounded): exact agreement with an ABF of the same recording is not expected.
