# Maintaining `openreadout-igor`

WaveMetrics Igor Pro binary waves (`.ibw`, `.bwav`) and packed experiments (`.pxp`, `.pxt`), format `igor`. Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/igor.md](../../docs/formats/igor.md); provenance: [docs/provenance/igor.md](../../docs/provenance/igor.md) (WaveMetrics' technical notes TN003 and PTN003 and hex dumps of corpus files; `igor2` only as a black-box oracle).

## Decode pipeline

1. **Detect** (`lib.rs` `looks_like_wave`, `packed.rs` `looks_like_packed`): a binary wave by its version (1, 2, 3, 5) and a zero checksum over its headers; a packed experiment by a chain of record headers in the first 64 KiB that holds Igor's record kinds.
2. **One wave** (`wave.rs` `parse_wave`): byte order from the first byte, then the binary header and wave header of that version. **Versions branch here**: versions 1–3 use the 110-byte wave header, 16 bytes of padding and only a note (and a formula in version 3); version 5 uses the 320-byte header with four dimensions and the optional sections (formula, note, extended units, dimension labels, string indices). Every section is bounded by the wave's bytes (the file, or its record).
3. **Packed experiments** (`packed.rs` `walk`): the record chain, the data-folder stack (`FolderStart`/`FolderEnd`), superseded records skipped; `parse_variables` decodes variables records; history, recreation and procedure records are kept as text (the recreation's first line gives the Igor version).
4. **Model** (`dataset.rs` `parse_file`, `classify`): each numeric wave becomes a trace (one dimension, or two with labelled columns) or an image (two to four dimensions; labelled layers are channels, others Z); text and empty waves are vendor metadata. `read_trace` and `read_plane` read only the requested elements (`Wave::read_elements`, swapped to little-endian).

## Invariants and checks

- No offset is used before it is checked against the wave's bytes; a section that runs past them is a `Problem` and makes the wave `Unreadable` when it affects the data (`Wave::readable`).
- `check`: header checksums, wave type, point count against the dimension sizes and the data size, sections inside the wave, the record chain to the end of the file, data folders opened and closed, variables decoded, bytes after a binary wave.
- Refused: unknown wave types (`wave_type`, the wave is not exposed); complex integer images (exit 6 on `read_plane`).

## Debugging a new file

- `openreadout info FILE --view structure` lists every wave with its offset, type, dimensions and what it became, and every other record of a packed experiment; `info --view full --vendor --json` → `vendor.waves[]` has the header values, notes and labels, `vendor.variables` the variables.
- A file `igor2` reads but this reader does not: compare `oracle/igor_oracle.py`'s output (`ORACLE_OUT=/tmp/o oracle/.venv/bin/python oracle/gen.py --id x FILE`) with `info`.
- `tests/synthetic.rs` writes version-5 and version-2 waves in both byte orders and a small packed experiment from the format note.

## Fragile spots

- **Integer, unsigned, complex and 64-bit wave types** follow the bit pattern of TN003's list (2, 4 and 8 are seen in the corpus); no corpus file has one yet, and the assurance profile marks such waves unvalidated.
- **Versions 1 and 3** and **version-2 variables records** follow the published sizes only.
- **Which waves are traces**: two-dimensional waves become traces only when their columns carry labels; a wave of unlabelled sweeps in columns is an image. Instrument packages (NeuroMatic, Patcher's Pal) group sweeps in their own ways, which the reader does not reconstruct.
- Asylum Research AFM files append their own data after the last section; it is counted and skipped.
