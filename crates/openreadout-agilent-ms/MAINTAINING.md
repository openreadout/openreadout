# Maintaining `openreadout-agilent-ms`

Agilent MassHunter `.d` mass-spectrometry directories: Q-TOF, TOF, triple quadrupole and 6560 ion mobility (`agilent-masshunter`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/agilent-masshunter.md](../../docs/formats/agilent-masshunter.md); provenance: [docs/provenance/agilent-masshunter.md](../../docs/provenance/agilent-masshunter.md) (public MetaboLights data sets compared spectrum by spectrum with the depositors' mzML conversions, and the `MSScan.xsd` schema every data directory carries; no vendor library).

## Decode pipeline

1. **Detect** (`lib.rs` `is_masshunter_dir`): a `.d` directory with `AcqData/MSScan.bin` (ChemStation `.D` directories without it go to `openreadout-chrom`).
2. **Scan layout** (`layout.rs` `scan_layout_from_xsd`): the record layout of `MSScan.bin` is read from the `MSScan.xsd` next to it (`complex_type`, `flatten`, `with_offsets`); `layouts_from_fallback_schemas` covers directories without it. **The MSScan layout version is the main branch**: layout 5 (6400-series triple quadrupole: MRM, dynamic MRM, full, product-ion, neutral-loss, SIM; quadrupole profiles) and 6 (6200 TOF, 6500-series Q-TOF, B.05–B.10); `version <= 5` checks in `dataset.rs` pick quadrupole paths (`triple_quad`, `is_quad_points`, `quad_profile`).
3. **Index** (`layout.rs` `scan_file_header`, `read_record`; `dataset.rs` `records`): every scan record (time, MS level, scan type, TIC, base peak, block offsets into the peak and profile files), and `MSTS.xml` time segments.
4. **Spectra** (`layout.rs`): centroids in `MSPeak.bin` (`decode_peaks`), LZF-compressed profiles in `MSProfile.bin` (`lzf_decompress`, `decode_profile`, `decode_quad_profile`), per-scan m/z calibration in `MSMassCal.bin` (`mass_cal_values`, `Calibration`, `default_calibrations`). Ion mobility (6560): frame layout from its own XSD (`frame_layout_from_xsd`, `read_frames`, `decode_ims_profile`; `dataset.rs` `load_ims`).
5. **Device signals** (`layout.rs` `signal_directory`, `signal_block`): `*.cd` descriptors and `*.cg` data (pumps, UV, pressure) as traces.

## Invariants and checks

- Every accessor in `layout.rs` is bounds-checked (`None` or an error string, never a panic).
- `check`: `MSTS.xml` scan counts per time segment against the index; every spectrum block's offset and byte count against `MSPeak.bin`/`MSProfile.bin`; every scan's calibration record inside `MSMassCal.bin`; the first and last spectrum decode (profiles: counts sum to the recorded TIC); every device-signal block inside its data file.

## Debugging a new file

- `openreadout info RUN.d --view structure` lists the `AcqData` files; `openreadout spectra RUN.d` lists the index without decoding peaks; `info --view full --json` → `vendor` has the XML documents.
- A new acquisition software release usually changes `MSScan.xsd`: the reader follows the schema, so diff the new XSD with a corpus one first. `layout.rs` unit tests (`layouts_from_fallback_schemas`, `lzf_literal_and_backref`, `calibration_clamps_the_polynomial`) are the templates for new cases.
- Ground truth: the depositor's mzML as `oracle-export`; `oracle/gen.py --export run.mzML --id ID RUN.d` (the oracle needs the export).
- `tests/synthetic.rs` builds `AcqData` directories.

## Fragile spots

- Layouts other than 5, 6 and the 6560 ion-mobility layout are read through their own XSD but are unverified.
- Q-TOF profiles are checked only against the index (TIC sum, base-peak m/z): no export holds them; zero runs between peaks are dropped.
- Precursor m/z is each MS/MS scan's own value (ProteoWizard averages over scans sharing a precursor).
- Ion mobility: drift-bin spectra only; compressed drift-bin profiles and CCS values are not supported. DAD spectra and several auxiliary files are listed, not decoded.
