# Maintaining `openreadout-sif`

Andor SIF files (Andor Solis), format `andor-sif`. Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/andor-sif.md](../../docs/formats/andor-sif.md); provenance: [docs/provenance/andor-sif.md](../../docs/provenance/andor-sif.md) (hex dumps of corpus files and the documentation of `sif_parser`, BSD-3-Clause; `sif_parser` and `sifreader` as black-box oracles).

## Decode pipeline

1. **Detect** (`layout.rs` `looks_like_sif`): the 36-byte signature.
2. **Blocks** (`layout.rs` `parse`, `parse_block`): the signal block after the second line, then four flag lines, each `1` followed by another block (reference, background, live, source), then an optional XML trailer. In a block: the first line's values by position (10 and 2 binary bytes at fixed places), the end of that line found by the shape of the detector and size lines after it, the file name and user text by their lengths, then the axis names and the image structure **found by their shape** (`axes_at`) so the version-dependent lines in between never need counting. **Versions branch** only in what lies between the time stamps and the data (nothing, a `0` line, or a `1` line and one number per frame): the data start is the candidate after which the data ends at a flag line or the end of the file.
3. **Model** (`dataset.rs`): a block whose frames are single rows is a trace (one sweep per frame, the calibrated axis as channel 0 when calibrated); any other block is an image with frames as T.

## Invariants and checks

- The header is read into a bounded buffer (`MAX_HEADER`); every position is checked. Frames × frame pixels must equal the total the header declares and the sub-images' pixels the frame pixels, or the file is corrupt (exit 4).
- `check`: a block's data inside the file, the flag lines, time stamps that go backwards, bytes after the last block that are not XML.

## Debugging a new file

- `openreadout info FILE --view structure` lists each block's header and data with offsets; `info --view full --json` → `vendor.blocks[]` has the parsed values, the settings lines as text and the calibration, `vendor.xml` the trailer.
- A new SIF version usually changes the settings lines only, which the reader skips by shape; check that `axes_at` still finds the axis names (`settings_lines` shows what lay before them).
- `tests/synthetic.rs` writes a calibrated kinetic series with a background block and an image.

## Fragile spots

- **Block names** after the signal come from their position; nothing in the file names them.
- **Calibration** is applied to the 1-based column number, as `sif_parser` does; for a sub-image that does not start at the first detector column the axis may be offset (no corpus file shows which is right).
- The axis unit (nm for `Wavelength`, cm⁻¹ for `Raman shift`) and the meaning of most first-line values are inferred.
- `sif_parser` cannot read the live block of `nd_lum_image_no_glue.sif`; that block is compared by presence only.
