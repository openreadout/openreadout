# Maintaining `openreadout-epr`

Electron paramagnetic resonance data: Bruker BES3T (`bruker-bes3t`: `.DSC` descriptor + `.DTA` data, optional `.XGF`/`.YGF`/`.ZGF` axis files; `bes3t.rs`) and Bruker ESP / WinEPR (`bruker-esp`: `.par` + `.spc`; `esp.rs`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Notes: [docs/formats/bruker-epr.md](../../docs/formats/bruker-epr.md); provenance: [docs/provenance/bruker-epr.md](../../docs/provenance/bruker-epr.md).

## Decode pipeline

1. **Detect** (`lib.rs`, `params.rs` `is_descriptor`): a `.DSC` descriptor (`#DESC` layer) next to its `.DTA`, or a `.par`/`.spc` pair (`esp.rs` `sibling_par`, `members`); `.par` files are also recognised from their bytes.
2. **Parameters** (`params.rs`): `KEY value` lines with continuations (`logical_lines`), the descriptor's layers (`#DESC`, `#SPL`, `#DSL`, `#MHL`; `parse_descriptor`) and the `.par` keys (`parse_par`).
3. **BES3T data** (`bes3t.rs`): **the descriptor's format keys are the branch**: byte order (`BSEQ`), value format per point (`IRFMT`/`IIFMT`: integer or float widths; `Num`), real or complex (`IKKF`), dimensions (`XPTS`, `YPTS`, `ZPTS`), linear axes or axis files (`IGD` → `.XGF`). ASCII data (`IRFMT A`), N-tuple axes and mixed formats are refused.
4. **ESP / WinEPR** (`esp.rs`, `Flavour`): the `.spc` holds little-endian float32 (WinEPR) or big-endian int32 (ESP cw and pulse/2D); the flavour is decided from the `.par` keys.
5. **Shared** (`common.rs`): axes (`Axis`: magnetic field in G or mT, time in ns, …) and the experiment facts of the standard parameters (microwave frequency and power, modulation, gain, time constant, scans, temperature).
6. **Dataset**: one trace per data value of a point: one sweep per slice of the second and third dimensions, channel `intensity` (or `real`/`imaginary`), the abscissa in `extra.axis`.

## Invariants and checks

- The data file length must equal points × value size × (2 if complex) from the descriptor; axis files must hold one value per point; unsupported layouts exit 6 with an Xepr export hint.

## Debugging a new file

- `openreadout info FILE.DSC --view full --json` → `vendor` has every descriptor layer as text; the device layer (`#DSL`) is kept but not normalized.
- `tests/synthetic.rs` writes BES3T and ESP/WinEPR pairs; `params.rs` unit tests hold descriptor and `.par` examples (`descriptor_layers_devices_and_continuations`, `par_needs_known_keys`).
- Oracle: DeerLab's BES3T reader (MIT, vendored unchanged as `oracle/third_party/deerload.py`) through `oracle/series_oracle.py --deerload`; ESP/WinEPR against the depositor's exports.

## Fragile spots

- Values are returned as stored: no normalization by scans, gain, power or conversion time (Xepr's and EasySpin's optional scalings differ).
- ESP vs WinEPR flavour detection relies on `.par` keys and sizes; an unusual ESP variant could be read with the wrong byte order — `check` compares the value count with the file size.
- The manipulation history (`#MHL`) is counted, not interpreted: processed data sets are read like acquired ones.
