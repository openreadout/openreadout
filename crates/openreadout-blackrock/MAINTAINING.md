# Maintaining `openreadout-blackrock`

Blackrock Neurotech NSx continuous files and NEV event files (`blackrock`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/blackrock.md](../../docs/formats/blackrock.md); provenance: [docs/provenance/blackrock.md](../../docs/provenance/blackrock.md) (Blackrock's public NEV/NSx specification LB-0023; Neo, BSD-3, read as documentation for spec 2.1).

## Decode pipeline

1. **Detect** (`lib.rs` `BlackrockReader::sniff`): the 8-byte signature, which is also **where the versions branch**: `NEURALSG` (NSx spec 2.1), `NEURALCD` (2.2/2.3), `BRSMPGRP` (3.0, 64-bit timestamps, PTP one-sample packets), `NEURALEV`/`BREVENTS` (NEV). A directory is a session (`session_files`, `open_session`).
2. **NSx** (`nsx.rs` `parse_nsx`): basic header, `CC` channel headers (spec 2.2+; 2.1 has only channel ids), then `index_packets` walks the data packets (header byte 0x01, timestamp, sample count) without reading samples. Each packet becomes a sweep (`NsxSweep`); PTP files (one sample per packet) are merged into gap-free sweeps.
3. **NEV** (`nev.rs` `parse_nev`): basic header, extended headers (waveform headers, labels, filters), fixed-size data packets. Spec ≥ 2.3 or 3.x have wide timestamps (`wide_timestamps`).
4. **Scaling** (`nsx.rs` `scaling_and_labels`, `cc_scaling`): digital-to-analog from the `CC` header's min/max digital and analog values. Spec 2.1 has no scaling in the NSx: it comes from the NEV with the same name (`dataset.rs` `companion_factors`).
5. **Datasets** (`dataset.rs`): `NsxDataset` is one trace (packets are sweeps); `NevDataset` is one table of packets (spikes with waveforms, digital events, comments).

## Invariants and checks

- NSx header length must equal 314 + 66 × channels (2.2+); every data packet starts with 0x01 and its declared sample count lies inside the file (else truncation, exit 4 from `check`).
- NEV header length = 336 + 32 × extended headers; the data section is a whole number of fixed-size packets; timestamps do not decrease within a recording.
- PTP files: every packet timestamp is read and gaps are reported as findings.

## Debugging a new file

- `openreadout info FILE --view structure` lists the packets (NSx) or packet kinds (NEV) with offsets; `info --view full --json` → `vendor` has the basic and extended headers by their spec names.
- A spec 2.1 file read without its `.nev` has unscaled values: `report` shows the assumption in `assurance.assumed`.
- `tests/synthetic.rs` writes NSx 2.2/3.0 and NEV files from the spec layout; add a case there for a new packet or header variant.

## Fragile spots

- **Spec 2.1 scaling** borrows factors from the companion NEV; a session with several NEVs picks the one with the same stem.
- **PTP (3.0) merging** into sweeps relies on timestamps advancing by exactly one sample period; clock jitter splits sweeps.
- NEV packet kinds other than spikes, digital events and comments (video sync, tracking, buttons, configuration, log) are counted, not decoded (`known_gaps`).
