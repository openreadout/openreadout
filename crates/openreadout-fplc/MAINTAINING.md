# Maintaining `openreadout-fplc`

Cytiva ÄKTA / UNICORN protein-purification results: UNICORN 3–5 `.res` files (`cytiva-unicorn-res`) and UNICORN 6/7 result exports (`cytiva-unicorn-zip`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/cytiva-unicorn.md](../../docs/formats/cytiva-unicorn.md); provenance: [docs/provenance/cytiva-unicorn.md](../../docs/provenance/cytiva-unicorn.md).

## Decode pipeline

1. **Detect** (`lib.rs`): `.res` by its header (`UnicornResReader`); the export `.zip` by its members (`export.rs` `is_unicorn_export`: `Result.xml` and chromatogram documents).
2. **`.res`** (`res.rs` `parse`): a directory of named blocks (`descriptors`, `split_block_name`, `block_kind`): text blocks (method, logbook), curve blocks, event lists. Curves are fixed-interval samples with a volume per sample (`curve`); fraction, injection and logbook marks are event records (`event_records`).
3. **Export** (`export.rs` `Export::open`): XML documents, nested zips of .NET-serialized XML (`nrbf.rs`: the two [MS-NRBF] records UNICORN uses, a string and a float array) and one nested zip of float arrays per curve (`zip_curve`, `curve_points`); UNICORN's own peak tables (`peak_table`) and method variables.
4. **Model** (`model.rs` `Parsed`): both readers fill the same model: curves (one trace each; channel 0 values, channel 1 retention volume in ml), event lists, peak tables, facts, the vendor tree. `CurveKind::classify` names UV (with wavelength), conductivity, pH, pressure, temperature, concentration, flow.
5. **Dataset** (`dataset.rs` `FplcDataset`, `Backing`): one dataset for both; curves decode lazily.

**Where variants branch**: the `.res` layout text (`UNICORN 3.10` in both corpus files) and the export's UNICORN version and system model (`system_model`, `technique_of`).

## Invariants and checks

- `.res`: header and block directory parse; every block's byte range lies inside the file.
- Export: zip directory, `Result.xml` and the chromatogram documents parse; each curve's nested zip is indexed; CRC-32 is checked on every member read.
- Full `check` decodes every curve: counts volumes and values, flags non-finite numbers and volumes that run backwards.

## Debugging a new file

- `openreadout info FILE --view structure` lists `.res` blocks (name, kind, offset, size) or the export's members; `info --view full --json` → `vendor` has the method text and XML.
- `tests/synthetic.rs` builds `.res` block directories and export zips; `nrbf.rs` unit tests cover the two NRBF records.
- Oracle: `oracle/fplc_oracle.py` (see the format note); curves are compared with UNICORN's text export where one exists.

## Fragile spots

- **`.res` is validated on two files** (ÄKTAprime 2009, Ettan LC 2017), both `UNICORN 3.10`; other UNICORN 3–5 systems are expected to share the layout but have no public sample.
- The run start is derived from the header's end time minus the curves' duration; a sub-sample start offset is read as milliseconds (unvalidated).
- Binary configuration blocks (CONFIG, CALIB, column choice, template, fraction collector) are listed by `ls`, not decoded.
