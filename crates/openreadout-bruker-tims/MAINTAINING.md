# Maintaining `openreadout-bruker-tims`

Bruker timsTOF acquisitions (`.d` directories; TDF and TSF; `bruker-tdf`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout and formulas: [docs/formats/bruker-tdf.md](../../docs/formats/bruker-tdf.md); provenance: [docs/provenance/bruker-tdf.md](../../docs/provenance/bruker-tdf.md) (frame layouts as documented by timsrust, Apache-2.0; calibration models fitted against vendor-library conversions and cross-checked with the documentation of mzdata and rustims).

## Decode pipeline

1. **Detect** (`dataset.rs` `kind_of`): a `.d` directory with `analysis.tdf` (+ `analysis.tdf_bin`: frames of trapped-ion-mobility scans) or `analysis.tsf` (+ `analysis.tsf_bin`: one line spectrum per frame). **TDF versus TSF is the first branch** (`TimsKind`).
2. **Metadata** (`sqlite.rs`): the `.tdf`/`.tsf` files are SQLite databases, read by a minimal pure-Rust reader written from the public file-format document (b-tree rows, records, write-ahead log `open_wal`, `wal_frames`). Tables read: `GlobalMetadata`, `Frames`, the precursor and PASEF/DIA selection tables, `MzCalibration`, `TimsCalibration`, MALDI spots (names as stored; see the format note).
3. **Frames** (`frame.rs`): zstd-compressed frame blobs (`decode_tdf_frame`; `TimsCompressionType` 1 uses LZF, `decode_tdf_frame_lzf`); TSF line and profile spectra (`decode_tsf_spectrum`, `decode_tsf_profile`).
4. **Calibration** (`calibration.rs`): **model types branch here**: `MzCalibration` types 1 and 2 (type 2 adds a polynomial correction faded outside its range) and `TimsCalibration` type 2 for 1/K0, applied per frame with the frame's temperatures. Other model types fall back to the acquisition-range approximation and say so (`CalibrationStatus`).
5. **Spectra** (`dataset.rs`): per MS1 frame (summed over scans), per DDA-PASEF precursor (`PrecursorRecord`, `Selection`) and per DIA-PASEF window; chromatograms from the `Frames` table (TIC, base peak) as traces.

## Invariants and checks

- `sqlite.rs`: every read is bounds-checked; a damaged database is an error, never a panic.
- `check_headers`: the SQLite database (and its write-ahead log) reads; every frame's blob offset lies inside the binary file.
- `check`: also decodes every frame blob and compares its scan and peak counts with the `Frames` table; evaluates every frame's calibration models; checks that every PASEF selection and DIA window names an existing frame and scan range.

## Debugging a new file

- `openreadout info RUN.d --view structure` lists the database tables with row counts and the binary file; `info --view full --json` → `vendor` has `GlobalMetadata` and the calibration rows.
- `openreadout report RUN.d` shows the calibration state (`assurance.calibrations`): `not_applied` means a model type the reader does not know yet.
- `oracle/timsrust-oracle` (a separate Rust workspace, Apache-2.0 timsrust) and vendor-library conversions are the ground truth; `tests/fuzz_regressions.rs` replays malformed databases and blobs.

## Fragile spots

- Calibration model types other than m/z 1/2 and 1/K0 2 are approximations (tens of ppm off) — the notes and `check` say so.
- prm-PASEF frames (MsMsType 10) are summed whole, not split per target window (no public file).
- TimsCompressionType 1 frames hold more scans than `Frames.NumScans`; all are read.
- The SQLite reader supports ordinary rowid tables only; a schema change to WITHOUT ROWID tables would need new code.
