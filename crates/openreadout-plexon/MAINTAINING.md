# Maintaining `openreadout-plexon`

Plexon PLX ("Plexon 1") and PL2 electrophysiology recordings (`plexon`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/plexon.md](../../docs/formats/plexon.md); provenance: [docs/provenance/plexon.md](../../docs/provenance/plexon.md) (PLX from Neo, BSD-3, read as documentation; PL2 from hex dumps of corpus files only — Plexon's PL2 reader is a DLL that is neither opened nor run).

## Decode pipeline

1. **Detect** (`lib.rs` `PlexonReader::sniff`): `PLEX` (PLX) or the PL2 signature (`pl2.rs` `looks_like_pl2`). **The generation is the first branch**: PLX and PL2 have separate parsers and datasets.
2. **PLX** (`plx.rs` `parse_plx`): file header, spike/event/continuous channel headers, then `walk_blocks` over every data block header (PLX has no index). **Versions branch here**: header fields and gain formulas depend on the file version (`version >= 103`, `>= 105`, `>= 106`; `continuous_scale`, `spike_scale`); versions 100/101 assume a preamplifier gain of 1000. `runs` groups a channel's blocks into gap-free runs.
3. **PL2** (`pl2.rs` `parse_pl2`): file header, channel-header records, then `walk_records` over the data records up to the end-of-recording record at the footer offset. The footer index and device settings are not read.
4. **Datasets** (`dataset.rs` `PlxDataset`, `pl2_dataset.rs` `Pl2Dataset`): continuous channels on one sample grid share a trace; gap-free runs are sweeps; spike waveforms and events are two tables.

## Invariants and checks

- PLX: signature; file and channel headers inside the file; every data block of a known type with its samples inside the file; per-channel timestamps never go backwards; gaps reported.
- PL2: signature; every channel-header record's type and length; every data record inside the file and the walk ending on the end-of-recording record; per-unit spike counts in the channel headers equal the spikes found; analog timestamps never go backwards.

## Debugging a new file

- `openreadout info FILE --view structure` lists headers and block/record runs; `info --view full --json` → `vendor` has the headers.
- `tests/plx_synthetic.rs` and `tests/pl2_synthetic.rs` build files from the format note.
- `info` walks every block header: slow on very large PLX files is expected, not a hang.

## Fragile spots

- **PL2 is not oracle-validated**: derived from two public files; no independent reader could be run. Treat any PL2 variant change as unvalidated until a second source confirms it.
- PLX gain formulas per version follow Neo's documentation; version 100/101 preamplifier gain is an assumption.
