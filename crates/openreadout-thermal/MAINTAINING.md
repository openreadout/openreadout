# Maintaining `openreadout-thermal`

Thermal-analysis instrument files: NETZSCH Proteus (`netzsch-ngb`: `.ngb-ss3`, `.ngb-bs3`, `.ngb-ds3`, `.ngb-sd7`, `.ngb-dla`, `.ngb-cla`; `ngb.rs`) and TA Instruments Q-series data files read by Universal Analysis (`ta-universal-analysis`: `.001`, `.002`, …; `ta.rs`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Notes: `docs/formats/{netzsch-ngb,ta-universal-analysis}.md`; provenance logs of the same names.

## Decode pipeline

1. **Detect** (`lib.rs`): an NGB zip with `Streams/stream_N.table` members and a measurement extension (`ngb_extension`; analysis `.ngb-taa` and state `.ngb-od7` files are refused); a TA file by its UTF-16 header (`ta.rs` `looks_like`).
2. **NGB** (`ngb.rs`): each stream is a small database of serialized tables: records with typed fields (`parse_record`, `Field`), table openings (`table_open`), strings, scalars and arrays. Stream 1 and 2 hold metadata (`meta`: instrument, operator, sample, date) and channel definitions (`channel`); later streams hold the runs (`stream_runs`). **Instrument kinds branch here** (`kind_of`: STA/TG, DSC, dilatometer) and channel ids map to our vocabulary (unknown ids become `channel_<id>` without a unit).
3. **TA** (`ta.rs` `parse`): a UTF-16 text header (signals, instrument, serial, operator, sample, size, method), a form-feed, the signal count, then float32 records ended by a sentinel record (`signal`, `signal_names`).
4. **Dataset**: one trace per run: channel 0 `time` (s, irregular axis), then one channel per stored signal, values as stored (the DSC signal in µV, not converted with the sensitivity calibration).

## Invariants and checks

- NGB: streams 1 and 2 must exist (otherwise it is not a measurement file); every record inside its stream; gaps between records are only allowed where they are known to be benign (`benign_gap`).
- TA: the data block's signal count must equal the header's; a time signal must exist and be in a known unit.

## Debugging a new file

- `openreadout ls FILE` lists the NGB streams and tables; `dump --json` → `vendor` has the metadata records.
- `ngb.rs` unit tests (`records_and_table_opens`) and `tests/synthetic.rs` pin the record grammar; a new Proteus version usually adds a field type or table.
- Oracle: Proteus/UA text exports of the same measurement through `oracle/series_oracle.py --export`.

## Fragile spots

- The NGB record grammar is reverse-engineered; unknown field types end the record cleanly but may hide channels.
- The DSC sensitivity calibration, temperature program, PID settings and calibration tables are not decoded.
- Channel meanings come from ids seen in the corpus; a new instrument may carry ids without a known meaning.
