# Maintaining `openreadout-spectro`

Optical and vibrational spectroscopy, one module per format: Bruker OPUS (`bruker-opus`, `opus.rs`), Thermo OMNIC `.spa`/`.spg` (`thermo-omnic`, `omnic.rs`), Renishaw WiRE `.wdf` (`renishaw-wdf`, `wdf.rs`), PerkinElmer `.sp` (`perkinelmer-sp`, `pesp.rs`), JASCO Spectra Manager `.jws`/`.jrs` (`jasco-jws`, `jasco.rs`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Notes and provenance: `docs/formats/<format id>.md` and `docs/provenance/<format id>.md`.

## Decode pipeline

1. **Detect** (`lib.rs`, one reader per format): OPUS by `0A 0A FE FE` on any numbered extension; OMNIC by `Spectral Data File` (or its series signature); WDF by `WDF1`; PerkinElmer by `PEPE`; JASCO by the compound-file streams (`is_compound_jws`) or the flat `L~S ` header (`header_is_jasco`).
2. **Parse** (each module's `parse`) into the shared model `common.rs` `Parsed`: spectrum sets (spectra sharing an x axis and y quantity; one trace each, one sweep per spectrum), per-spectrum tables (positions, times), maps (spectra on a grid → one image, one channel per spectral point), attachments (a white-light image), experiment facts and the vendor tree. **Formats and their versions branch in the modules**:
   - OPUS: a block directory (`BlockType`: parameter, data, data-status, history, series blocks), parameter blocks (`parse_params`), data blocks paired with their data-status blocks (`pairs_with`, `make_set`); 3D series follow brukeropus's layout.
   - OMNIC: key-addressed header entries (`Key`, `header`), x and y axes (`x_axis`, `y_axis`), history text; `.spg` holds several spectra.
   - WDF: a chain of named blocks (header, spectra, x list, origins, map geometry, white-light JPEG with EXIF, property sets `psets`); the header's version words.
   - PerkinElmer: nested blocks of typed members (`tree`, `walk`).
   - JASCO: two containers (compound file via `openreadout_core::cfb`, `parse_compound`; flat, `parse_flat`) and channel kinds (CD, HT voltage, absorbance, fluorescence; `ChannelKind`).
3. **Dataset** (`common.rs` `SpectroDataset`): one dataset for every format; values are read lazily through the byte source (`read_values`, `Rows`, `Stored`).

## Invariants and checks

- `check_headers`: the block directory and headers parse; every spectrum's byte range lies inside the file. Full `check` reads every spectrum and flags non-finite values.
- Blocks of unknown type, report blocks and data blocks without a data-status block (OPUS) are listed by `ls`, not decoded.

## Debugging a new file

- `openreadout info FILE --view structure` lists the blocks (OPUS directory, WDF chain, PE nested blocks, JASCO streams) with offsets and sizes; `info --view full --json` → `vendor` has the parameter blocks by their stored names.
- `tests/synthetic.rs` (OPUS, OMNIC, WDF, PE) and `tests/jasco_synthetic.rs` build files from the notes.
- Oracles (`oracle/spectro.py`, run as black boxes): brukeropus (MIT) for OPUS with brukeropusreader (GPL, black box) as a second opinion, SpectroChemPy for OMNIC, renishawWiRE (MIT) for WDF, specio for `.sp`; JASCO has `oracle/jasco_oracle.py`. Vendor text exports (`oracle-export`) are compared by `openreadout-corpus-tests/tests/spectro.rs`.

## Fragile spots

- OPUS 3D series (rapid scan, time-resolved) have no public file; OPUS parameter names are kept as stored.
- OMNIC timestamps (`omnic_time`) and WDF FILETIMEs (`filetime_iso`) are epoch conversions validated on a few depositors.
- WDF maps: stage coordinates and map geometry combinations beyond the corpus's line scans and area maps are unvalidated.
- `common.rs` is shared by all five formats: a change there moves every spectroscopy snapshot.
