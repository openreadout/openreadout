# Maintaining `openreadout-zarr`

OME-Zarr / OME-NGFF 0.1–0.5 on Zarr v2 and v3, directory and zip stores (`ome-zarr`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/ome-zarr.md](../../docs/formats/ome-zarr.md); provenance: [docs/provenance/ome-zarr.md](../../docs/provenance/ome-zarr.md) (open specification, https://ngff.openmicroscopy.org).

## Decode pipeline

1. **Detect** (`lib.rs` `sniff_dir`, `ngff_text`): a directory (or zip) whose root group attributes carry NGFF metadata (`.zattrs` / `zarr.json`).
2. **Store** (`store.rs` `Store`): a directory (`DirStorage`) or a zip archive (`ZipStorage`, the store at the archive root or inside one top-level folder), through the shared zip reader in `openreadout_core::zip` (keys matched exactly: Zarr keys are case-sensitive).
3. **Group metadata** (`ngff.rs`, pure functions of JSON): **NGFF versions branch here** (`version_of`, `multiscales`, `transforms`, `axes_scales_and_versions`): 0.1–0.3 have implicit axes, 0.4 axis objects and coordinate transformations, 0.5 is Zarr v3 with metadata under `ome`. `plate`/`well` give HCS layouts; `bioformats2raw.layout` gives one image per series with `OME/METADATA.ome.xml` parsed by `openreadout-tiff`'s OME-XML parser.
4. **Arrays** (`dataset.rs` `array_meta`, `read_level`, `read_region`): through the pure-Rust `zarrs` crate. `codecs.rs` registers decode-only replacements for `blosc`, `zstd` and numcodecs `lz4` backed by `openreadout-codecs` (no C libraries in the static builds). Axis roles map t/c/z/y/x (`axis_roles`); other axes are read at index 0.

## Invariants and checks

- `check`: the store opens; the NGFF group metadata (multiscales, plate, well, bioformats2raw) parses; every listed dataset has array metadata whose rank matches the axes; pyramid levels do not grow in x or y; the omero channel count matches the c axis. A store still being written is recognised (`growing_state`, `write_state`).
- Unsupported codecs exit 4 on read and are reported by `check`; unsupported data types (strings, structured, datetime) exit 6; float16 is widened, bool is uint8 0/1.

## Debugging a new file

- `openreadout ls STORE` lists groups, arrays and chunks; `dump --json` → `vendor` holds the group attributes as written.
- A new NGFF version: `ngff.rs` is pure JSON → add a unit test with the new `.zattrs`/`zarr.json` next to `axes_scales_and_versions`.
- `tests/fixtures.rs` reads the committed stores in `tests/fixtures/` (and their oracle JSON); `oracle/make_zarr_fixtures.py` regenerates them.

## Fragile spots

- The codec pipeline is an assurance feature (`internal`): a store with a codec combination the corpus has not validated is `unvalidated` for pixels.
- NGFF 0.6 coordinate systems and affine/rotation transforms are reported, not applied; scale and translation are composed (multiscales after dataset, NGFF 0.4); label images are exposed after the others (`add_label_images`), so image indices of stores with labels grew; OME-TIFF export skips them unless `--image` names one.
- `openreadout-zarr` uses a hidden item of `openreadout-tiff` (the OME-XML parser): a patch release must not break it (docs/release-process.md).
