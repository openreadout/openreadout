# Maintaining `openreadout-waters`

Waters MassLynx `.raw` directories (`waters-raw`): full-scan spectra of TOF instruments (SYNAPT, Xevo, Vion) with the m/z calibration applied, MS/MS precursors, lock-spray reference functions, MRM/SIR intensities of triple quadrupoles, per-scan statistics, PDA and analog channels. Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/waters-raw.md](../../docs/formats/waters-raw.md); provenance: [docs/provenance/waters-raw.md](../../docs/provenance/waters-raw.md) (public MetaboLights and PRIDE acquisitions compared spectrum by spectrum with the depositors' mzML conversions; rainbow's public documentation pages for the 2-, 6- and 8-byte layouts; no vendor library).

## Decode pipeline

1. **Detect** (`dataset.rs` `is_waters_dir`): a `.raw` directory with `_HEADER.TXT` and `_FUNC*.DAT` files.
2. **Text metadata** (`layout.rs` `parse_header_txt`, `parse_extern`, `dataset.rs` `read_text`): `_HEADER.TXT` (`$$ key: value`), `_extern.inf` (per-function scan settings), `_INLET.INF`, calibration lines (`Calibration::parse`: polynomial `T0`, `T1`, identity).
3. **Functions** (`layout.rs` `parse_functions`, `function_type`): one 416-byte block per function in `_FUNCTNS.INF`: MS scan, MS/MS, MRM, SIR, PDA, reference (lock spray, `is_reference_code`).
4. **Scan index** (`layout.rs` `parse_idx`): `_FUNCnnn.IDX` records of 22 or 30 bytes (`idx_record_len_for`) with offset, count, TIC, retention time and flags.
5. **Values** (`layout.rs`): **the value layout is the main branch**: 12-byte values (`decode_value12`, `decode_mass27`, `decode_intensity12`), 8- and 6-byte (`decode_value8`, `decode_value6`), 4- and 2-byte MRM/SIR (`decode_packed32`, `decode_packed16`); `infer_bytes_per_value` picks it from the record and data sizes. Index flag 0x100 means values are stored calibrated; otherwise the `Cal Function n` polynomial is applied (`stored_calibrated`).
6. **Dataset** (`dataset.rs` `WatersRawDataset`): spectra (`spectrum_at`, `visit_scan_headers`), MRM/SIR as tables and traces, PDA and analog channels (`_CHROnnn.DAT`, `_CHROMS.INF`) as traces, statistics (`_FUNCnnn.STS`, `parse_stats_layout`) in scan headers.

## Invariants and checks

- Every accessor in `layout.rs` is bounds-checked; malformed input yields `None` or an empty list.
- `check`: `_HEADER.TXT` present and parsed; IDX files are whole 22- or 30-byte records whose offsets and counts lie inside the DAT and whose retention times do not decrease; one 416-byte block per function; 4-byte MRM values sum to the stored TIC; `_CHROnnn.DAT` is whole (time, value) pairs after the 128-byte header; the first and last spectrum of every scanning function decode.

## Debugging a new file

- `openreadout info RUN.raw --view structure` lists every member file and function; `openreadout spectra RUN.raw` shows the index without decoding peaks.
- A new instrument usually means a new function type or value layout: `openreadout check RUN.raw --report` names the function types and layouts (the assurance fingerprint); `layout.rs` has unit tests with rainbow's documented examples (`rainbow_examples`).
- The ground truth is a depositor mzML (`oracle-export`); `oracle/gen.py --export … RUN.raw` (use `uv run --group chrom` for rainbow-based chromatography oracles).
- `tests/synthetic.rs` builds directories for each layout.

## Fragile spots

- Lock-mass correction is not applied (reported per reference scan); ion-mobility drift bins (`_funcNNN.cdt`) are not decoded (drift-summed spectra are returned and say so).
- MRM 4-byte values are scaled so each scan sums to the IDX TIC (rainbow reports twice these values): a documented choice validated against exports.
- PDA functions are unscaled absorbance counts; `.EE`/`.CMP` files and the third word of 12-byte values are listed, not decoded.
