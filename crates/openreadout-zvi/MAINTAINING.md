# Maintaining `openreadout-zvi`

Zeiss AxioVision ZVI files (`zvi`; OLE2 / MS-CFB compound files). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/zvi.md](../../docs/formats/zvi.md); provenance: [docs/provenance/zvi.md](../../docs/provenance/zvi.md) (the container from Microsoft's public MS-CFB specification; ZVI streams, value encoding and tag ids from hex dumps of corpus files compared with Bio-Formats' output, run as a black box).

## Decode pipeline

1. **Detect** (`lib.rs` `ZviReader::sniff`): the compound-file signature plus the ZVI stream names.
2. **Container**: the shared MS-CFB reader (`openreadout_core::cfb`) gives the storages and streams.
3. **Items** (`dataset.rs` `item`, `find_header`): each `Image/Item(n)/Contents` stream holds typed values, a 28-byte raw-image header and the samples of one plane; `Image/Item(n)/Tags/Contents` is its tag list.
4. **Values and tags** (`tags.rs`): a value is a 2-byte OLE Automation `VARENUM` type code and its data (`read_value`); a tag list is version, count, then (value, tag id, attribute) triples (`parse_tags`).
5. **Images** (`dataset.rs` `build_image`): the index tags of every item place it at (c, z, t) (and position, mosaic tile); image-level tags give the scale, channel names and colours (`zvi_color`), dates (`ole_date`). **Variants branch here**: the pixel format (`sample_layout`: 16-bit grey 4 and 3 × 16-bit colour 8 validated; 8-bit grey and 3 × 8-bit colour inferred; others exit 6) and the index tags used by time series, multi-position and mosaic files.

## Invariants and checks

- `check`: the compound-file header, FAT and directory parse; every `Contents` stream has a raw-image header and its full sample block, reachable through its sector chain; every (c, z, t) of every image has exactly one item; item sizes match the image.

## Debugging a new file

- `openreadout info FILE --view structure` lists the storages and streams; `info --view full --json` → `vendor` has every tag by id with its value.
- To identify an unknown tag, compare its values across corpus files (the method of the provenance log), never from vendor code.
- `tests/synthetic.rs` builds compound files with items and tag lists.

## Fragile spots

- Time series (tag 2821), multi-position and mosaic files are placed by index tags that no public file exercises; a note says so in `info`.
- Scale units other than micrometres (code 76) are not interpreted; uncalibrated axes have no physical size.
- Layers, annotations and document summary property sets are listed, not decoded.
