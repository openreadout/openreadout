# Maintaining `openreadout-lif`

The Leica LIF family (`lif`): LIF, LIFEXT, LOF, XLIF, XLEF, XLCF, XLLF. Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout and vocabulary: [docs/formats/lif.md](../../docs/formats/lif.md); provenance: [docs/provenance/lif.md](../../docs/provenance/lif.md) (liffile, BSD-3, read as documentation; readlif and bioio-lif are GPL oracles only).

## Decode pipeline

1. **Detect** (`container.rs` `looks_like_lif`, `looks_like_lifext`, `looks_like_lof`; `xlef.rs` `looks_like_xml_container`): the three binary containers share a header block (`0x70`, length, `0x2A`, UTF-16 text); XLIF/XLEF/XLCF/XLLF are plain XML (UTF-8 or UTF-16).
2. **Containers** (`container.rs` `LifFile::open`): **container kinds and versions branch here**. LIF/LIFEXT: the XML header, then a chain of memory blocks (`walk_blocks`; version 2 has 64-bit block lengths, version 1 32-bit, `parse_version`). LOF: the literal `LMS_Object_File`, one payload, then its XML (`open_lof`). XML members (`xlef.rs`): XLEF/XLCF/XLLF list other files (`Element/Children/Reference/@File`, `resolve_reference`); an XLIF's `Memory` children name the files holding its frames (`.lof` payloads or TIFF/JPEG/PNG images).
3. **XML model** (`xml.rs` `parse_images`): the element tree → image nodes with dimensions (`DimID`: X, Y, Z, T, lambda, rotation, XT slices, tiles 10), channels (LUT colours, bytes and resolution), hardware settings (objective, legacy hardware `legacy_hardware`, acquisition mode), FLIM info (`parse_flim`), tile-scan positions (`parse_tile_scan`), time stamps.
4. **Storage** (`storage.rs`, `dataset.rs` `Builder`): every image node is resolved at open to a `Storage`: byte ranges in one or more files (a LIF block is one segment; an XLIF block one segment per frame). LIFEXT sidecars attach to their `.lif` (`attach_sidecar`, `attach_parent`).
5. **Pixels** (`dataset.rs` `read_plane`): plane offsets from the dimension strides (`geometry`, `plane_offset`); lambda folds into channels; half floats widen exactly (`widen_half`); tile scans are stitched (`mosaic.rs`: stage positions, flips and swap, rounded half up, later tiles win — reproduces LAS X's merge bit for bit on the corpus pair); XLIF image frames are decoded (`frames.rs`, RGB remapped by channel tag).

## Invariants and checks

- `check`: header markers and `block_len == 2 × xml_len + 5`; well-formed XML; every memory block header valid and the chain ends exactly at the end of the file; every image's block exists and is at least as large as its geometry; `Memory/@Size` equals the payload; every XLEF/XLCF/XLLF reference and XLIF frame file exists and reads; a LIFEXT's `ChildrenOf/@MemoryBlockID` names an image in its `.lif`.
- Refused (exit 6): FLIM/TCSPC raw photon data (FALCON); BMP and multi-page OME/Aivia TIFF frames.

## Debugging a new file

- `openreadout info FILE --view structure` lists the memory blocks (id, offset, size) and the XML member files; `info --view full --json` → `vendor` is the XML as JSON.
- `xml.rs` unit tests hold small XML headers for each case found (`parses_images_flim_and_tiles`, `hardware_settings_mode_and_legacy_objective`, `timestamps_as_hex_text_or_filetime_halves`); add the new element there first.
- `tests/fixtures.rs` reads the committed LIF/LOF/XLEF fixtures in `tests/fixtures/` against their oracle JSON (`tests/fixtures/make_fixtures.py`).
- Oracles: liffile (primary) and readlif (second opinion).

## Fragile spots

- LOF, XLEF and XLCF come from liffile's documentation and synthetic files; XLLF and TIFF-frame XLIF are validated on two LAS X 3.7 depositors; JPEG/PNG frames are unvalidated (a note says so).
- Tile scans are stitched without registration or blending: LAS X "Merged" images may differ where it registered overlapping tiles.
- Rotation (DimID 6) and XT/T-slice (7/8) addressing is validated on synthetic files only; version-1 containers are untested.
