# Maintaining `openreadout-neuralynx`

Neuralynx Cheetah/Pegasus files: NCS continuous channels, NEV events, NSE/NST/NTT spike waveforms (`neuralynx`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/neuralynx.md](../../docs/formats/neuralynx.md); provenance: [docs/provenance/neuralynx.md](../../docs/provenance/neuralynx.md) (Neuralynx's public "Data File Formats"; Neo, BSD-3, read as documentation).

## Decode pipeline

1. **Detect** (`lib.rs` `looks_like_neuralynx`, `has_header_keys`): the 16 KiB text header with `######` and known `-Key` lines, plus the extension; a directory is a session (`session_files`).
2. **Header** (`header.rs` `parse_header`): decode the text (`decode_text`: Latin-1/UTF-8), key/value entries, dates in the several styles Cheetah and Pegasus write (`iso_from_slash_time`, `iso_from_comment`). **Versions branch here**: the application name and version (`application`) change date styles, key names and the timestamp clock.
3. **Records** (`records.rs`): `FileKind` from the extension and record length (NCS 1044 bytes, NEV 184, NSE/NST/NTT by channel count); `index_continuous` walks NCS record heads (timestamp, channel, sample rate, valid-sample count) and splits them into gap-free `Segment`s (`segments_from`).
4. **Datasets** (`dataset.rs` `NeuralynxDataset`): NCS is one trace whose sweeps are the segments, scaled by the header's `ADBitVolts`; NEV and spike files are tables (`read_events`, spike records with waveforms).

## Invariants and checks

- The header is present and parses; `-RecordSize` agrees with the record type; file length = header + whole records (a cut-off record is truncation, exit 4 in `check`).
- NCS records: valid-sample count ≤ 512, one channel number, increasing timestamps; gaps split segments and are reported; the sampling rate implied by timestamps is compared with the header's.

## Debugging a new file

- `openreadout info FILE --view structure` shows the header and record ranges; `info --view full --json` → `vendor` has the header keys as written.
- Date or rate surprises: look at `extra.timestamp_rate_hz` in `info` and the header's application version.
- `tests/synthetic.rs` builds headers and records; the header-style cases are unit tests in `header.rs` (`parses_header_styles`, `dates`).

## Fragile spots

- **Clock**: pre-Cheetah-5 files count timestamps with a 1 MHz clock that does not match the header's sample rate; the reader reports the implied rate, it does not resample or correct.
- **Segmenting** on gaps uses the median record duration (`median`); partial records split segments.
- Video tracker (`.nvt`) and raw data (`.nrd`) files are not read.
