# Maintaining `openreadout-vsi`

Olympus/Evident cellSens VSI files (cellSens, VS120/VS200 slide scanners) with their `_<name>_/stack<id>/frame_t*.ets` tile files; a standalone `.ets` opens too (`vsi`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/vsi.md](../../docs/formats/vsi.md); provenance: [docs/provenance/vsi.md](../../docs/provenance/vsi.md) (no specification: record tree and ETS layout derived from corpus files; tag meanings identified by comparison with Bio-Formats, run as a black box).

## Decode pipeline

1. **Detect** (`tiff.rs` `looks_like_vsi`, `ets.rs` `looks_like_ets`): the `.vsi` is a TIFF with one IFD (a small JPEG preview, `preview_info`) followed by the record tree.
2. **Record tree** (`tree.rs` `TagTree::parse`): record sets ("volumes") of typed records chained by offsets relative to the volume start; records may nest volumes (`volume_header`, `children`).
3. **Metadata** (`meta.rs` `read_meta`): tag numbers identified by differential analysis → stacks (`StackMeta`), dimensions (`DimKind`: Z 1, T 2, channel 4), channels, objective, camera exposure, calibration with unit factors (`unit_factor`, `quantity_in`).
4. **Tiles** (`ets.rs` `EtsFile`): SIS header, ETS header (`EtsHeader`: sample type, compression, tile size, extra dimensions), tile table (`load_table`: column, row, level, extra coordinates), tiles decoded raw, JPEG or JPEG 2000 (`decode_tile`). **ETS versions and compressions branch here** (versions 0x00030003/5/6 seen).
5. **Images** (`dataset.rs` `build_image`, `read_level_region`): one image per stack that has an ETS file; tiles stitched per pyramid level; unstored tiles filled with the ETS background value; the tile-grid offset (record 2410) places coarser levels (`level_origin`).

## Invariants and checks

- `check`: every record set has its signature, links point forward inside the file, record counts match; the `_<name>_` directory exists and each stack directory has a readable `frame_t*.ets`; ETS headers, tile table and every tile's bytes inside the file; tile coordinates within the image and pyramid; one tile per image decodes; dimension sizes in the `.vsi` agree with the ETS header.
- ETS sample types other than 8- and 16-bit unsigned, and compressions other than raw, JPEG and JPEG 2000, exit 6.

## Debugging a new file

- `openreadout info SLIDE.vsi --view structure` lists the record tree summary, stacks and ETS files; `info --view full --json` → `vendor` has every record under its numeric tag (only identified tags are named).
- An unknown dimension kind is exposed as T with a note and a `check` warning: that note is the signal of a new acquisition type.
- No integration tests in this crate beyond unit tests (`tree.rs` `parses_nested_records`, `reports_bad_links`; `ets.rs` `write_small_ets`, `reads_header_and_table`); the corpus with the Bio-Formats second opinion pins it.

## Fragile spots

- Everything is derived without a specification from 27 corpus files (11 with pixel data); tags not yet identified live only in `vendor`.
- JPEG tiles decoded with jpeg-decoder may differ by a few grey levels from other decoders (the corpus compares with a tolerance).
- Coarser levels with an offset tile grid can differ by one pixel from Bio-Formats (rounding versus truncation, documented).
- Planes above 4 GiB are read by region or pyramid level only.
