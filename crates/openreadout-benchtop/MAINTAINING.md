# Maintaining `openreadout-benchtop`

Formats: `nanodrop`, `qubit`. Start with [docs/maintaining.md](../../docs/maintaining.md) for the project-wide process.

## Decode pipeline

`NanoDropReader` and `QubitReader` (`src/lib.rs`) read the whole file (exports are kilobytes),
decode it (`text::decode`: UTF-16 with a byte-order mark, UTF-8, else Latin-1) and hand the text
to `nanodrop::parse` or `qubit::parse`. Each first decides the layout from the first lines
(`sniff`, the same function detection uses), then splits the lines into a header row and data
rows and calls `table::build`. `build` looks every header up in the reader's `role` map: our
column name and unit, a concentration whose unit comes from the `Units` column after it, a date
(with an optional separate time column), or text. Headers the map does not know keep a name made
from the header (`model::slug`). The result is a `model::Parsed`: the columns, the optional
spectra and the instrument facts. `SampleTableDataset` (`src/model.rs`) serves it as table 0 and,
with spectra, trace 0, and builds the experiment model.

Variants branch in three places: the layout (`sniff`), the role maps (one header spelling per
software version), and `parse_eight`/`parse_spectra` for the two layouts with spectra.

## Invariants and checks

- Detection is by content only and always `definite`: these readers come before the plate reader,
  whose generic sniff would take any delimited text.
- Every table column has as many rows as the table; a cell that is not a number is NaN in a
  number column (empty, `NaN`, `ERROR`), and words in place of a concentration go to
  `<name>_note`.
- A concentration column has one unit: rows in another mass-per-volume unit are converted
  (`units_converted`), other units become NaN (`unit_not_recognised`).
- Refused: files over 64 MiB (exit 6), a spectrum export whose blocks do not share one evenly
  spaced axis (exit 6), more rows or points than any instrument writes and a head that is no known
  layout (exit 4). Ragged rows and unreadable spectrum lines are `check` findings.

## Debugging a new file

Start with `openreadout info FILE` (the layout is `format_version`) and `openreadout table FILE`.
A header the role maps miss shows as a slug name with the header as its label; add the spelling
to `role` in `src/nanodrop.rs` or `src/qubit.rs` and a row to the vocabulary table in
`docs/formats/`. Compare with allotropy: `uv run --only-group plate --with pandas python
oracle/benchtop_oracle.py --id ID FILE` in `oracle/`, then
`CORPUS_FORMAT=nanodrop,qubit cargo test -p openreadout-corpus-tests --features corpus --test corpus`.
The unit tests in each module hold a minimal example of every layout.

## Fragile spots

- Date order. Exports write dates month first, but the Qubit 4 test date of the corpus is day
  first; its run id (an ISO date) settles the order. Without such a hint an ambiguous date is
  read month first and flagged `date_order_assumed`.
- The Qubit Flex 1.5 header names fewer columns than its rows hold; the reader names the
  untitled ones after the Flex's Excel export. A later version may title them, or add others.
- The NanoDrop Eight's `Sample Id` is a measurement id, not the sample; `Sample Name` is the
  sample. The RNA layout calls them `UID` and `Sample`.
- All development files of a layout come from one depositor (allotropy's test data, partly edited
  for testing), so spellings from other software versions are likely to appear.
