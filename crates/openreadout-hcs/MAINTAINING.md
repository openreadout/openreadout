# Maintaining `openreadout-hcs`

High-content screening plates, three plate-imager families, each an index file plus one TIFF per plane: Revvity/PerkinElmer Harmony and Columbus exports and Opera `.flex` (`opera-harmony`), Molecular Devices ImageXpress / MetaXpress (`imagexpress`), Yokogawa CellVoyager CV7000/CV8000/CQ1 (`cellvoyager`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Shared plate model: [docs/formats/hcs.md](../../docs/formats/hcs.md); per format: `docs/formats/{opera-harmony,imagexpress,cellvoyager}.md` and their provenance logs.

## Decode pipeline

1. **Detect** (`lib.rs`, one reader per family; `index_of`, `definite`): the index file (or a folder holding it): `Index.idx.xml` / `Index.xml` / `Index.ref.xml` / `ImageIndex.ColumbusIDX.xml` (`harmony.rs` `looks_like_harmony`), `.flex` files (`flex.rs` `is_flex_name`), an `.HTD` (`imagexpress.rs` `looks_like_htd`) or a plate folder without one (`plate_folder_without_htd`), `MeasurementData.mlf` (`cellvoyager.rs` `looks_like_cellvoyager`).
2. **Index parsing** — **the families and their versions branch here**:
   - Harmony (`harmony.rs` `parse`): the index is streamed with quick-xml (a 384-well index is ~47 MB); plate header, channel descriptions and one record per plane (`Rec`); HarmonyV5/V7 namespaces; Columbus indexes with multi-page TIFF or `.flex` planes.
   - Opera `.flex` (`flex.rs`): a multi-page TIFF whose first IFD carries tag 65200, the Flex XML describing plate, well and every page (`Image@BufferNo`).
   - ImageXpress (`imagexpress.rs` `parse_htd`, `parse_name`): the HTD key/values and the plane file names `<plate>_<well>[_s<site>][_w<wave>][<GUID>].tif` in optional `TimePoint_<t>/`, `ZStep_<z>/` folders; calibration and channel names from the planes' MetaMorph metadata (decoded by `openreadout-tiff`).
   - CellVoyager (`cellvoyager.rs` `parse`): `MeasurementData.mlf` records, `MeasurementDetail.mrf` plate and channel geometry, the `.mes` setting, `.wpi`/`.wpp` plate files.
3. **Plate model** (`model.rs` `PlateBuilder`): readers push `RawPlane` records in any order; the builder sorts wells row by row, fields by number, Z and T by recorded index, and marks missing planes. Every field of view is one image.
4. **Planes** (`planes.rs`): each plane is a TIFF page decoded by `openreadout-tiff`; one file is opened per read, nothing is kept open. `info` opens at most one plane file (for the sample type).

## Invariants and checks

- `check_headers`: every plane file present has a readable TIFF header with the plate's image size and sample type, and its strips lie inside the file; missing plane files are findings per well (a partial copy of a plate is common).
- Index parsers reject other XML and truncated indexes cleanly (`rejects_other_xml_and_truncation`, `malformed_records_are_clean_errors`).

## Debugging a new file

- `openreadout info PLATE --json` → `plate` (wells, fields, completeness); `ls` lists the index and plane files; `info --view full --json` → `vendor` has the index header and channel descriptions.
- A new Harmony version: a namespace or element change in `Index.idx.xml` — the unit tests in `harmony.rs` hold small indexes of each version seen (`parses_a_small_index`, `channel_descriptions_from_maps`).
- `tests/synthetic.rs` builds plates of each family; `oracle/hcs.py` is the oracle (tifffile on the plane files, the index read independently).

## Fragile spots

- The older `Index.ref.xml` layout with gzip-compressed planes (`.tiff.gz`) is not read; FLIM planes and sequence/fk/fl variants in Harmony file names are not told apart.
- The Z step is the PositionZ difference of the first field's first two planes.
- Flat-field profiles and skew-crop parameters are listed by `dump`, not applied; standalone `.flex` time series and compressed pages are not validated on a public file.
