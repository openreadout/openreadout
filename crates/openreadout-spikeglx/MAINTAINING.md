# Maintaining `openreadout-spikeglx`

SpikeGLX recordings: a `.meta` text file beside a headerless interleaved int16 `.bin` (Neuropixels imec AP/LF, NI-DAQ and OneBox streams; `spikeglx`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/spikeglx.md](../../docs/formats/spikeglx.md); provenance: [docs/provenance/spikeglx.md](../../docs/provenance/spikeglx.md) (the SpikeGLX authors' public metadata documentation).

## Decode pipeline

1. **Detect** (`lib.rs` `looks_like_meta`, `sniff_input`): a `.bin` with a `.meta` beside it, or the `.meta` itself; a run directory (`is_probe_dir_name`, `session_files`) is a session with one trace per stream.
2. **Metadata** (`meta.rs` `parse_meta`): `key=value` lines; the saved-channel subset (`parse_subset`, `saved_channels`) and the channel counts by kind (`counts`: neural, LF, sync/status, digital).
3. **Scaling** (`meta.rs`): **stream kinds and probe types branch here**: `imec_scale` for Neuropixels probes (gain from the imro table for NP 1.0 `np1_imro_gains`, fixed gains for NP 2.0 `fixed_gain`, `imMaxInt` from the metadata or `default_max_int`), `ni_scale` for NI-DAQ and OneBox (`nidq_gains`). imec to µV, NI/OneBox to V; status (SY) and digital (XD) words are returned raw.
4. **Dataset** (`dataset.rs` `SpikeGlxDataset`): one `.bin` stream is one trace with a single sweep; samples are read by frame (`frame`, `samples`).

## Invariants and checks

- `.meta` parsed: stream type known; the saved-channel list agrees with `nSavedChans` and the acquired layout.
- `.bin` size is a whole number of samples of `nSavedChans` int16 values and equals `fileSizeBytes`.

## Debugging a new file

- `openreadout info FILE --view full --json` → `vendor` is the `.meta` as written; the probe type (`imDatPrb_type`) decides the scaling path.
- `tests/synthetic.rs` writes `.meta`/`.bin` pairs for each stream kind.

## Fragile spots

- `imMaxInt` for probe types other than NP 1.0 and 2.0 (types 21/24) is inferred from the ProbeTable when the metadata omits it: a new probe type is the most likely source of wrong scaling.
- Streams of a run are not aligned on their sync pulses; probe geometry and imro settings are kept in `dump`, not normalized.
