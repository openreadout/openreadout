# Maintaining `openreadout-xrd`

X-ray diffraction scans: PANalytical XRDML (`panalytical-xrdml`, `xrdml.rs`), Bruker DIFFRAC `.raw` (`bruker-raw`, `raw.rs`), Bruker DIFFRAC.SUITE `.brml` (`bruker-brml`, `brml.rs`), Rigaku `.ras` and `.rasx` (`rigaku-ras`, `rigaku-rasx`, `rigaku.rs`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Notes: [docs/formats/xrd.md](../../docs/formats/xrd.md); provenance: [docs/provenance/xrd.md](../../docs/provenance/xrd.md). XRDML is a public XML schema.

## Decode pipeline

1. **Detect** (`lib.rs`, one reader per format): the XRDML root element (`xrdml.rs` `looks_like`), `RAW1.01`/`RAW4.00` (`raw.rs` `looks_like`), a zip holding DIFFRAC XML (`brml.rs` `is_brml`), a `*RAS_DATA_START` text (`rigaku.rs` `looks_like_ras`) or a `.rasx` zip (`is_rasx`).
2. **Parse** into scans (`common.rs` `Scan`: abscissa, intensities, axis name and unit; `ScanAxis`) — **each format and version is its own branch**:
   - XRDML: every scan of every measurement: axis positions (listed or start/end, `Positions`), counts or intensities, counting times, attenuation factors, wavelength, tube, optics.
   - Bruker `.raw`: `RAW1.01` (DIFFRACplus, `v3`) and `RAW4.00` (DIFFRAC.SUITE, `v4`, `range4` with variable-length range headers; `r.stride == 8` data); start, step, scanned drive, step time, tube settings, wavelengths, user and sample.
   - `.brml`: every data route of every raw-data member, its columns as the file's data views name them.
   - Rigaku: `.ras` header blocks (`ras_blocks`, `header_facts`) and data rows; `.rasx` zip with its XML header (`rasx_header`).
3. **Traces** (`common.rs` `finish`, `evenly_spaced`): every scan is one trace: channel `intensity` (counts as stored, attenuation applied as the instrument reports them), the scan axis in `extra.axis` (`two_theta`, `omega`, … in °; a listed axis is channel 0).

## Invariants and checks

- Every binary read in `raw.rs` is bounds-checked; short and unknown files are refused (`short_and_unknown_files_are_refused`); axes must be consistent with their point counts (`check_axis`).
- Area-detector frames (2D XRDML) are refused (exit 6); 1D scans of 1D and 2D detectors are read.

## Debugging a new file

- `openreadout info FILE --view full --json` → `vendor` holds the headers (XRDML optics stay there); `openreadout check FILE --report` gives the version and layout.
- `tests/synthetic.rs` builds each format; `common.rs` unit tests pin axis handling (`axes_and_spacing`).
- Oracle: the instrument software's `.xy`/`.txt` exports of the same scan through `oracle/series_oracle.py --export`.

## Fragile spots

- Count rates versus counts: intensities are returned as stored; rates are intensity divided by `extra.counting_time_s`.
- `RAW4.00` range headers vary in length by DIFFRAC.SUITE version; the `stride` of data records was learned from the corpus.
- Only tube, wavelength and detector name are normalized; optics remain in the vendor tree.
