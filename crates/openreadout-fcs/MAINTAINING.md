# Maintaining `openreadout-fcs`

Flow Cytometry Standard files, versions 2.0, 3.0, 3.1 and 3.2 (`fcs`), plus flow analysis on them: FlowJo 10 workspaces and Gating-ML 2.0 (`gating/`), compensation, data-scale transforms, gate evaluation, `table --filter`. Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Notes: [docs/formats/fcs.md](../../docs/formats/fcs.md), [docs/formats/flowjo-wsp.md](../../docs/formats/flowjo-wsp.md); provenance: [docs/provenance/fcs.md](../../docs/provenance/fcs.md), [docs/provenance/flowjo-wsp.md](../../docs/provenance/flowjo-wsp.md). FCS and Gating-ML are open ISAC standards.

## Decode pipeline

1. **Detect** (`header.rs` `looks_like_fcs`): the `FCS` version identifier; FCS 1.0 and 4.0 are detected and refused.
2. **HEADER** (`header.rs` `parse_header`): version and the ASCII byte offsets of TEXT, DATA and ANALYSIS (blank fields read as zero; large files put offsets in TEXT).
3. **Data sets** (`file.rs` `FcsFile::open`, `read_data_set`): one after another via `$NEXTDATA`; for each, the primary TEXT (`keywords.rs` `parse_keywords`: first byte is the delimiter, doubled delimiters escaped, UTF-8 with a Latin-1 fallback, duplicates reported), supplemental TEXT and ANALYSIS; where DATA really is (`resolve_data`: HEADER vs `$BEGINDATA`/`$ENDDATA`, `OffsetSource`). **Versions branch here** (`version == "FCS3.2"` per-parameter data types; 2.0 lacks segment keywords).
4. **Layout** (`layout.rs`): `$DATATYPE` (I, F, D, A), `$BYTEORD`, `$MODE`, `$PnB`/`$PnR`/`$PnE` per parameter (`read_parameters`), the spillover matrix (`parse_spillover`), and decoding (`decode_fixed`: masks to the next power of two, 24-bit integers; `decode_free_ascii`).
5. **Instrument family** (`vendor.rs`): which platform wrote the data set and what each parameter is (scatter, fluorescence, full-spectrum detector, metal-tagged mass channel, time) from the file's own keywords — **acquisition platforms branch here** (conventional, spectral, mass cytometry).
6. **Dataset** (`dataset.rs` `FcsDataset`): each data set is one table (rows = events, columns = parameters) of raw values.
7. **Analysis** (`events.rs`, `gating/`, `analysis.rs`, `filter.rs`): scale values (FCS 3.1 §3.2.19–20), compensation (`gating/compensation.rs`: square inverse or spectral least squares), transforms (`gating/transform.rs`: flin, flog, fasinh, logicle, hyperlog, fratio, FlowJo log and biex, cofactor arcsinh), workspaces (`gating/wsp.rs`) and Gating-ML (`gating/gatingml.rs`) into a `Strategy`, evaluated per event block (`gating/evaluate.rs`).

## Invariants and checks

- `check`: every data set's HEADER (identifier, ASCII offsets); TEXT syntax (delimiter, escapes, duplicates); required keywords (`$BYTEORD`, `$DATATYPE`, `$MODE`, `$PAR`, `$TOT`, `$PnB`, `$PnN`, `$PnR`, `$PnE`; segment keywords for 3.x); `$PnB` consistent with `$DATATYPE`; unique `$PnN`; DATA offsets agree and DATA length = `$TOT` × event width; every segment inside the file and the `$NEXTDATA` chain; the CRC after the last segment (`crc.rs`), verified when stored.
- Refused (exit 6): histogram data sets (`$MODE` C/U), bit-packed `$PnB`, `$BYTEORD` permutations other than 1,2,3,4 and 4,3,2,1; workspace transforms and derived parameters not listed above.

## Debugging a new file

- `openreadout dump FILE.fcs --json` → `vendor` has every keyword as written; `openreadout ls` lists the segments with offsets; `check` names the keyword or offset that is off.
- `tests/synthetic.rs` writes FCS files from the standard (every data type and byte order); `tests/fcs32.rs` covers 3.2; `tests/gating.rs` the analysis. Keyword and layout edge cases are unit tests in `keywords.rs` and `layout.rs` (`spec_escape_example`, `spillover_spec_examples`).
- Oracles: FlowIO (primary, with fcsparser as a second opinion); FlowKit/flowutils for gating and transforms (`oracle/flow.py`).

## Fragile spots

- The instrument-family rules in `vendor.rs` come from keywords seen in the corpus (listed in the format note); a new cytometer may need a new rule to label its parameters, though raw values are unaffected.
- Workspace parsing follows FlowJo 10 element names seen in files; transforms beyond the supported list and non-OLS spectral unmixing are refused, not approximated.
- Dates (`datetime.rs`) have no time zone in FCS; acquisition spans may roll over midnight.
