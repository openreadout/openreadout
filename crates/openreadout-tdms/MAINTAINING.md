# Maintaining `openreadout-tdms`

Formats: `ni-tdms`. Start with [docs/maintaining.md](../../docs/maintaining.md) for the project-wide process.

## Decode pipeline

1. **Detect** (`lib.rs`): the `TDSm` segment tag; a `TDSh` index file is refused with a hint.
2. **Segments** (`parse.rs` `parse`): every lead-in is read in turn (flags, version 4712/4713, segment and metadata lengths, byte order). Metadata (`Meta`, `read_index`) updates the objects (`Object`: path, group, channel, properties, first data type) and the active object list; a segment without metadata reuses the previous list and indexes. **Variants branch here**: big-endian segments, the new-object-list flag, the DAQmx index (`0x1269`), strings (byte size in the index).
3. **Placement** (`parse.rs` `place`): the chunks of a segment's raw data are cut by the indexes, and each channel gets `Piece`s (file offset, value count, stride, stored type): contiguous, interleaved (one row of every channel) or DAQmx (rows of raw buffers, a channel at its byte offset). String chunks are kept as offsets + text positions.
4. **Values** (`values.rs`): `raw` reads a range of values from the pieces and converts each stored type to f64 (timestamps to seconds since 1970); `scaling`/`apply` build and apply the `NI_Scale` chain (linear, polynomial).
5. **Dataset** (`dataset.rs`): channels become traces (per group when channels share count and `wf_increment`, else per channel); properties go to `extra` and `vendor`.

## Invariants and checks

- Every size and offset read from the file goes through checked arithmetic and bounds-checked reads; metadata of a segment is capped (256 MiB), and so are the stored pieces (4 Mi) and the chunks of a segment.
- A segment that runs past the end of the file, a missing `TDSm` tag after the first segment, or an unfinished last segment: the values before it are read, `notes` say so, `check` reports `truncated`.
- Not read (listed in `notes`, `check` `channel_not_read`, assurance `undecoded`): extended floats, complex values, fixed point, DAQmx digital-line data and DAQmx raw type codes other than 3, scale types other than linear and polynomial (the raw values are returned), channels whose data type changes between segments. Values after an unknown-size type in a segment cannot be located and are not read.
- Exit 4 for a file whose first segment has no `TDSm` tag, a version other than 4712/4713, or metadata that does not parse; exit 6 for a `.tdms_index` file.

## Debugging a new file

`openreadout info FILE --view full --json` lists every object with its properties and data type (`vendor.objects`); `info --view structure` the objects with their first data offset. `openreadout trace FILE --trace N --count 10` shows values. The fixture `tests/fixtures/mini.tdms` (`oracle/make_tdms_fixtures.py`) has two segments, two groups, a scale, int16, timestamp and string channels. `oracle/tdms_oracle.py` runs npTDMS (LGPL, black box) for ground truth. For a new layout, compare the lead-in flags and the first object's raw-data index with `docs/formats/ni-tdms.md`.

## Fragile spots

- DAQmx: the raw type code mapping (only 3 = int16 is confirmed) and the scale chain (scale N−1 back to an index without a scale) are inferred from two depositors' files.
- Scaling of channels that are not DAQmx raw data but say `NI_Scaling_Status` `unscaled` is applied the same way; no corpus file has one.
- Big-endian files are written from the description only: no development file is big-endian.
- A channel's data type and the grouping of channels into traces come from the first index; files that change a channel's type are refused for that channel.
