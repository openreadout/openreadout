# Maintaining `openreadout-oif`

Olympus FluoView OIF and OIB data sets (`oif`, `oib`; FV1000/FV1200/FV10i). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/oif.md](../../docs/formats/oif.md); provenance: [docs/provenance/oif.md](../../docs/provenance/oif.md) (hex dumps and the documentation and source of `oiffile`, BSD-3; Bio-Formats only as a black-box oracle).

## Decode pipeline

1. **Detect** (`lib.rs`): OIB is an OLE2 compound file (`OibReader`); OIF is a UTF-16 INI settings file (`OifReader`, `looks_like_settings`).
2. **Store** (`store.rs` `Store`): the two containers of the same set of files. **The container is the first branch**: OIB is read with the shared MS-CFB reader (`openreadout_core::cfb`) and its `OibInfo.txt` stream maps stream names to file names (`open_oib`); OIF is the `.oif` file plus the `<name>.oif.files` folder next to it (`open_oif`). Everything downstream reads members through `Store::member`.
3. **Settings** (`settings.rs`): INI text in UTF-16LE with a BOM or UTF-8, `[Section]` and `Key=Value` lines; a binary `[ColorLUTData]` section ends the text. Numbers may use a locale decimal comma (`locale_comma_numbers`).
4. **Images** (`dataset.rs` `build`, `build_image`): plane TIFF names carry the axis indices (`s_C001Z002T003.tif`, `parse_plane_name`); the main settings file's axis sections give sizes, dimension order and physical sizes (`axis_section`, `dimension_order`, `um_from`). **Variants branch here**: the FluoView version decides the axis section names and date formats (`fluoview_date`).
5. **Pixels**: each plane TIFF is decoded by `openreadout-tiff` (`tiff`, `read_member`); `.pty` files hold per-plane properties; the thumbnail is an attachment.

## Invariants and checks

- `check`: the compound-file header, FAT and directory parse (OIB); every stream `OibInfo.txt` lists exists; the `.oif.files` folder exists (OIF); the main settings parse; every plane TIFF parses and decodes to the image's size and sample type; every (c, z, t) of every image has exactly one plane file with its `.pty`.

## Debugging a new file

- `openreadout info FILE --view structure` lists every member (streams or files) with sizes; `info --view full --json` → `vendor` has the settings sections.
- A missing or extra plane usually means a new plane-name pattern: look at `parse_plane_name` and the unit tests beside it.
- `tests/synthetic.rs` builds OIF folders and OIB compound files.

## Fragile spots

- Axis sections and their units changed across FluoView versions; physical sizes depend on `um_from` unit conversion.
- Settings text encoding (UTF-16 with BOM versus UTF-8) and locale decimal commas were each found on one corpus source.
- OIB depends on `openreadout-core`'s CFB reader, shared with ZVI, Sciex, the chromatography, spectroscopy, biophysics and plate readers: a change there affects all of them (their corpus snapshots catch it).
