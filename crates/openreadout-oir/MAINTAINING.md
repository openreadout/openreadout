# Maintaining `openreadout-oir`

Olympus/Evident FluoView OIR files, including multi-file series whose pixel blocks continue in `<name>_00001`, `<name>_00002`, … (`oir`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/oir.md](../../docs/formats/oir.md); provenance: [docs/provenance/oir.md](../../docs/provenance/oir.md).

## Decode pipeline

1. **Detect** (`container.rs` `looks_like_oir`): the header signature.
2. **Container** (`container.rs` `OirFile::open`): a 96-byte header (`OirHeader`: recorded file size, index offset, block count, thumbnail offset), a chain of typed blocks from byte 96 (`walk_chain`, `BlockKind`: XML documents, frame properties, chunk tags, raw pixel chunks, bitmap thumbnail) and a block index at the end (`index_offsets`). Chunk tags (`load_chunk_tags`, `ChunkName`) name each pixel chunk by its axes (`t`, `l` for lambda, `z`) and channel.
3. **Metadata** (`meta.rs`): the length-prefixed XML documents inside metadata blocks (`XmlDoc`). Elements are matched by **local name** because namespace prefixes vary between FluoView versions — **this is where versions branch** (`image_properties`, `channel_settings`, `frame_properties`, `geometry`, `unit_to_um`).
4. **Layout** (`dataset.rs` `build_layout`, `frame_axes`, `expected_planes`): the plane map from the chunk tags against the acquisition axes; a reference image (`reference_layout`) is a second image; continuation files (`continuation_path`, `open_continuations`) extend the chunk list.
5. **Pixels** (`dataset.rs` `read_plane`): a plane is the concatenation of its chunks (possibly across files); `pixel_type_for` maps the sample width.

## Invariants and checks

- Header: signature, recorded file size, index offset, block count, thumbnail offset.
- Block chain contiguous from byte 96 to the index, kinds known, nothing past the end of the file; every chunk tag followed by a pixel block of its declared length.
- Every plane's chunks cover it exactly (no gap, no overlap); planes present for every channel × lambda × z × t the axes declare (continuation files included); XML documents parse; channels with pixels are described.

## Debugging a new file

- `openreadout ls FILE` lists every block (kind, offset, size) and chunk tag; `dump --json` → `vendor` has each XML document by its root name.
- `check` names planes with missing or overlapping chunks: the first thing to run on a file from a new FluoView version.
- There are no synthetic tests in this crate: the corpus (oirfile oracle, Bio-Formats second opinion) pins it. A new variant is best pinned by adding its file to the corpus through `cargo xtask variant intake`.

## Fragile spots

- 4-byte samples are read as float32 on the strength of oirfile's documentation only; compressed pixel blocks are not known to exist and are not handled.
- RGB camera acquisitions (three planar channels) and line scans (height = stored lines) have no corpus file.
- Chunk names with axis letters other than `t`, `l`, `z` are listed by `check` but not exposed; POIR/MPOIR archives are not read.
- Excitation wavelength is reported only when exactly one enabled laser line is linked to the channel.
