# Maintaining `openreadout-dcimg`

Hamamatsu DCIMG camera streams (`dcimg`; ORCA-Flash, ORCA-Fusion). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/dcimg.md](../../docs/formats/dcimg.md); provenance: [docs/provenance/dcimg.md](../../docs/provenance/dcimg.md) (hex dumps of corpus files and the documentation of the `dcimg` Python package, MIT; Bio-Formats only as a black-box oracle).

## Decode pipeline

1. **Detect** (`layout.rs` `looks_like_dcimg`): the `DCIMG` signature in the file header.
2. **Layout** (`layout.rs` `DcimgLayout`): file header → session header → frame geometry (`validate_geometry`). **Versions branch here**: format version 7 stores frames packed back to back with the per-frame counters and time stamps in tables after the last frame plus a footer (`FrameLayout::Packed`, `packed_session`, `read_footer`); version 0x1000000 puts a trailer after every frame (`FrameLayout::Framed`, `framed_session`). `complete_frames` and `frames_end` decide how many frames are whole.
3. **Stored pixels** (`layout.rs` `stored_values`, `StoredPixels`): some cameras overwrite the first pixels of one sensor row in every frame and store the real values separately; `dataset.rs` `read_frame` puts them back.
4. **Dataset** (`dataset.rs` `DcimgDataset`): one image whose frames are time points; `frames` returns per-frame counters and time stamps (`FrameStamp`).

## Invariants and checks

- Every offset read from the file is checked against the file length before use; a structure pointing outside the file becomes a `Problem`, not a panic (`layout.rs` module doc).
- `check`: signature, known version, header size; geometry (width × bytes per pixel ≤ bytes per row; bytes per frame = bytes per row × height); every frame and trailer inside the file; declared file length; version 7 footer tables inside the file; frame counters increasing by one (gaps are dropped frames).

## Debugging a new file

- `openreadout info FILE --view structure` lists the header, session, frame region and footer with offsets; `info --view full --json` → `vendor` has the header fields and the camera text (`CameraText`).
- A new camera or firmware usually shows as a new version or a new stored-pixel arrangement: compare the header bytes with a corpus file (`openreadout check FILE --report --hex 64` masks text but keeps the structure).
- `tests/synthetic.rs` writes both layouts from the format note.

## Fragile spots

- **Derived without a specification** from 15 corpus files (versions 7 and 0x1000000, 16-bit); 8-bit frames are inferred, not seen.
- **Stored-pixel restoration**: which row and how many pixels were learned from ORCA-Flash4.0 and ORCA-Fusion files; another model may store them differently.
- Only the first session of a file is read; sibling files `<stem>_NNN_NNN.dcimg` are not joined into a Z stack (Bio-Formats does); rows are in stored order (Bio-Formats flips them). The oracle comparison accounts for both.
