# Maintaining `openreadout-intan`

Intan Technologies RHD2000 (`.rhd`) and RHS2000 (`.rhs`) recordings (`intan`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Layout: [docs/formats/intan.md](../../docs/formats/intan.md); provenance: [docs/provenance/intan.md](../../docs/provenance/intan.md) (Intan's public data-file-format application notes).

## Decode pipeline

1. **Detect** (`lib.rs` `IntanReader::sniff`): the magic number (RHD `0xC6912702`, RHS `0xD69127AC`); a directory with `info.rhd`/`info.rhs` is a split recording (`is_split_header`).
2. **Header** (`header.rs` `parse_header`): version, sample rate, filter settings, notes (Qt strings via `Cursor::qstring`), then signal groups and channel records. **Versions branch here**: the header grows with the file version (`version >= (1, 1)` adds the temperature-sensor count, `(1, 2)` makes time indices signed (`signed_timestamps`), `(1, 3)` adds the board mode, `2.x` the reference channel and 128-sample blocks), and RHS (`Family::Rhs`) has its own header with stimulation fields and always 128-sample blocks.
3. **Block layout** (`header.rs` `block_layout`): the enabled channels decide the bytes of each data block of 60 or 128 samples; `BlockPart` lists where each signal kind sits in a block.
4. **Traditional files** (`dataset.rs` `IntanDataset`): one trace per stored signal kind (amplifier, auxiliary, supply, temperature, board ADC/DAC, digital, DC amplifier, stimulation), each a single sweep read across blocks and scaled as the application notes specify (`scaling`, `stim_decoding`).
5. **Split layouts** (`split.rs` `SplitDataset`): header-only `info.rhd` plus `.dat` files, "one file per signal type" or "one file per channel"; every stream at the header rate.

## Invariants and checks

- The header is parsed to its end (every Qt string and channel record inside the file); traditional files hold a whole number of data blocks; time indices increase by exactly one sample within and across blocks.
- Split layouts: every `.dat` file the header names exists and holds a whole number of samples, every stream holds as many samples as `time.dat`, and nothing follows the header in `info.*`.

## Debugging a new file

- `openreadout info FILE --view structure` lists header parts and data blocks; `info --view full --json` → `vendor` has the header by the application-note names.
- A new Intan software version most often changes the header (a new field before the signal groups): compare the header length `ls` reports with the corpus file of the nearest version (`corpus/snapshots/intan.jsonl`).
- `tests/synthetic.rs` writes RHD/RHS headers and blocks from the format note.

## Fragile spots

- **Version-gated header fields**: a field added in a version not in the corpus shifts every later field; `check` then fails on the channel records, which is the signal to look here.
- **Stimulation words** (RHS) return the signed current only; the amp-settle, charge-recovery and compliance bits are not exposed.
- Split recordings (one file per N minutes) are read file by file, not joined.
