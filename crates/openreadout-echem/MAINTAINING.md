# Maintaining `openreadout-echem`

Electrochemistry and battery-cycler data: BioLogic EC-Lab binary `.mpr` and `.mpt` text export (`eclab.rs`), Gamry Framework `.DTA` (`gamry.rs`), Neware BTS `.nda` and `.ndax` (`neware.rs`). Project-wide process: [docs/maintaining.md](../../docs/maintaining.md). Notes: `docs/formats/{biologic-eclab,gamry-dta,neware}.md`; provenance logs of the same names.

## Decode pipeline

1. **Detect** (`lib.rs`, one reader per format): the `.mpr` settings/data module signature, the `.mpt` header text, Gamry's `EXPLAIN` first line (`gamry.rs` `looks_like`), the `.nda` header and the `.ndax` zip members.
2. **EC-Lab `.mpr`** (`eclab.rs` `parse_mpr`, `modules`): a sequence of modules (settings, data, log, loop); the data module's column ids map to our vocabulary (`Col`, `Column`, `from_label`, `unit_of`) — **column ids are the main branch**: about 70 are validated against EC-Lab's own `.mpt` export, any other is refused (exit 6) with the advice to read the `.mpt`. Module versions change the data-module header size (`version == 2 { 405 } else { 406 }`). The acquisition start is an OLE date in local time (`ole_local`).
3. **EC-Lab `.mpt`** (`eclab.rs` `parse_mpt`): the text export's header (technique, start) and its table (`looks_like_table_header`), decimal commas included.
4. **Gamry** (`gamry.rs` `parse`): `KEY<TAB>type<TAB>value` header lines, then tables (`CURVE`, `ZCURVE`, `OCVCURVE`); a CV's cycles become sweeps of one trace.
5. **Neware** (`neware.rs`): **file versions branch here**: `.nda` version 29 (`parse_nda29`) and 130 (`parse_nda130`, `parse_nda130_bts91` for BTS 9.1 record layouts), `.ndax` (a zip of `.ndc` page files and XML descriptions; `parse_ndax`, `ndax_v5`, `ndax_split`); current ranges scale integer records (`range_scale`); step types named (`step_type_name`); auxiliary channels (temperatures, voltages).
6. **Dataset**: every record is one trace: channel 0 `time` (s, irregular axis), then one channel per stored column in our vocabulary; values as stored (quantities EC-Lab computes only when exporting text are not invented).

## Invariants and checks

- Every binary read is bounds-checked (`slice`, `u32_at` …); unknown `.mpr` column ids, `.nda`/`.ndc` versions, BTS 9.1 record sizes and current ranges without a known scale are refused with exit 6 rather than guessed (see `refuses` in the source and the notes).
- `.ndax` without `data.ndc` is refused; `.mpt` tables must have as many values per row as columns.

## Debugging a new file

- `openreadout report FILE` names the technique, version and column set (fingerprint); `openreadout info FILE --view structure` lists the `.mpr` modules or the `.ndax` members; `info --view full --json` → `vendor` has the settings text and headers.
- A refused EC-Lab column id: export the same file as `.mpt` from EC-Lab, then add the id with its label and unit after comparing the two (never guess a unit).
- `tests/synthetic.rs` builds `.mpr`, `.mpt`, `.DTA`, `.nda` and `.ndax` files; unit tests in each module pin layouts (`labels_and_times`, `tables_and_sweeps`, `ranges_and_names`, `calendar_stamps`).
- Oracles: the vendor's text exports and permissive readers' outputs, through `oracle/series_oracle.py` (`corpus/oracle/series/`), compared by the corpus test's series comparison.

## Fragile spots

- EC-Lab: technique parameters (the settings module) are not decoded; instrument model and software version are not in a decoded `.mpr` field.
- Neware: layouts differ by BTS version and by current range; a new range or record size is refused until validated against an export.
- Local-time OLE dates (`.mpr`) and US-format dates (Gamry) are interpreted without a time zone.
