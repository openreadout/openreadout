# Held-out generalization report, 2026-10-06 (draw D)

This is the fourth held-out draw. The earlier ones are [heldout-2026-09-24.md](heldout-2026-09-24.md)
(draw A), [heldout-2026-09-24b.md](heldout-2026-09-24b.md) (draw B) and
[heldout-2026-09-26c.md](heldout-2026-09-26c.md) (draw C). Draw D adds 105 held-out inputs from 100
source records, across 74 formats in 19 families. It is the first draw to cover the formats that
had no held-out file yet: the vendor mass-spectrometry directories (Agilent MassHunter, Waters
MassLynx, Bruker timsTOF), Chromeleon, OpenLab CDS, Empower, the newer electrophysiology, NMR and
spectroscopy readers, the bench instruments, VSI, MIRAX and OME-Zarr. It measures OpenReadout 0.1.0
whose reader code is `main` at `572e5922`, as a release build. The same build was re-run over every
earlier held-out input, 292 inputs in all. No model was called.

The rules of [heldout.md](heldout.md) apply. **Do not fix a reader on these files.** Reproduce each
finding below on a new public file first; that file joins the development corpus with its own
provenance entry. The held-out file only confirms afterwards that the fix generalizes. The reader
errors are also listed in machine-readable form in
[heldout-2026-10-06d-findings.json](heldout-2026-10-06d-findings.json).

## Method

As in draw C, with these changes.
- **Four area agents.** Mass spectrometry and chromatography, imaging, signals (electrophysiology,
  NMR, spectroscopy) and assays (plates, qPCR, flow, bench instruments) were assembled in parallel.
  None of them ran OpenReadout on a draw-D file. Manifest entries were committed as each area
  appended them (first at `7879e4a9`), so other workstreams saw the reserved records within the
  first hours.
- **Ground truth.** The same third-party readers as the development corpus, and depositor exports.
  `oracle/gen_heldout.py` gained branches for timsTOF (timsrust through `oracle/timsrust-oracle`),
  Chromeleon (reports no oracle), headerless ARW, WITec (`witio` in its own venv), Spinsolve,
  SpikeGLX (a `.meta` copy with its missing `fileName` key added; the `.bin` was not touched),
  PatchMaster (pyHEKA, AGPL, black box), TA instruments, Octet, UXD exports, ITC concentrations
  from the file name, and `neware_reader`. `oracle/series_oracle.py` skips non-numeric columns.
  `oracle/openlab_chromconverter.R` now keeps printable ASCII only in sample, operator and method
  text, because a Chinese method path broke its CSV.
- **Questions first.** The 162 new questions (`ho-d-*`, 111 lookups and 51 analysis tier, in
  `evals/heldout_draw_d_*.py`) were committed in `ec44e209`, with their ground truth in `ff2529e8`,
  before OpenReadout ran on any draw-D file. The held-out split now has 353 questions.
  `evals/heldout.py --only TEXT` was added to check new facts and questions without writing.
- **Changes after the first run, disclosed.** Two comparison settings and two question stagings
  changed after OpenReadout first ran. No answer changed.
  1. The probe compared a series oracle's entry count (one entry per channel) with our trace count.
     It now counts distinct traces (`7a5deffd`). This removed four false disagreements (EPR, Gamry,
     Neware NDAX, NETZSCH), whose deep comparisons had passed.
  2. The VSI slide got `lossy = true`, as every development VS120/VS200 JPEG slide has. Its overview
     image then agrees within the lossy tolerance.
  3. The timsTOF questions staged `analysis.tdf` without its `analysis.tdf_bin`, and the EPR
     question staged the `.DSC` without its `.DTA`. Both now stage the whole data set (`7098be42`).
  The first run, before adjudication, read 74 of 101 agreeing
  ([heldout-2026-10-06d-first.json](heldout-2026-10-06d-first.json)). The four probe artifacts and
  the VSI overview hashes account for the difference from the 77 of the corrected run
  ([heldout-2026-10-06d.json](heldout-2026-10-06d.json)).

**Depth of the 85 adjudicated agreements.** Almost all compared values: planes, samples, peaks,
events, Cq values, plate values, report points or curves. The two partial plate copies compared
every plane present. Three compared less. The timsTOF prm-PASEF run compared its frames (point
counts and intensity sums) but not m/z, because timsrust approximates the calibration that
OpenReadout applies. The Xevo TQ run compared the point counts and intensity sums of its two MRM
functions. The ITC file compared its stored concentrations only.

**Speed.** Every draw-D file finished `info` in ≤ 0.26 s except the NWB file with 810 sweeps
(3.5 s), and `check` in ≤ 3.7 s. Detect, info, check and dump over all 292 inputs took 52 s of
wall time. No command panicked. 104 of 105 draw-D files were detected as their manifest format; the
headerless ARW was not (D-G4).

**Question level.** `run.py preflight --split heldout` stages all 353 questions. It flags 15 draw-D
questions and 2 refusals (exit 6), all explained by the findings below: the two Thermo runs (D-H1,
D-H2), the BMG export (D-H3), the OIB (D-H4), the EC-Lab text file (D-H5), the MPR and NDA refusals,
the headerless ARW, and three files whose `check` exits 4 (the 2003 ANDI file, the Shimadzu run and
the DM3 profile).

intact file rejected, on a mainstream instrument. **Medium** means a wrong or missing value an agent
would report. **Low** means metadata, precision or a false integrity alarm. **Gap** is a variant
refused with a hint. **Oracle** means the ground truth, its converter or the comparison is at fault.

  CDS, OME-Zarr 0.5). The others are variants no development file confirms yet, such as an NWB
  icephys file, a JCAMP-DX link file and a solid-state Bruker pseudo-2D.
- **Right or refuse.** All four refused variants were refused with an actionable hint, not read
  wrongly. Unlike draw C, a third-party reader reads three of them, so these are real capability
  gaps.

## Reproduce

```bash
cargo xtask corpus fetch --tier heldout
cd oracle && TIMSRUST_ORACLE=… WITEC_PYTHON=… JWS2TXT_DIR=… CHROMCONVERTER_LIB=… uv run python gen_heldout.py   # (ground truth; already committed)
oracle/.venv/bin/python evals/heldout.py && (cd evals && uv run python generate.py)
cargo build --release -p openreadout
HELDOUT_REPORT=/tmp/heldout-corpus.jsonl cargo test -p openreadout-corpus-tests --features corpus --profile corpus --test corpus heldout -- --nocapture
cd evals && uv run python heldout_probe.py --binary ../target/release/openreadout --corpus-test /tmp/heldout-corpus.jsonl -o ../docs/benchmark/heldout-2026-10-06d.json
uv run python heldout_summary.py ../docs/benchmark/heldout-2026-10-06d.json --classes ../docs/benchmark/heldout-2026-10-06d-classes.json [--draw 2026-10-06d]
uv run python run.py preflight --split heldout
```

`evals/heldout.py` needs a few readers beyond the oracle venv: rainbow-api (as for the earlier
ChemStation facts), and, for the draw-D bench facts, geddes, pyNGB and allotropy (`ASSAYS_SITE`
names a site-packages directory that holds them) and jws2txt (`JWS2TXT_DIR`). The oracles need
witio (MIT-0, `WITEC_PYTHON`), chromConverter (`CHROMCONVERTER_LIB`), rainbow-api, and the
timsrust oracle built with `cargo build --release --manifest-path oracle/timsrust-oracle/Cargo.toml`.
