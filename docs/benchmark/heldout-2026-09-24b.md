# Held-out generalization report, 2026-09-24 (addendum: new families and analysis commands)

This addendum to [heldout-2026-09-24.md](heldout-2026-09-24.md) covers the files added to the held-out set on 2026-09-24 for the format families and analysis commands that arrived after the first draw: vibrational spectroscopy, qPCR, high-content screening plates, and files for chromatogram peak integration, compressed and HDF5 mzML, plate-assay curves, NMR FID processing, current-clamp spike features and JPEG 2000 whole-slide tiles. It measures OpenReadout 0.1.0 at commit `cd48fd1` (a development build, which includes `main` at `98fc34e`), release build. No model was called.

The rules of [heldout.md](heldout.md) apply: **do not fix a reader on these files.** Each finding below must be reproduced on a new public file first, which joins the development corpus with its own provenance entry. The held-out file only confirms afterwards that the fix generalizes.

## Method

It is the same as the first report:
- `evals/heldout_probe.py` runs detect, info, check and dump on every held-out input. It now also compares qPCR vendor Cq values per well and target through `table`, and Shimadzu chromatogram sizes against the LabSolutions export. Its JSON is [heldout-2026-09-24b.json](heldout-2026-09-24b.json).
- `cargo test -p openreadout-corpus-tests --features corpus --profile corpus --test corpus heldout` records the deep comparison: plane hashes, sweep blocks, every scan, plate layouts and planes.
- For each new question, the command an agent would use was run once to check whether the tool's output holds the answer (a tool-level check, not a benchmark run): `trace`, `stats`, `stats --per well` (or `--per field`), `table`, `analyze qpcr --cq`, `analyze peaks`, `analyze chromatogram`, `spectra`, `analyze assay curve`, `analyze nmr-peaks --from fid` and `analyze ephys-features`.

At the question level, the tool's output holds the answer to 33 of the 38 new questions. The five it cannot answer:

**Speed:** `info` took ≤ 0.76 s and `check` ≤ 3.4 s on every new file; both maxima are on the 20 MB `.mzML.gz`, which has to be decompressed to be indexed. detect, info, check and dump over all 76 held-out inputs took 9 s of wall time.

**Whole set, re-run with this build:** 69 of 76 inputs pass the deep comparison, 5 FAIL and 2 have no usable oracle. The first report's H1 (Exploris 480), H2 (Bio-Formats JPEG OME-TIFF), M1 (RGB ND2 order), M2 (QE HF PRM centroids) and L2 (empty JCAMP-DX title) now pass after the fixes on `main`, which were developed on other files. The i-control CSV (M3) now passes `check` (it still has no oracle). L1 (LTQ XL / TSQ metadata) and O2 (Gen5 kinetic count) are unchanged.
