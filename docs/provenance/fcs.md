# Provenance log — FCS (Flow Cytometry Standard)

Rules: `docs/legal/clean-room-policy.md`. Each entry: date, who, corpus files, prior art (URL + license), what was inferred.

FCS is an open standard published by the International Society for Advancement of Cytometry (ISAC). Unlike the microscopy formats, the structure comes from a public specification, so most normalized fields carry `Source::Spec`.

## 2026-09-22 — initial derivation (Richard Zimring with Claude as assistant)

**Specification consulted** (public, ISAC):
- "Data File Standard for Flow Cytometry, Version FCS 3.1 — Normative Reference", ISAC Recommendation, 2009-08-13, Creative Commons Attribution-ShareAlike 3.0. Originally at `http://www.isac-net.org/images/stories/documents/Standards/fcs3.1_normativespecification_20090813.pdf` (the link given in the PMC copy of Spidlen et al., Cytometry A 2010;77(1):97–100, PMC2892967); retrieved through the Internet Archive copy of that ISAC URL because the ISAC site has since moved it. Used for: HEADER layout (bytes 0–57, right-justified 8-byte ASCII offsets, inclusive end offsets, zeros when a segment lies beyond byte 99,999,999), TEXT delimiter and escaping rule (doubled delimiter, no empty keywords or values), required keywords, `$DATATYPE` I/F/D/A, `$BYTEORD` 1,2,3,4 / 4,3,2,1, `$MODE` L/C/U, `$PnB`/`$PnR` bit-mask rule (next power of two of `$PnR`, no mask for F/D), `$PnE`/`$PnG`/`$PnV`/`$PnL`/`$PnS`/`$PnD`/`$PnCALIBRATION` value grammar, `$SPILLOVER` layout, `$BTIM`/`$ETIM` (`hh:mm:ss[.cc]` in 3.1, `hh:mm:ss[:tt]` sixtieths in 3.0 per Appendix B), `$DATE` `dd-mmm-yyyy`, `$NEXTDATA` (offset from the start of the current data set), supplemental TEXT (`$BEGINSTEXT`/`$ENDSTEXT`), ANALYSIS segment, and the CRC field (8 ASCII bytes after the last segment; CCITT polynomial, bit-reflected, initial value 0; `00000000` when not computed).
- ISAC data-standards page https://isac-net.org/data-standards/ (checked 2026-09-22) — confirms FCS 3.1 is the current ISAC standard. No FCS 2.0 or 3.0 specification text was consulted; 2.0/3.0 differences are taken from Appendix B of the 3.1 document and from corpus files.

**Prior art consulted** (permissively licensed; documentation and source read, no code copied):
- `FlowIO` 1.4.0, Scott White, BSD-3-Clause, https://github.com/whitews/FlowIO — `flowdata.py`/`utils.py`: `$NEXTDATA` is followed as a relative offset with a loop guard; TEXT offsets are preferred over HEADER offsets for 3.x; DATA end offsets that are one byte too long occur in real files; `$BYTEORD` `1,2` / `2,1` appear in FCS 2.0 files; the bit mask is `next_power_of_two($PnR) - 1`.
- `fcsparser` 0.2.4, Eugene Yurtsev, MIT, https://github.com/eyurtsev/fcsparser — `api.py`: integer fields that are not a power-of-two bytes wide (the Cytek xP5 writes 24-bit integers) are real; trailing whitespace in numeric keyword values is common (DiVa `$TOT`); mask rule `2^ceil(log2($PnR)) - 1`.

Both readers are also run as black-box oracles (`oracle/gen.py`).

**Corpus files used** (all in `corpus/manifest.toml`, pinned to repository commits):
- fcsparser test data (MIT, commit `da70aaa`): `fcsparser-cytek-xp5`, `-facscalibur-hts-a02`, `-facs-diva`, `-fortessa-a01`, `-guava-muse`, `-hts-lsr-ii-d06`, `-miltenyi-fcs20`, `-miltenyi-fcs30`, `-miltenyi-fcs31`, `-miltenyi-fcs31-add`, `-miltenyi-fcs31-without`, `-miltenyi-duplicate-names`, `-cyflow-cube-8`, `-fake-large`, `-fake-bitmask` (held; see manifest), `-corrupted`, `-cytek-nl-2000-header`.
- FlowIO test data (BSD-3-Clause, commit `83d28a2`): `flowio-100715`, `-3fitc-4pe-004`, `-b01-kc-a-w-91-us`, `-g11`, `-coulter-lmd`, `-data1`, `-data-start-offset-discrepancy`, `-data-stop-offset-discrepancy`, `-variable-int`, `-m0-wm278-s1-zero-gain`, `-ki67-117-tube-1-empty-timestep` (held; see manifest).

**Method:** a 60-line Python walker (HEADER → TEXT → `$NEXTDATA`) printed every file's HEADER offsets, delimiter byte, `$DATATYPE`, `$BYTEORD`, `$MODE`, `$PAR`, `$TOT`, `$PnB`/`$PnR` sets, segment keywords and the eight bytes after the last segment. Observed and now handled:
- Delimiters seen: `/`, `\`, `|`, form feed (0x0C), record separator (0x1E).
- Numeric keyword values padded with spaces (`$TOT/83411               /`, `$BEGINDATA/     3446/`) or leading zeros (`$BEGINDATA/0000000000004161/`); both are trimmed. The spec (3.2.17) forbids space padding, so `check` reports it as `info`.
- `$BYTEORD/1,2/` (two-byte order) in Beckman Coulter FCS 2.0 data sets.
- Mixed `$PnB` (8/16/32 in one data set: `fcsparser-cyflow-cube-8`, 16/32: `flowio-variable-int`), and 24-bit big-endian integers (`fcsparser-cytek-xp5`, 8 × 3 bytes × 23126 events equals the DATA length exactly).
- `$PnR` larger than the field (`4294967296` with `$PnB/32/`), and non-integer `$PnR` for F data (`26.3432`).
- HEADER DATA offsets of zero with `$BEGINDATA`/`$ENDDATA` in TEXT (`fcsparser-fake-large`), HEADER blanks instead of zeros.
- HEADER vs TEXT disagreement on the DATA offsets (`flowio-data-*-offset-discrepancy`): the TEXT pair is the one whose length equals `$TOT` × event width; the HEADER pair is not.
- Four data sets chained by relative `$NEXTDATA` (`fcsparser-guava-muse`); a second data set whose TEXT follows its DATA (`flowio-coulter-lmd`, HEADER TEXT offsets 579578–580291, DATA 58–579577).
- Supplemental TEXT: starting with the delimiter (Miltenyi), starting directly with a keyword (`flowio-m0-wm278-s1-zero-gain`), pointing at the primary TEXT range (`flowio-b01-kc-a-w-91-us`), and holding a ZIP archive instead of keywords (`fcsparser-cyflow-cube-8`, bytes `PK\x03\x04`).
- CRC field: `00000000` (DiVa, Guava, Navios), seven zeros (Miltenyi), NUL bytes, or absent. No corpus file carries a computed CRC, so CRC verification is implemented from the spec text alone and a mismatch is reported as a warning, not an error.
- Truncation: `fcsparser-cytek-nl-2000-header` ends after its TEXT (3931 bytes, `$ENDDATA` 2165911).

**Instrument-specific keywords** (recorded verbatim, grouped by prefix, no semantics assigned): seen in `fcsparser-facs-diva`, `-fortessa-a01`, `-hts-lsr-ii-d06`, `flowio-100715` (BD FACSDiva: `CREATOR`, `TUBE NAME`, `EXPERIMENT NAME`, `GUID`, `SPILL`, `APPLY COMPENSATION`, `THRESHOLD`, `WINDOW EXTENSION`, `FSC ASF`, `AUTOBS`, `EXPORT USER NAME`, `EXPORT TIME`, `CST …`, `CYTOMETER CONFIG …`, `LASERn…`, `PnDISPLAY`, `PnBS`, `PnMS`), `fcsparser-cytek-nl-2000-header` (Cytek SpectroFlo: `CREATOR`, `LASERnNAME/DELAY/ASF`, `USERSETTINGNAME`, `TUBENAME`, `GROUPNAME`, `CHARSET`, `PnDISPLAY`) and `fcsparser-cytek-xp5` (FlowJo Collectors' Edition on a Cytek xP5: `ANALOG_COMP`, `FJ$ACQSTATE`, `FJ_$P1R`, `LASERnNAME`, `SAMPLEID`). The only one given a meaning is `SPILL`: its value has the same shape as `$SPILLOVER` (count, that many `$PnN` names that exist in the same data set, count² numbers), which is checked per file before it is exposed as the spillover matrix. `CREATOR` is exposed as the writing software because its values are recognisable software names in every file that has it (`BD FACSDiva Software Version 6.2`, `SpectroFlo 2.2.0`, `FlowJoCollectorsEdition 7.5.109.8`); provenance `inferred`.

**Inferred, not yet corroborated:** the CRC variant (no corpus file has one); `$DATATYPE/A/` decoding and `$MODE/C/`/`U/` detection (no corpus file uses them; unit tests only); `$COMP` layout (not in the corpus; exposed as a raw matrix without a claim about direction).

**Corpus files placed on hold:** `fcsparser-fake-bitmask` and `flowio-ki67-117-tube-1-empty-timestep` carry `@SAMPLEID` values that look like clinical sample accession numbers or a surname. They are publicly distributed by their upstream projects, but per the clean-room policy (nothing patient-identifiable) they are `tier = "hold"` until someone confirms they are anonymized. Their oracle JSON holds no keyword values.

**Inferred from those files** (`Source::Inferred`): the writing family from `$CYT`, `CREATOR` and family-specific keywords (`CYTEXPERTFIL`; SpectroFlo `CREATOR`; `$CYT` containing `CYTOF`, `DVSSCIENCES` or `FLUIDIGM`; `$CYT` of `SA3800`, `ID7000`, `SH800`, `MA900`; `CREATOR` starting `BD FACSDiva`); spectral instruments recognised by their detector naming (`<laser><n>-A` with a laser prefix `UV`, `V`, `B`, `YG`, `R`) and by `$PnTYPE`; mass-cytometry channels recognised by an element symbol + mass + `Di`/`Dd` in `$PnN` (the symbol checked against the periodic table, mass 75–209), with the marker taken from `$PnS` after its `<mass><element>_` prefix. Channel roles from `$PnN` prefixes (`FSC`, `SSC`, `Time`) and suffixes (`-A`, `-H`, `-W`), the convention FlowIO also uses to separate scatter, time and fluorescence channels.

**Prior art:** none beyond the entries above; element symbols are public domain.

## 2026-09-23 — FCS 3.2 data sets and BD spectral keywords (Richard Zimring with Claude as assistant)

**Written before the code.** Opens `FCS3.2` data sets, which were rejected (exit 6).

**Standard consulted** (public): Spidlen J. et al., "Data File Standard for Flow Cytometry, Version FCS 3.2", Cytometry A 2021;99(1):100–102, PMID 32881398, read as the NIH author manuscript on PMC (PMC8241566, NIHMS1703450). The technical note's summary of changes is what we implement: optional `$PnDATATYPE` (a measurement stored with a data type other than `$DATATYPE`: mixed I/F/D in one data set); optional `$PnDET` (detector), `$PnTYPE` (measurement type), `$PnFEATURE` (area, height, width, …), `$PnTAG` (dye) and `$PnANALYTE` (target); `$BEGINDATETIME`/`$ENDDATETIME` (ISO 8601) replacing the deprecated `$DATE`/`$BTIM`/`$ETIM`; `$CARRIERID`, `$CARRIERTYPE`, `$LOCATIONID` replacing `$PLATEID`, `$PLATENAME`, `$WELLID`; `$FLOWRATE`, `$UNSTAINEDCENTERS`, `$UNSTAINEDINFO`; `$MODE` deprecated (list mode only, so a missing `$MODE` means `L`); `$BEGINSTEXT`, `$ENDSTEXT`, `$BEGINANALYSIS`, `$ENDANALYSIS` optional; `$PnG` only for integer data. The normative PDF in the article's supporting information could not be downloaded (the server returned a web page); nothing beyond the note's summary is assumed.

**Corpus file:** `zenodo19221995-facsdiscover-draq5` (Zenodo 19221995, CC-BY-4.0, *C. elegans* single-cell suspension on a BD FACSDiscover S8, `CREATOR` `BD FACSChorus 5.4.0.0`): `FCS3.2`, delimiter CR, 440 measurements each with `$PnDATATYPE/F/`, `$PnFEATURE` values `Area`, `Height`, `Width`, `MaskSize`, `Eccentricity`, … (imaging features), `$PnDET` like `UV1 (375)`, `$PnTAG`/`$PnANALYTE` on the unmixed dye measurements, `$BEGINDATETIME` with `Z`, a 78×78 `SPILL` over the full-spectrum detectors, and BD keywords `BDSPECTRAL UNMIXED` (the unmixed measurements, comma-separated), `BDSPECTRAL PROBES`, `BDSPECTRAL UNMIXING METHOD` (`SpectralFX 10`), `BDSPECTRAL APPLY`. Inferred from this file (`Source::Inferred`): these files come from BD FACSChorus spectral instruments; `BDSPECTRAL UNMIXED` lists measurements that already hold unmixed values. The same deposit's FlowJo 10.10 workspace (`20250307.wsp`, spectral OLS matrix, biex and log transforms) is paired with it.

## 2026-09-25 — assurance profile (`src/assurance.rs`)

**Corpus files:** every development input of this format on disk (`corpus/assurance/evidence.json` lists them); no held-out file.
**Prior art consulted:** none.
**What was done.** No parsing logic changed. The reader declares an assurance profile (docs/assurance.md) that fingerprints each file from this reader's own normalized output: the FCS version, $DATATYPE, byte order, $MODE, the acquisition platform family, spillover compensation and $PnE/$PnG scaling (both available on request). The table of validated feature values and the confidence level are generated from the development corpus by `cargo xtask assurance-audit`.
