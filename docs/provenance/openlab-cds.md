**Inferred from the files (before reading prior art):**
- `.dx` and `.rx` are zip archives (stored or deflated members) laid out as Open Packaging Conventions packages: `[Content_Types].xml` maps extensions to content types (`CH` → `Agilent.OpenLab.Rawdata/Signal179`, `IT` → `Agilent.OpenLab.Rawdata/InstrumentTrace179`, `acmd` → `Agilent.OpenLab.Rawdata/ACMD`), `_rels/.rels` points at `/injection.acmd` (relationship type `urn:schemas-agilent-com:acmd`). The `.rx` has only `[Content_Types].xml`, `Base/InjectionACAML` (XML, deflated) and `Base/AuditTrail` (binary with readable user/computer/message strings).
- `injection.acmd` is UTF-8 XML (BOM) in namespace `urn:schemas-agilent-com:acmd20`: one `InjectionInfo` with `Version` (2), `Location` (vial: `71`, `1`), `InjectionSource` (`GC Injector`, `HipAls`), `InjectionVolume` + `InjectionVolumeUnits` (`1` `μL` — U+03BC in the GC files, U+00B5 in the LC files), `SequenceLine`, `Replicate`, `SampleName`, `RunOperator`, `Barcode`, `RunDateTime` (ISO-8601 with zone and 7 fractional digits), `AcquisitionMethod` (the method file path), and `Signals/Signal` entries. Each signal: `Encoding` (the content type), `TraceId` (a GUID; the part is `<TraceId>.CH` / `.IT`), `DeviceName` (`FID`, `DAD`, `PMP`, `THM`, `WPS`, `FLD`), `DeviceNumber`, `ChannelName` (`FID2B`, `DAD1D`, `PMP1A`), `Description` (`FID2B`; `DAD1D,Sig=228,4 Ref=360,100`; `PMP1A,Pressure`), `TimeStart`/`TimeEnd` (ms for `Signal179`: 19.812 / 680,000; for `InstrumentTrace179` 0 and the value count), `Minimum`, `Maximum`, `Slope` (equals the part's scale factor), `NumberOfValues`, `Units` (`pA`, `mAU`, `bar`, `mL/min`, `%`, `°C`, `V`, empty), `IsIntegrable` (`true` for detector signals, `false` for instrument curves) and empty `GenericResults…` elements.
- `Signal179` parts are ChemStation version-179 signal files (`03 31 37 39` at byte 0, file type `OL DATA FILE` in UTF-16 at 0x15B, the 0x1800 header of `docs/formats/chemstation.md`, sample name at 0x35A, operator 0x758, date 0x957, method path 0xA0E, units 0x104C, signal description 0x1075, scale f64 at 0x127C = the manifest's `Slope`, first/last time f32 at 0x11A/0x11E = `TimeStart`/`TimeEnd`), with a little-endian f64 body: 34,000 values in the GC parts (6,144 + 272,000 bytes). The existing version-179 decoder applies unchanged.
- The sampling grid of the GC parts: first time 19.812 ms, 20 ms apart. The header's last time is 680,000 ms = 34,000 × 20 ms, not first + 33,999 × 20 ms (679,999.812); `(last − first)/(n − 1)` gives 20.0000055 ms, a drift of 0.19 ms (3·10⁻⁶ min) at the end of the run. The vendor peak limits confirm the 20 ms grid (below). We keep the ChemStation rule, which is also what both oracles do.
- `InstrumentTrace179` parts have the same 0x1800 header (units at 0x104C, description `PMP1B,Flow` at 0x1075, scale at 0x127C = `Slope`) but a body of 16-byte pairs: little-endian f64 time in ms, then the little-endian f64 raw value; value = raw × scale (`1000 × 0.001` = 1.0 mL/min flow; `380 × 0.1` = 38 % solvent B, matching a 38 % acetonitrile method name). Their header times are not a time range (0 and value count × 1,000). The corpus pairs are evenly spaced (60, 97.875, 100, 1,000 ms) and start between 32 ms and 1 s.
- `Base/InjectionACAML` (namespace `urn:schemas-agilent-com:acaml21`, schema version 2.1.30.999): `Doc/Content/Method` (`Name` = processing method, `QuantitationMethod` `ESTD`, `OriginalVersion`), `Injections/Result` with `InjectionMeasData_ID`, `SignalResult`s (one per signal: `Signal_ID` and zero or more `Peak`s), `InjectionCompound`s (one per peak, linked by `Identification/Qualified/Peaks/Peak_ID`; `CompoundName` empty in every corpus file, `Type` `Unknown`), `DataAnalysisSoftware` (`Agilent OpenLAB Data Analysis Processing Server Version 2.6 - Build 2.206.0.780`), `DataAnalysisMethodVersion`, `ProcessingStatus`, `Integrator` (`TwelveTone`). A `Peak` holds `RetentionTime` (min), `Type` (`NormalPeak`), `Area` (unit `pA·s` / `mAU·s`), `AreaPercent`, `Height` (`pA`/`mAU`), `HeightPercent`, `Symmetry`, `BeginTime`/`EndTime` (min), `BaselineCode` (`BB  `, trailing blanks), `BaselineStart`/`BaselineEnd`, `LevelStart`/`LevelEnd` (≈ 0), `WidthBase`, `PurityPassed`, `MSPurityPassed`, `BaselineModel` (`Linear`), `BaselineParameters` (two numbers) and `BaselineRetentionHeight`.
- **Which signal a result belongs to.** `Signal_ID` is not a `TraceId` of the `.dx`. In the result sets, the sequence file `<name>.acaml` (same namespace) lists, per injection (`Injections/MeasData`, whose `BinaryData/DataItem/Name` is the `.dx` file name and whose `@id` is the `.rx`'s `InjectionMeasData_ID`), `Signal` elements whose `@id` is the `Signal_ID` and whose `TraceID` is the manifest's `TraceId`. The Polyarc data set has no `.acaml`. There, `BaselineStart` equals the raw signal at the sample nearest `BeginTime` (and `BaselineEnd` at `EndTime`) to machine precision on the signal the vendor integrated (FID2B: 16.04766 vs 16.04766 pA) and differs completely on the other (FID1A: 7.79 pA), and `BaselineRetentionHeight + Height` is within 1 % of the signal at the apex; the vendor CSV names the signal (`Signal:,FID2B`). This match is the fallback mapping; the CSV is used only by the tests.
- The sequence `.acaml` also lists the instrument (`Resources/Instrument`: `Name` `Luxo HPLC`, `Technique` `LiquidChromatography`, `Module`s with `Name`, `Manufacturer`, `Type`, `PartNo` `G7117C`, `SerialNo`, `FirmwareRevision`), and each `Signal`'s `InstrumentModule_ID`, `DetectorName`, `Type` (`InstrumentCurve`, …).
- The vendor CSV export (`_1.csv`, not read by the reader) lists RT, type, width, area, height and area % rounded to 2–3 decimals; its values equal the `.rx` values rounded, its `Width [min]` is `WidthBase`, its `Injection date` is 19 minutes after `RunDateTime` (end of the run vs start of acquisition).

## 2026-09-24 — Zip containers read by the shared `openreadout_core::zip`

**Scope:** the crate-private zip reader is replaced by one shared module in `openreadout-core` (`zip.rs`), used by qPCR (RDML, `.eds`, `.pcrd`), OpenLab CDS (`.dx`, `.rx`) and zipped OME-Zarr stores. No new interpretation of any format. The shared reader is the union of the three copies: central directory with ZIP64 records, case-insensitive and exact name lookup, stored and deflated members checked against their CRC-32, partial reads of stored members, a deterministic writer. Hardening over the copies: every offset and length is checked against the file size before it is read (a range past the end is exit 4, not an I/O error); a declared member count the central directory cannot hold is corrupt; inflation is bounded by the member's declared size (`miniz_oxide::inflate::decompress_to_vec_with_limit`, so a zip bomb stops there instead of pre-reserving or growing past it); the archive is read through one byte source with positional reads instead of a file opened per member. Fuzz target `core_zip`; unit tests flip and truncate every byte of a small archive.

**Prior art consulted:** PKWARE APPNOTE.TXT (public specification), as before. No new corpus files.

**Inferred:** the `Spectra131` part (content type from the manifest's `Encoding`) is a ChemStation version-131 file (`03 31 33 31`, file type `OL DATA FILE`, header scale f64 big-endian 0.000476837158203125 = the manifest's `ScaleFactor`), whose records (from byte 4096) have tag 70 instead of 67: the 22-byte record header as for tag 67 (length 1,270 = 22 + 156 × 8 for 190–500 nm in 2 nm steps), then little-endian f64 values. rainbow's `parse_uv` returns exactly stored × scale for every value (4,050 × 156 values of MeOH1). That this is not yet the unit showed against the DAD's own channels in the same container (`DAD1A,Sig=210,4` etc., recorded by the detector, mAU): the spectra × scale are 2,097 times larger; × scale × scale averaged over the channel's band agree with the channel (slope 0.993–1.009, r ≥ 0.99999, 8 channels of 2 injections). The `.UVD` member (`urn:schemas-agilent-com:spectradirectory` relationship) is left listed. The manifest's `NumberOfRecords` equals the spectrum count.
