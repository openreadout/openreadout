# Provenance log — flow analysis: FlowJo workspaces, Gating-ML 2.0, compensation, transforms

Rules: `docs/legal/clean-room-policy.md`. Each entry: date, who, corpus files, prior art (URL + license), what was inferred.

FlowJo workspaces (`.wsp`) are XML written by FlowJo (BD). The gate, transform and compensation elements inside them reuse the public ISAC Gating-ML 2.0 namespaces (`gating:`, `transforms:`, `data-type:`); the surrounding structure (`Workspace`, `SampleList`, `Sample`, `SampleNode`, `Population`, `Groups`, `AndNode`, …) is FlowJo's own and is read from the files themselves. Gating-ML 2.0 is an open ISAC standard. Vocabulary: `docs/formats/flowjo-wsp.md`.

## 2026-09-23 — derivation of the reader, the gate evaluator, compensation and transforms (Richard Zimring with Claude as assistant)

**Written before the code.**

**Standards and papers** (public):
- ISAC Gating-ML 2.0 (Spidlen et al., Cytometry A 2015;87(7):683–687, "Gating-ML 2.0: International Society for Advancement of Cytometry (ISAC) standard for representing gating descriptions in flow cytometry"). Not re-read in full; its definitions reach us through the compliance files and FlowKit/flowutils below: `flin(x,T,A) = (x+A)/(T+A)`, `flog(x,T,M) = 1/M·log10(x/T) + 1`, `fasinh(x,T,M,A) = (asinh(x·sinh(M·ln10)/T) + A·ln10) / ((M+A)·ln10)`, `fratio(x,y,A,B,C) = A·(x−B)/(y−C)`, logicle and hyperlog as the roots of the biexponential `B(y) = a·e^(by) − c·e^(−dy) − f` and of `EH(y) = a·e^(by) + c·y − f`; rectangle gates with an inclusive minimum and exclusive maximum, polygon gates by the winding-number rule, ellipsoid gates by the Mahalanobis distance against `distanceSquare`, quadrant gates from dividers and positions, Boolean gates `and`/`or`/`not` with `use-as-complement`; compensation references `uncompensated`, `FCS` (the file's own spillover; treated as uncompensated when the file has none) or a `spectrumMatrix` id (rows = fluorochromes, columns = detectors).
- Moore W.A. and Parks D.R., "Update for the logicle data scale including operational code implementations", Cytometry A 2012;81A(4):273–277: the logicle parameter derivation (`w = W/(M+A)`, `x2 = A/(M+A)`, `x1 = x2 + w`, `x0 = x2 + 2w`, `b = (M+A)·ln10`, `d` from `2(ln d − ln b) + w(b + d) = 0`), the Taylor series near data zero and Halley's method for the inverse. Our Rust follows the published algorithm; flowutils' C port (below) was read to confirm the constants (16 Taylor terms, tolerances).
- FCS 3.1 §3.2.19–20 (already in `docs/provenance/fcs.md`): channel values to scale values — `$PnE f1,f2` (f1 > 0: `10^(f1·x/$PnR)·f2`, f2 = 0 read as 1), `$PnG` (divide by the gain), `$TIMESTEP` for the time parameter. Gating-ML gates are defined on scale values.

**Prior art consulted** (permissively licensed; source read, no code copied, all Rust written independently):
- FlowKit 1.3.2, Scott White, BSD-3-Clause, https://github.com/whitews/FlowKit (installed from PyPI into `oracle/`): `_utils/wsp_utils.py` (which workspace elements carry samples, keywords, `spilloverMatrix` with `prefix`/`suffix`/`spectral`, per-channel `Transformations`, `Population`/`Gate`, `eventsInside`, `AndNode`/`OrNode`/`NotNode` with `Dependents`, `Groups`/`GroupNode`/`SampleRefs`; gate coordinates stored untransformed and moved into the transformed space before evaluation; `Comp-` prefixed dimensions refer to the sample's matrix), `_models/gates/_wsp_gates.py` (FlowJo ellipses stored as two foci and four edge points in a 256-bin display space, converted to a 128-vertex polygon; display range 4096 for FlowJo biex, 1 otherwise), `_models/transforms/_wsp_transforms.py` (FlowJo log `(log10(max(x,offset)) − log10(offset))/decades`; FlowJo biex as a 4097-point lookup table ported from cytolib, linearly interpolated and clamped), `_utils/xml_utils.py` and `_models/gates/_gml_gates.py` (Gating-ML element and attribute names; quadrant ranges from sorted divider values and a location), `_models/gating_strategy.py` (evaluation order, parent intersection, one compensation reference per gate, fluorochrome names resolved through the matrix), `_models/transforms/_matrix.py`.
- flowutils 1.2.2, Scott White, BSD-3-Clause, https://github.com/whitews/FlowUtils (commit `b3aa2708eb25953e4e4dd9f9edcba3d503297e50`): `transforms.py`, `compensate.py` (compensated = raw · S⁻¹ via `solve(Sᵀ, rawᵀ)`; spectral OLS via least squares on the non-square matrix), `gating.py` and `gating_c_ext/gate_helpers.c` (winding number with a bounding-box shortcut; a point is inside when the winding count is odd), `logicle_c_ext/logicle.c` (C port of the Moore–Parks code).
- FlowIO 1.4.0 (BSD-3-Clause, already logged in `fcs.md`): `as_array(preprocess=True)` — the scale-value rules above, applied before gating; the time parameter's `$PnG` is ignored; fluorescence channels are those whose `$PnN` does not start with `FSC-`, `SSC-` or `Time`.

**Run as oracles** (black box): FlowKit `Workspace`/`Session`/`GatingStrategy.gate_sample` for population counts, `Sample.apply_compensation` and the transform classes for compensated and transformed values (`oracle/flow.py`). FlowJo's own counts, stored as `count` attributes on `SampleNode`/`Population` elements of workspaces that were saved after analysis, are a second, independent reference.

FlowJo transforms other than `linear`, `log`, `logicle`, `biex` and `fasinh` are reported as unsupported (exit 6) rather than guessed.

## 2026-09-23 — median per population (`analyze gate --median`) (Richard Zimring with Claude as assistant)

**Written before the code.** A population's median of a parameter is computed over the same events the population counts (the evaluator's membership, which `oracle/flow.py` already checks against FlowKit), on scale values (FCS 3.1 §3.2.19–20, as for gating). A name that starts with the workspace sample's compensation prefix (`Comp-` by default; FlowJo's `spilloverMatrix/@prefix`, already read for gate dimensions) is the compensated parameter: the sample's matrix (FlowJo), else the gating file's only matrix, else the FCS file's own spillover, applied with the same solver as `table --compensate`. The median is the middle value, or the mean of the two middle values for an even count (the usual definition, as NumPy and pandas compute it).

**Prior art:** none beyond the entries above; no code read for this. **Oracle** (black box): FlowKit 1.3.2 `Session.get_gate_events` (the events of one gate as a DataFrame of raw or compensated values) and pandas `median`, run by `oracle/batch.py` into `corpus/oracle/batch/gate-medians.json`. FlowJo stores medians only when the user added a statistic; no corpus workspace does, so FlowJo's own medians are not a reference here.

**Corpus files:** `flowkit-8c-ics` with `flowkit-8c-e01`, `-e03`, `-e05`.

**Addendum (same day): matching a renamed FCS file to its workspace sample.** When neither `--sample`, the file name, the `DataSet/@uri` file name nor `$FIL` picks a sample (a file renamed since the workspace was saved, as in a staged share), the sample whose stored keywords (`Keywords/Keyword/@name,@value`, already read) agree with the file's TEXT on every one of `$TOT`, `$BTIM`, `$ETIM`, `$DATE`, `$CYT`, `$CYTSN` present on both sides — at least three compared, `$TOT` among them — is used when it is the only one. Inferred from the workspaces themselves (FlowJo copies the FCS TEXT keywords into each sample); corpus files `flowkit-8c-ics` with `flowkit-8c-e01`, `-e03`, `-e05` (no `$FIL`, renamed from `101_DEN084Y5_15_E0?_0??_clean.fcs`).
