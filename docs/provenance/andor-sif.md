# Provenance log — Andor SIF (`andor-sif`)

Rules: `docs/legal/clean-room-policy.md`. Each entry: date, who, corpus files, prior art (URL + license), what was inferred.

## 2026-10-19 — reader (Richard Zimring with Claude as assistant)

**Prior art read (permissive):** `sif_parser` 0.3.6 by Keisuke Fujii, BSD-3-Clause (https://github.com/fujiisoup/sif_parser; licence checked in the package metadata and the repository), files `_sif_open.py`, `sif_open.py` and `utils.py`, read as documentation. From it: the 36-byte signature `Andor Technology Multi-Channel File\n`; the order of the header items (a line with the SIF version, the acquisition time in Unix seconds and the detector temperature; exposure time, cycle time, accumulated cycle time, number of accumulations, stack cycle time and pixel readout time further on that line; the detector model line; the detector size and the length of the original file name; the user text with its length; the shutter line); the three length-prefixed axis strings (frame axis, data type, image axis); the image-structure line (area, number of frames, number of sub-images, total length, image length) and one line per sub-image (area and binning: width = (1 + right − left) ÷ x binning); one time-stamp line per frame; float32 little-endian samples, frame after frame; the wavelength calibration as polynomial coefficients in ascending powers of the 1-based pixel number, and per-frame calibrations in the user text (`Calibration data for frame N`). Names in our code are ours.

**Black-box oracles:** `sif_parser` 0.3.6 (above) produces the ground truth planes; `sifreader` 0.2.4 by lightingghost (MIT, https://github.com/lightingghost/sifreader) is run as a black box, with a NumPy shim for the binary `fromstring` it calls, on the files `sif_parser` does not read.

**Corpus files used** (`corpus/manifest.toml`, format `andor-sif`): the test data of `sif_parser` (commit 8362a48, BSD-3-Clause) and of `sifreader` (commit fafbaab, MIT); Zenodo 18293266 (CC-BY-4.0, photoluminescence spectra of ZnO-PVA nanoparticles), 15118586 (CC-BY-4.0, electroluminescence images of solar cells), 4904806 (CC0-1.0, an iXon FRET image of Drosophila Kenyon cells); figshare 30795137 and 28054061 (CC-BY-4.0, VUV laser and Raman/PL spectra).

**Observed (hex dumps of the corpus files):**
- SIF versions 65555, 65559, 65564 and 65567 on line 3; detectors DH734, DU401, DU420, DU888, DU897, DU920P, DU940P and iXon models on line 4.
- Line 3's binary bytes sit at fixed places: 10 bytes after the temperature (`\x00 \x00 \x00 \x02 \x00 `), 2 bytes after the number of accumulations (`\x00 `). The remaining binary tokens on that line are never a newline in the corpus, but the reader finds the end of the line by the detector and size lines that follow it, not by the first newline.
- The lines between the shutter line and the axis strings change with the version (spectrograph, intensifier and calibration-version lines, 8 to 22 of them). Every file has the same last part: a line starting with a calibration version (65539 or 65540) followed by single control bytes (`\x01 \x00 \x01 \x00 \x01 \x00` or `\x02 \x00 …`), the coefficient line (four numbers; `0 1 0 0` means pixel numbers), two or three `0 1 0 0` lines, then a few numbers (pixel size in µm such as `13 13` or `16 16`; meaning inferred, not used), then the axis strings. The reader therefore finds the axis strings and the image-structure line by their shape (three length-prefixed printable strings followed by a line of nine or more integers starting with 655xx), not by counting lines.
- Image structure: `65541 1 1024 1024 1 1 1 1024 1024` (or 65538 in version 65555/65559): area left, top, right, bottom, then frames, sub-images, the pixels of all frames, the pixels of one frame (`test_sequence.sif`: 3 frames, 23103 = 3 × 7701, 7701 = 151 × 51). Sub-image line `65538 900 300 1050 250 1 1 0`: left, top, right, bottom, y binning, x binning.
- Time stamps: one line per frame in microseconds (`0`, `1603330`, `3206660` with a stack cycle time of 1.60333 s).
- Between the time stamps and the data: nothing (65555, 65559), a `0` line (65564, most 65567 files), or a `1` line and one more number per frame (65567: `1` then `1122186`). The reader accepts the position after which the data ends exactly where the trailer begins.
- After the data: four `0`/`1` lines, one per further data block; a `1` is followed by a whole block (line 3 onwards) of the same layout (`image.sif`, `cli-0.sif`, `ZP2-1.sif`, `hBN_Raman…`: the second flag; `step_and_glue.sif`: the third). Version 65567 files then end with an XML document (`<Signals><Signal><TInstaImageData><PreAmpGainText>…`).
- Frame data: float32, little-endian, each frame's sub-images in order, rows of `width` values.

**Inferred (flagged in the format notes):** the names of the further blocks (reference, background, live, source, in flag order: the names Andor Solis uses for its data types); that the stack cycle time is the time between frames (it equals the time-stamp step in `test_sequence.sif`); the unit of a `Wavelength` axis (nm; the spectrograph line names the grating blaze in `NM`) and of a `Raman shift` axis (cm⁻¹); that the acquisition time is UTC (Unix seconds).

**Validation:** `oracle/sif_oracle.py`.
