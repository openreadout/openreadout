# Bio-Rad Image Lab `.scn` provenance

## 2026-09-26 — before the reader was written (Richard Zimring with Claude as assistant)

**Corpus files used** (all in `corpus/manifest.toml`, CC-BY-4.0 Zenodo records; licences checked on
the record pages 2026-09-26): `scn-zenodo3517804-p27` (5.2.1, a merged image, imager
type 3), `scn-zenodo6723849-tubulin` (4.1.0, ChemiDoc XRS+), `scn-zenodo11355396-geldoc` (6.0.0,
Gel Doc XR+, cropped), `scn-zenodo7977915-ncbp2` (6.0.1, ChemiDoc MP, IRDye 800CW, 3×3 binning),
`scn-zenodo15237267-lchc-marker` (6.0.1, ChemiDoc MP), `scn-zenodo21792158-porcelli` (6.1.0,
ChemiDoc MP), `scn-zenodo10391734-wbchemi` and `-wbcolor` (3.0.1, ChemiDoc MP chemiluminescence and
colorimetric), `scn-zenodo10419859-paf1` (6.0.0, cropped from 2550×3509), `scn-zenodo13882568-lamp1`
(5.2.1), `scn-zenodo20836084-chemi` and `-cbb` (3.0.1), `scn-zenodo7803294-fbxo7` (5.2.1). Eleven
depositors, Image Lab 3.0.1 to 6.1.0. One further depositor's files are held out
(`docs/benchmark/heldout.md`) and were not opened.

**Prior art consulted:** none for the layout. The container is MIME multipart (RFC 2046, public);
the part names, XML elements and the raw pixel layout were read from the files.

**Copyleft reader, run as a black box only:** Bio-Formats 8.5.0 (`showinf`,
`bfconvert`, GPL) — its `BioRadSCNReader` opens every development file; `showinf` reports the
image size, pixel type (uint16) and byte order, and `bfconvert` gives the planes the corpus test
compares with ours bit for bit.

### Inferred from the files (scratch dumps, not committed)

- The file starts `MIME-Version: 1.0 (Generated by Image Lab <version>)`, then
  `Content-Type: multipart/mixed; boundary="…"`, `Content-Description: Image Lab Image File`,
  `X-LastSaveDate`; header lines end in CRLF; a blank line ends each header block.
- Parts, in order in every file: `ItemHeaderTag` (text/xml: authoring application and version,
  item name, scan id, description, user, channel count, display settings, per-scan display
  transform `low_frac`/`high_frac`/`gamma`/`invert`), `ScanImageTag0` (a nested multipart with
  `ImageData`, application/octet-stream, and `ImageHeader`, text/xml), `ItemProtocolSettingsTag`
  (text/xml: imager type, exposure mode and time, band-detection and molecular-weight settings,
  standard name, and the audit log `ListLogEntries/LogEntry` with Unix timestamps, full name,
  user, type and text such as rotations, crops and "saved as").
- Every leaf part carries `Content-Length`; the ImageData length is exactly width × height × 2 in
  all fifteen files (`ImageHeader/size_pix`), little-endian (`<endian>little</endian>`), one 16-bit
  channel even for colorimetric captures; `scanner/@data_ceiling` and `@max_value` are 65535.
- `ImageHeader`: `name`, `creation_date` (Unix time), `size_pix`, `org_size_pix` (the size before
  cropping), `size_mm` with `known="true"` (the imaged area: 95 × 76 mm on ChemiDoc MP), `image
  @zero_is` (`white` for chemiluminescence and colorimetric blots displayed dark-on-white, `black`
  for gels and fluorescence), `scan_attributes` (name/value/type triples: Imager, Image Date,
  Exposure Time (sec), Serial Number, Software Version, Application, Excitation Source, Emission
  Filter, Binning, Flat Field), `extended_scan_attributes` (flat-field, dark and bias
  corrections applied by the imager), `units` (`Int`), and for the Typhoon import `scaler/moldyn
  @mode="1" @real_scale` (the Molecular Dynamics `.gel` square-root encoding: not applied, see the
  format note).
- The pixel size is `size_mm` × 1000 / `size_pix` (µm): 138.3 µm on the 687-pixel-wide ChemiDoc MP
  captures at 95 mm, consistent with the imager's field of view; Bio-Formats reports the same.
- No file has more than one `ScanImageTag` (`channel_count` is 1 in all) and none stores lane or
  band analysis; the reader keeps every further part in the vendor tree and lists it (`info --view structure`).

## 2026-09-26 — corpus correction (Richard Zimring with Claude as assistant)

A fourteenth development file, a Typhoon FLA 9500 `.gel` scan imported into Image Lab 6.0.0,
came from a Zenodo record that also holds another format's held-out file (a Rotor-Gene `.rex`,
held out 2026-09-24). A record is held out entirely or not at all, so the `.scn` file was removed
from the corpus and from the fuzz seeds (`cargo xtask heldout-check`). The only thing learned
from it alone is the `scaler/moldyn @mode="1"` element of imported Molecular Dynamics scans: the
reader reports it and does not apply the square-root encoding it names, and no file in the corpus
exercises it now. The held-out `.rex` file concerns the qPCR reader, which this work did not touch.
