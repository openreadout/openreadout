# Provenance log — Igor Pro binary waves and packed experiments (`igor`)

Rules: `docs/legal/clean-room-policy.md`. Each entry: date, who, corpus files, prior art (URL + license), what was inferred.

## 2026-10-19 — reader (Richard Zimring with Claude as assistant)

**Vendor documentation read:** WaveMetrics Technical Note TN003 "Igor binary file format" (revised February 1999) and Igor Pro Technical Note PTN003 "Writing Packed Files" (revised February 1999), downloaded from WaveMetrics' public technical-note archive (https://downloads.wavemetrics.com/Downloads/FTP_Archive/IgorPro/Technical_Notes/, `TN003.zip`, `PTN003Win.zip`; no registration, no licence terms on the page). The notes' text (`TN003.ifn`, `PTN003.ifn`) was read. From TN003: the four binary-wave versions (1, 2, 3, 5) and what each adds; the version-dependent layout (binary header of 8, 16, 20 or 64 bytes, wave header of 110 or 320 bytes without its data field, the wave data, 16 bytes of padding in versions 1–3, then the optional sections in a fixed order: formula, note, extended data units, extended dimension units, dimension labels, string indices); the meaning of every header field (wave type bits for double, float, 32/16/8-bit integers, complex and unsigned, 0 for text; the name, its length limits, data and dimension units of up to 3 bytes, the point count, the four dimension sizes, the scaling `sfA × index + sfB` per dimension, full-scale values, creation and modification times in seconds since 1904-01-01); the checksum rule (the first 134, 142, 146 or 384 bytes summed as 16-bit integers give 0); data stored row, column, layer, chunk; complex values as real then imaginary; text waves as concatenated bytes with cumulative end offsets in the string indices; dimension labels as 32-byte NUL-terminated fields, one for the dimension and one per element; files without data when a dependency formula governs the wave. From PTN003: a packed file is a sequence of records, each a header (type, version, length of the data) followed by its data; a set high bit of the type marks a superseded record; the record kinds (variables, wave, data folder start with a 32-byte name, data folder end, recreation procedures, procedures, history, get-history, packed file); variables records start with a header of version 1 or 2 counting system variables (single-precision floats), user numeric variables, user string variables and (version 2) dependent variables; string variables have no terminating NUL; byte order follows the writing platform.

**Prior art consulted:** none. `igor2` (https://github.com/AFM-analysis/igor2, LGPL-3.0-or-later) is run as a black-box oracle.

**Observed (hex dumps):**
- Byte order: the version is a 16-bit integer at offset 0; files whose first byte is 0 store it big-endian (`00 02` in `mac-version2.ibw`), the others little-endian (`05 00`, `02 00`). TN003 states the rule the other way round; the files decide.
- Version 2 (`mac-version2.ibw`, `win-version2.ibw`: a 5-point float wave named `version2` with values 5, 4, 3, 2, 1 and the note `This is a test.`): binary header = version (0), wave-section size (2, = 146), note size (6, = 15), an unused 32-bit field (10, = 0), checksum (14). Wave header from 16: type (16, = 2), the name in a 20-byte field (22), the point count (58, = 5), the X step as a double (64, = 1.0) and X offset (72), two 32-bit dates (112, 118: 3001251979 and 3001573594 s after 1904, both in 1999), the data at 126 (5.0 … 1.0 as floats), 16 bytes of padding, then the 15-byte note. The units fields (50, 54: 4 bytes each) are empty here; their place follows from the field list and sizes in TN003 and the name field's end, and was checked on the version-5 files' unit fields below. The first 142 bytes sum to 0 as 16-bit integers in both byte orders.
- Version 5 (all other binary waves and every wave record of the packed files): binary header = version (0), checksum (2), wave-section size (4), then fourteen 32-bit section sizes. Located by matching the file length: 64 + wave-section size + the sum of the sizes at 8…56 equals the file length in 10 files; in the others the note (`ScanSize: …` text, Asylum Research AFM images) starts right after the data, so offset 12 is the note size and offset 8 the formula size (formula before note, as TN003 orders the sections). Sizes at 36, 40, 44, 48 are the dimension labels of dimensions 0–3 (`70300BesselFilter.ibw`: 192 = 6 × 32 for 5 rows, 96 = 3 × 32 for 2 columns; the AFM images: 128 or 160 for 3 or 4 layers, whose labels `HeightRetrace`, `DeflectionRetrace`, … follow the note). By elimination 16 is the extended data units and 20…32 the extended dimension units; 52 the string indices (text waves in the packed files). The first 384 bytes sum to 0.
- Version 5 wave header from 64: creation time (68), modification time (72; later than 68 in every file), point count (76, = the product of the dimension sizes), type (80: 2 float, 4 double, 0 text, 8 a signed 8-bit integer wave in a packed file whose values are small integers), a 16-bit 1 at 90 (TN003: the wave-header version is 1 for version 5), the name in a 32-byte field (92; text after the NUL is left-over memory), the four dimension sizes (132…144; unused dimensions 0), four doubles of step (148…172) and four of offset (180…204) — AFM images: step 1.17647e-8 m, the 3 µm scan size of their note over 255; a force curve: step 5e-4 with dimension unit `s` —, the data units (212) and the four dimension units (216…228), 4 bytes each (`m`, `nm`, `mV`, `s` in the corpus), full-scale flag (236) and values (240, 248). Data starts at 384; its size is the wave-section size − 320.
- Asylum Research AFM images append bytes after the last section TN003 describes (a byte thumbnail and `Version:2;DataType:Byte;…` text): they are left unread and counted (`trailing_bytes`).
- Packed experiments (11 files, all little-endian): records of an 8-byte header — 16-bit type, 16-bit version, 32-bit data length — chaining exactly to the end of every file. Types by content: 3 holds one version-5 (or version-2) binary wave; 9 has 32 bytes holding a NUL-terminated folder name and is matched by a later 10 with no data; 1 starts with a variables header; 2, 4 and 5 hold text (history, recreation procedures starting `// Platform=`, procedures starting `#pragma`); 7 is empty after the history; 8 holds a packed notebook. 11, 13–18, 20–22, 26, 33 and 42 hold window and package settings and are skipped as PTN003 says.
- Variables record (version 1 header): version (0), system-variable count (2, = 21), user numeric count (4), user string count (6); the system variables as 21 floats (8…92); each numeric variable as a 32-byte name, two 16-bit fields (1, then 4 = double) and two doubles (real, imaginary) plus 4 bytes (56 bytes); each string variable as a 32-byte name, a 16-bit length and its bytes (`S_path` = 43 bytes `C:igorWinTrans_templ:Graph1_3transfered.pxp`, the record ending exactly there).

**Inferred (flagged in the format notes):** the type values of 16- and 32-bit integers (16, 32), unsigned (64) and complex (1) and 64-bit integers (128) follow the bit pattern of the observed values (2, 4, 8) and TN003's list; no corpus file holds one yet. The version-1 and version-3 layouts follow TN003's sizes and the version-2 field positions. The version-2 variables header and its 32-bit string lengths follow PTN003; no corpus file has one. The meaning of the 16-bit field before the numeric type in a numeric variable. Which axis is X: Igor shows rows along the horizontal axis, so dimension 0 becomes X.

**Validation:** `igor2` 0.5.14 run as a black box (`oracle/gen.py` `igor`).
