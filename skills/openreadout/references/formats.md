# Formats in detail

Per-family notes for `SKILL.md`: where each fact lives in the JSON, family workflows and known limits. `openreadout self formats --json` (`known_gaps`) is authoritative for limits, `openreadout self schema <command>` for fields.

## Where facts live in `info`

Every `info` reply (every `--view`) also has `data.experiment`, the same shape for every format: `sample` (`id`, `name`, `well`, `barcode`, `sequence_position`, and `source_field`, the field the id came from), `instrument` (`vendor`, `model`, `serial`, `software`, `kind`), `method` (`name`, `technique` and `assay` as ontology terms `{id, label}` from CHMO, FBbi, OBI or PSI-MS, `parameters` as `{value, unit, ucum}`), `acquisition` (`started_at`, `ended_at`, `operator`, `duration_s`, `comment`), `measurements[]` (`kind`, `indices`, `what` in scientific words such as `LC-MS, negative mode, ESI, 2,031 scans, MS1`, `technique`, `terms`) and `provenance` (every value's `from` field and `source`). Missing parts are omitted: a file that records no sample id has no `sample.id`; say so rather than guessing from the file name. For "what sample / which well / what method / who ran it" questions, read `data.experiment` first.


- `data.images[]` is one entry per image (a scene, position or tile). Indices are what `--image` takes.
- FCS files have no images; `data.tables[]` is one entry per data set: `row_count` (events, `$TOT`), `columns[]` (`name` = `$PnN`, `label` = `$PnS`, storage `dtype`, `range` from `$PnR`, `extra` with gain/voltage/wavelength), and `extra` with `instrument`, `software`, `acquisition_start`, `spillover` (matrix), `platform` (`family` bd-facsdiva / bd-spectral / cytek-spectral / beckman-cytoflex / sony-spectral / mass-cytometry, `vendor`, `technology` conventional/spectral/mass, lasers, full-spectrum `detectors_by_laser`, `unmixing`, CyTOF `markers_by_isotope`), `vendor_keywords` (non-`$` keywords, verbatim). Columns carry `extra.channel_kind` (scatter, fluorescence, spectral_detector, mass, time, …), `measure` (area/height/width), `laser`, `metal_tag` and `marker`.
- Electrophysiology files have `data.traces[]`: `sweep_count` (ABF episodes, Neuralynx segments, Blackrock data packets, Plexon gap-free runs; 1 for SpikeGLX/Intan), `sample_count` (samples per sweep; `extra.sweep_sample_counts` when sweeps differ), `sample_rate_hz`, `channels[]` (`name`, `unit`, `scale`, `offset`: value = raw × scale + offset), `start_s`, and `extra` (ABF: `protocol`, `created_at`, `tags`, `outputs[].epochs` command waveforms; Intan: one trace per signal kind, `name` = `amplifier`, `auxiliary`, `digital_in`, …). Neuralynx NEV/NSE/NTT and Blackrock NEV files have `data.tables[]` of events/spikes instead.
- NMR and JCAMP-DX files have no images; `data.traces[]` is one entry per FID or spectrum: `name` (`fid`, `ser`, `pdata/1`, `spectrum`, or the JCAMP-DX `##TITLE=`), `sample_count`, `sweep_count` (2D/3D rows, NTUPLES pages, Varian traces), `channels[]` (`real`/`imag`; Bruker 2D/3D processed `real`, `ri`, `ir`, `ii` / `rri` …; `y`, `x`; `scale` = the factor already applied), `sample_rate_hz` (0 for spectra), and `extra`: `axis` `{quantity, unit, first, step}`, `nucleus`, `spectrometer_frequency_mhz`, `pulse_program`, `solvent`, `temperature_k`, `scans`, `acquired_at`, `probe`, `group_delay_points` (Bruker), `data_type`, `observe_frequency_mhz` (JCAMP-DX).
- A Bruker data set is a **directory**: pass the experiment directory `name/1/` (or its `fid`, `acqus`, `pdata/1`). The directory above several experiments is refused with the list of experiment numbers (exit 2). A Varian/Agilent VnmrJ data set is a `name.fid/` directory (`fid` + `procpar`; pass the directory or its `fid`); a folder of several `.fid` directories is refused the same way. JEOL Delta data are single `.jdf` files.
- FT-IR/Raman files (OPUS `.0/.1/…`, OMNIC `.spa`/`.spg`, WiRE `.wdf`, PerkinElmer `.sp`) have `traces[]` too: one per kind of spectrum (OPUS: the result — absorbance/transmittance/reflectance — first, then sample/reference single channels, interferograms, phases), one sweep per spectrum of a group, series or map. `extra.axis` `{quantity: wavenumber|raman_shift|wavelength, unit: 1/cm|nm, first, last, step}`; WiRE's Raman-shift list is uneven: channel 0 holds the x values (`axis.irregular: true`), channel 1 the intensities. `extra`: `resolution_cm1`, `scans`, `background_scans`, `apodization`, `laser_wavenumber_cm1`, `laser_wavelength_nm` (Raman), `grating`, `exposure_time_s`, `objective`, `laser_power_percent`, `accumulations`, `acquired_at`; WiRE maps are also `images[0]` (one channel per band).
- Agilent (Varian) Cary `.dsw`/`.bsw`/`.bsk`: one trace per set of spectra with the same wavelengths (a sweep per spectrum; baselines a separate `baseline absorbance` trace), absorbance in AU as stored; `extra.spectrum_names` names the sweeps; for several spectra table 0 has `collected_s` and, in kinetics files, `scheduled_min` (the method's schedule, not the collection time); `experiment` has model (`Cary 4000`, `Cary 60`), operator, software, local `started_at` (no zone) and scan parameters.
- JASCO `.jws`: one trace per channel (a CD run: `circular_dichroism` (mdeg), `ht_voltage` (V), `absorbance`); `extra.axis` wavenumber, Raman shift (irregular: channel 0 holds x), wavelength (nm) or time (no unit); `experiment` has model, serial, sample, UTC `started_at`, and for FT-IR `accumulations`, `resolution`, `aperture`, `scan_speed`, `gain`, `filter`, `light_source`, `detector`.
- Bench instruments: ÄKTA/UNICORN `.res`/`.zip` — one trace per curve (channel 0 the value, channel 1 the volume in ml; `extra.axis` = retention volume), tables for fractions, injections, logbook and UNICORN's peak tables; MicroCal `.itc` — trace 0 thermogram (µcal/s), table 0 injections, concentrations in `experiment.method.parameters`; Biacore `.blr` — one trace per stored curve (`extra.cycle`, `flow_cell`, `reference_subtracted`, `report_points`), tables `report_points`, `cycles`, `event_log`; Seahorse `.asyr` — traces 0-1 are the O2/pH sensors' corrected emission (channel 0 time in s, one channel per well), trace 2 temperatures, tables `wells`, `measurements`, `injections`, `protocol` and (standard 96-well plate, validated settings) `rates` with OCR, ECAR and PER, traces 3-4 the O2 (mmHg) and pH levels; Octet `.frd` — trace 0 the sensorgram (`time` s, `response` nm, `step`), table 0 the assay steps; Zetasizer `.dts` — table `records` (one row per record: size or zeta results), table `peaks`; GenePix `.gpr` — table 0 is the feature table with GenePix's own column names (`Error` → NaN), scan settings in `experiment.method.parameters`; Image Lab `.scn` — one 16-bit image per scan, pixel size only when Image Lab marks the imaged area known, audit log table.
- Non-uniform sampling: the schedule is a table (`tables[]`: Bruker `nuslist`, one `index_N` column per indirect dimension; JEOL `axis_list`, the sampled indirect times) — `export FILE --table 0 -o schedule.csv` or MCP `openreadout_table`. Rows are returned as acquired; there is no NUS reconstruction.
- Sizes: `size_x`, `size_y` in pixels; `size_z`, `size_c`, `size_t` counts; `plane_count = z*c*t`.
- `pixel_type` is OME's spelling (`uint8`, `uint16`, `float`); `samples_per_pixel` is 3 for RGB.
- `physical_size.{x,y,z}` are micrometres per pixel; missing means the file did not record it.
- `provenance` (in `info --view full`) says where each field's meaning came from: `spec`, `vendor-impl`, `prior-art`, or `inferred`. Trust `inferred` fields less.
- `vendor` (in `info --view full`) is the raw vendor metadata converted to JSON with names untouched. Use it when the normalized fields are not enough.
- Units and conventions are the same for every format ([metadata conventions](https://openreadout.github.io/openreadout/guides/metadata.html)): lengths µm, wavelengths nm, times s unless the name ends in `_ms`, timestamps ISO-8601 UTC (`Z`; a `notes` entry says when the source has no time zone, as in FCS), colours `#RRGGBB`, `channels[].index` = the C index `--select c=` takes, `dimension_order` = the source's storage order (planes are always addressed by c/z/t).
- `images[].extra.frames[]` (in `info --view full`, ND2 today) is one record per acquired frame: `frame`, `t`, `z`, `time_ms` (since the experiment start), `acquired_at` (ISO-8601 UTC), `stage_x_um`/`stage_y_um`/`stage_z_um`, and where recorded `pfs_status`, `pfs_offset`, `exposure_ms`, `camera_temperature_c`, other columns under `tags`. `frame_records_total` and `frames_truncated` say whether you have them all; rerun with `--all-frames` if not.

## Workflows by family

**"What is this file?"** → `info FILE --view explain --json` gives a ready-made plain-English `summary` and `paragraphs` (built from the same fields as `info`), `caveats` to pass on, and `suggested_commands` for the next step; relay them, adapting to the user's level. For numbers you will compute with, use `info --json`. Mention `notes`/`caveats` (they flag things like pyramids skipped or tiles not stitched).

**"Analyze it in Python."** → if `import openreadout` works (`pip install openreadout`), read directly: `f = openreadout.File(p)`; `f.read_plane(image, c=, z=, t=, level=, region=)` / `f.read_image(image)` give NumPy; `f.to_dask(image)` / `f.to_xarray(image)` are lazy (dims T, C, Z, Y, X, µm/s coordinates, channel names); `f.to_arrow()` / `f.to_pandas()` for tables, traces and spectra. Otherwise `export FILE -o FILE.ome.tiff` then `tifffile.imread('FILE.ome.tiff')` or `bioio.BioImage('FILE.ome.tiff')`. The export is verified by reading it back before it is reported (`verified: true`). For big files export a subset: `--image 0 --select t=0`, `--level N`, `--region`.

**"Open it in napari / a web viewer / the cloud", or the image is very large.** → `export FILE --format ome-zarr -o FILE.ome.zarr`. A single image sits at the store root; a multi-image file (scenes, positions, tiles) becomes a collection with one image per group `FILE.ome.zarr/0`, `/1`, … (listed in `OME/zarr.json` `series`). In Python: `bioio.BioImage('FILE.ome.zarr/0')` or `ome_zarr.reader`. Arrays are `t, c, z, y, x`; RGB samples become three channels.

**"When was each frame taken / where was the stage?"** → `info FILE --view full --json --no-vendor --all-frames` and read `images[i].extra.frames[]` (`time_ms`, `acquired_at`, `stage_*_um`, `exposure_ms`). `images[i].acquired_at` is the experiment start; `extra.time_periods` lists the phases of a multi-phase time-lapse.

**"What is in this FCS file / give me the events."** → `info FILE.fcs --json` for parameters, event counts, cytometer, date and spillover; `export FILE.fcs -o events.csv --labels` for the event matrix (`pandas.read_csv('events.csv', header=[0, 1])` with `--labels`), or `export FILE.fcs --format parquet` for typed columns with units and labels in the schema (`pandas.read_parquet`, polars, DuckDB). `export` values are raw channel values: compensation (`extra.spillover`) and `$PnE` log/`$PnG` gain scaling are not applied — say so, or use `table FILE --compensate --transform logicle --json` (mass cytometry: `--transform arcsinh-cofactor:5`), which applies them and records the steps in `processing`. Over MCP, `openreadout_table` returns rows as JSON with the same options (max 10000 per call, page with `first_row`).

**"How many cells are in each gate of this FlowJo workspace?"** → `analyze gate FILE.fcs --workspace analysis.wsp --json` (or `--gatingml gates.xml`); report `count` and `percent_of_parent` per `path`. `stored_count` is what FlowJo saved; small differences (a few events on rare populations) are expected, and `notes` lists them. Several samples in the workspace: pass `--sample`; `analyze gate --workspace W.wsp --json` alone lists samples, groups, matrices and the gate tree. Per-event membership: `table FILE.fcs --workspace W.wsp --population /Lymphocytes/Singlets --max-rows 10000 --json`. Over MCP: `openreadout_analyze` with `kind: "gate"` (`options`: `workspace` or `gatingml`, `sample`).

**"What is in this recording / show me sweep 3."** (ABF, ATF, NCS, NSx, SpikeGLX, Intan, PLX/PL2, NWB, or a recording directory) → `info FILE --json` for sweeps, channels, units and sample rate; `trace FILE --sweep 3 --json` for statistics and the first samples; `export FILE --sweep 3 -o sweep3.csv` for the whole sweep (`pandas.read_csv`), `export FILE --format parquet` for every sweep in one table, or `export FILE --format nwb` for an NWB 2.x file (pynwb, DANDI; add the subject with pynwb before an upload). Values are already in physical units; say which unit. Over MCP, `openreadout_trace` returns the same slice (max 10000 samples per call, page with `first_sample`). In Python: `openreadout.File(path).read_trace(trace, sweep)` → NumPy `(channels, samples)`.

**"What is in this NMR data set / give me the spectrum."** → `info name/1 --json` for nucleus, frequency, pulse program, solvent, temperature and the traces (`fid` or `ser`, then one per `pdata/<n>`). `trace name/1 --trace 1 --json` (statistics, first samples and `axis`) or `export name/1 --trace 1 -o spectrum.csv` (every point with its ppm) gives the processed spectrum; trace 0 is the raw FID (`real`/`imag`, time axis). `export name/1 --format jcamp` (add `--trace 1` for the spectrum) writes JCAMP-DX for MestReNova, nmrglue or spectral databases (`exact: true` = bit-exact). Bruker values are scaled by 2^NC / 2^NC_proc; the digital-filter group delay is reported (`extra.group_delay_points`) and removed only when processing (`analyze nmr-peaks`, `--process`). Varian `.fid` directories: trace 0 is the FID; sweeps are the traces in file order (arrayed and nD data are not reordered: `extra.arrayed_parameters`, `indirect_dimensions` say how). JEOL `.jdf`: one trace, an FID (`fid`) or a processed spectrum (`spectrum`, ppm axis); values are as stored (nmrglue returns the complex conjugate); 2D complex data alternate indirect real (even sweeps) and imaginary (odd) rows. JCAMP-DX (`.jdx`, `.dx`): one trace per data block; 2D NTUPLES pages are sweeps. Over MCP, `openreadout_trace` returns statistics and samples as JSON (max 10000 samples per channel per call, page with `first_sample`).

**"Where is the strongest band / what resolution, laser, how many spectra?"** (OPUS, OMNIC, WiRE, PerkinElmer) → `trace FILE --json`: `channels[].stats.argmax_axis_value` is the wavenumber (or Raman shift) of the maximum — for transmittance the band is the minimum (`x_at_min`); OPUS trace 0 is the result spectrum, pick another with `--trace`. `info FILE --json` → `traces[0].extra` (`resolution_cm1`, `scans`, `laser_wavelength_nm`, `grating`, `exposure_time_s`) and `sweep_count` (spectra in a map, series or `.spg` group); `experiment.method.parameters` holds the same with units. A WiRE map: `table FILE --json` gives each spectrum's stage `x_um`/`y_um` and WiRE's own analyses; `preview FILE --select c=N` draws the map at band N (channel names are the band positions). `export FILE --format jcamp [--sweep K]` writes JCAMP-DX (IR: `##YUNITS= ABSORBANCE` …; Raman: `##XYPOINTS` because the axis is uneven); `export FILE -o spectrum.csv` writes x and y columns.

**"Integrate this band / compute a band ratio or ageing index / where is the band maximum in 1000–1100 cm⁻¹?"** (any spectrum: OPUS, OMNIC, WiRE, PerkinElmer, JCAMP-DX IR/UV, NMR spectra in ppm) → `analyze peaks FILE --x-range 980:1060 --x-range 1350:1525 --json`: `spectra[0].regions[k]` has `area` (linear baseline between the window's end samples; `--baseline none` for the plain integral), `area_no_baseline`, `max_x`, `max_height`, `centroid`, the bands inside; a ratio or index is `regions[0].area / regions[1].area` (state the baseline you used when the question does not). Windows are in the axis's own units (see `info` → `traces[].extra.axis`), either order. Detected bands without windows: `spectra[0].peaks[]` (`x`, `height`, `area`, `width_half`). Transmittance/reflectance: bands are minima (`bands_are_minima`), region areas are negative over a band — convert to absorbance for quantitative areas. Over a folder: `analyze peaks DIR -r --x-range … -o regions.csv` (one row per file × region) or `batch peaks DIR --set x_range=[[980,1060]]`. `trace FILE --x-range A:B` restricts the statistics to the window.

**"What is in this cryo-EM / TEM file?"** (MRC, DM3/DM4, SER, EMD) → `info FILE --json`: `physical_size` is µm per pixel (MRC also gives `extra.pixel_size_angstrom`), `extra.voltage_kv`, `extra.magnification`, `instrument` (microscope, camera, software). An MRC `.mrcs`/movie/tilt series is one image with the sections as T; a map/tomogram has them as Z (`extra.layout` says which). EPU/SerialEM per-frame metadata (tilt angle, dose, stage) is in `info --view full --all-frames` → `images[0].extra.frames`. `export FILE -o FILE.ome.tiff` gives Fiji/napari a file with µm calibration.

**"What is in this plate-reader export / give me the wells."** (`.txt`/`.csv`/`.xlsx` from Gen5, SoftMax Pro, BMG MARS/SMART Control, EnVision/Kaleido, Tecan i-control/Magellan, SkanIt, or any sheet of plate matrices) → `info FILE --json`: one table per plate; `extra.export` names the software, `extra.reads[]` each read's `mode` (absorbance, fluorescence, luminescence), wavelengths, unit and `origin` (`measured`, or `calculated` by the vendor software: blank-corrected, normalized, ratios; `formula` when stored; the `read` column label in `table` lists them too; answer questions about measured values from `measured` reads only), plus instrument, plate type, temperature and `non_numeric` cells (`OVRFLW`, `Range?` → NaN). `export FILE -o plate.csv` gives `well,row,col,read,wavelength_nm,time_s,value` (pivot in pandas: `df.pivot_table(index='well', columns='read', values='value')`); `export FILE --format asm` gives Allotrope ASM JSON for LIMS/ELN pipelines. Values are exactly as exported (OD stays OD). Gen5 experiment files (`.xpt`) are read directly (every plate and read, kinetic times included; the mode comes from the read name). SoftMax Pro binary documents (`.pda`, `.sda`) are read directly where their layout is validated (SoftMax Pro 5 absorbance endpoint/kinetic; SoftMax Pro 6/7 endpoint absorbance/fluorescence/luminescence); other sections exit 6 with a hint to export text. A SoftMax Pro 5 document's template becomes `extra.layout` (`Sample`, `SoftMax group`, `Role` blank for the `Blank` group), so `analyze assay` finds blanks without a layout file; values are raw (SoftMax Pro's exports subtract the plate blank).

**"What is the concentration of sample X / the IC50 / the Z′ / the max rate / the doubling time?"** → `analyze assay` (above), not a hand-written fit. Start with `analyze assay wells FILE --json` to see `layout.roles` (what the export's own layout already assigns; `unassigned` wells need `--layout` or flags) and `warnings` (role names it could not place). Gen5 `POSCON`/`NEGCON` are positive/negative controls; vehicle/DMSO/untreated wells stay controls of unknown sign until `--role DMSO=negative` (MCP `roles`). Percent activity of a screen: `analyze assay wells FILE --normalize controls` → `wells[].percent_effect` (0 % = negative, 100 % = positive control mean). Standard curve: `analyze assay curve FILE [--standard A1,A2=100 …] [--blank H1,H2] --json` → `wells[].back_calculated` (the concentration in the well), `final_concentration` (× dilution), `flag`; use the model and weighting the user names (vendor software often uses 4PL; linear for BCA/Bradford); report `below_range`/`above_range`/`*_curve` flags instead of a number when a value is outside the standards. IC50: `analyze assay dose-response FILE --layout MAP.csv --json` → `compounds[].ec50` (+ `ec50_ci_low/high`, `hill_slope`); say whether it was normalised (`--normalize controls` → also `absolute_ec50`). Z′: `analyze assay qc FILE --positive … --negative … --json`. Rates: `analyze assay kinetics FILE --json` (`max_slope_per_min`, window of 5 points or a tenth of the reads; `--window N` to match a stated window); growth: `analyze assay growth FILE --json` (`doubling_time_h` from the steepest ln-OD window, `logistic_doubling_time_h` from the growthcurver-style logistic fit — they differ; name the one you report). Methods: https://openreadout.github.io/openreadout/guides/plate-analysis.html. Over MCP: `openreadout_analyze` with `kind: "assay"` (`options.plot: true` returns the curve image).

**"What is the Cq of GAPDH in well A1? How many NTC wells? What was the annealing temperature? Tm in B3?"** (qPCR: `.rdml`, `.lc96p`, `.eds`, `.rex`, `.ixo`) → `analyze qpcr FILE --json` (filter with `--well A1 --target GAPDH`): report the vendor's `cq` (say "undetermined" when `cq_status` is `undetermined`: no amplification, `cq` null — never average it as 40), count wells with `task: ntc`, `acquisition_temperature_c` is the temperature fluorescence is read at during cycling (the annealing/extension step of a two-step PCR), `tm` lists melt peaks in °C. Mean Cq per target and how many wells are undetermined: `targets[]` (`cq_mean` over non-excluded wells with a Cq, `counts.undetermined`; `--sample S` restricts to one sample); `relative_quantities[].undetermined` counts the replicates ΔΔCq left out. Only when the user asks to count undetermined wells at a fixed Cq: `--undetermined-as 40`. Fold change: `analyze qpcr FILE --ddcq --reference 18s --control CALIBRATOR --json` → `relative_quantities[].rq` (2^−ΔΔCq; `vendor_rq` is the instrument software's own when stored). PCR efficiency from standards: `--standard-curve` → `efficiency_percent` (and the vendor's when stored). Curves: `trace FILE --trace N --channel C` (traces are per run and dye: `amplification <dye>`, `… baseline-corrected`, `melt <dye>`, `melt <dye> -dF/dT`; channel names are `A1 GAPDH`); plots: `preview FILE --trace N` (all wells overlaid), `preview FILE --table 0` (Cq heat map). Bio-Rad `.pcrd` exits 6: it is encrypted — ask for an RDML export from CFX Maestro. Several plates in one RDML file: records carry `run`.

**"Is this file OK?"** → `check FILE --json`. `ok: false` with `truncated`/`missing_planes` findings means the acquisition or copy was cut short; say which planes are missing (the message tells you). Exit code 4 is the machine signal.

**Batch a directory.** `info -r --jsonl --skip-unknown DIR` (one line per instrument file; `path` names it), `check -r --jsonl DIR` to find damaged files (exit 4 if any), `export -r --skip-unknown DIR -o OUT_DIR` to convert a tree, `info --view full --sidecar -r --skip-unknown DIR` to leave a `.openreadout.json` metadata file beside every data file (re-runs skip unchanged files). Read each line's `ok` before `data`.

**"Process this FID / where are the peaks / integrate these regions."** → `analyze nmr-peaks DIR --json` (`main_peak.ppm`, `peaks[]`, `integrals[]`). Say whether `source` was `processed` (the operator's TopSpin/Delta spectrum) or `fid` (processed here; `processing.phase_mode` stored/auto). For FID-only data sets (no `pdata`, Varian, JEOL FIDs) it processes the FID automatically; `--from fid` reprocesses even when a spectrum exists. Ratios: `--integrate 7.3:7.2 --integrate 3.7:3.6 --integral-reference 0=1`.

**"How many action potentials / rheobase / input resistance of this cell?"** (ABF current-clamp steps) → `analyze ephys-features FILE --json`: `sweeps[N].spike_count` (whole sweep; `spike_count_stimulus` inside the step), `cell.rheobase_pa`, `cell.input_resistance_mohm` (from the hyperpolarising steps), `cell.tau_ms`, `cell.sag_ratio`. The injected current per sweep comes from the protocol's epoch table (`sweeps[].stimulus_pa`, relative to holding). Voltage-clamp membrane tests: `cell.holding_current_pa`, `access_resistance_mohm`, `membrane_capacitance_pf`. Extracellular recordings: `analyze spikes FILE --trace N --json` (pick the broadband stream).

**"What is in this chromatogram / HPLC or GC run?"** (Agilent ChemStation `.D` directory or `.ch`/`.uv`/`.ms`, Agilent OpenLab CDS `.dx`, ANDI `.cdf`, Waters `.raw` directory, Shimadzu `.lcd`, Thermo Chromeleon `.cmbx` archive, Waters Empower `.arw` export) → `info PATH --json`: one `data.traces[]` entry per detector signal (`channels[0].unit` `pA`/`mAU`, `extra.signal` such as `DAD1 A, Sig=254,4 Ref=360,100`, `extra.wavelength_nm`, `extra.sample_name`, `method`, `operator`, `acquired_at`, `extra.axis` = retention time in minutes); a `.uv` DAD file is one trace with a channel per wavelength; `.ms`/ANDI-MS runs are `data.spectra[]` (`spectra PATH --index I --json`); ANDI peak tables and Waters MRM functions are `data.tables[]`. `trace PATH --trace N --json` gives statistics (min/max/argmax = the main peak; `argmax_axis_value` = its retention time in min, `argmax_time_s` in s; `argmax` is a sample index from the sweep start, and runs can start before 0 min, so never compute RT as index / rate) and first samples; `export PATH --trace N -o run.csv` writes `retention_time_min` + the signal. Shimadzu `.lcd`/`.gcd`: chromatograms, PDA and status traces (pump pressure, oven temperature; `extra.detector` `status`), and LabSolutions' own integration in `data.tables[0]` (`vendor_peaks`: `table PATH --json` for retention times, areas in µV·s/µAU·s, heights, plates, tailing); LC-MS data are not decoded.

**"What is in this mass-spec run?"** (Thermo `.raw`, mzML/mzXML/imzML, timsTOF or Agilent MassHunter `.d` or Waters `.raw` — pass the directory itself; Sciex `.wiff` with its `.wiff.scan` beside it) → `info FILE --json`: `data.spectra[0]` has `scan_count`, `ms_levels`, `rt_range_s`, `instrument` (model, software version) and `extra` (sample name, acquisition time, serial, method summary, MS1 scan filters, counts per MS level). `spectra FILE --json` lists scan headers without decoding peaks (per scan `index`, `scan_number`, `ms_level`, `rt_s`, `polarity`, `precursor_mz`, `precursor_charge`, `isolation_window_mz`, `activation`, `collision_energy`, `scan_filter`, the file's stored `total_ion_current`/`base_peak_mz`), filtered by `--ms-level`, `--polarity`, `--rt START-END` (minutes), `--precursor MZ` (`--tol` Da, default 0.01, or `--ppm`), `--charge`, `--activation`, `--filter TEXT`; `matched` and `ms_level_counts` count every match (answer "how many" from them; `--count` lists none), `--offset/--limit` page, `--csv` streams all rows; `batch spectra DIR --set ms_level=2` gives one table over many runs; `spectra FILE --scan N --json` returns one scan with its peaks; `export FILE --format mzml` hands the whole run to OpenMS, MZmine, pyteomics or msconvert-based pipelines; `export FILE --format parquet --spectra` gives one row per peak (`scan, rt_s, ms_level, precursor_mz, mz, intensity`) plus a per-scan table for pandas/DuckDB.

**"Show me the slide label / overview."** → `info FILE --view structure --json`, find `kind: attachment` rows (`Label (CZI)`, `SlidePreview (CZI)`, `Thumbnail (JPG)`), then `export FILE --attachment Label -o label.czi` and `export label.czi -o label.ome.tiff` (or open the `.jpg` thumbnail directly).

**"When was each frame taken?"** → `info FILE --view full --json --no-vendor --all-frames`: `images[].extra.frames[]` has `acquired_at`, `time_ms` and stage positions (CZI: per (c, z, t) plane; ND2: per frame; DCIMG: per frame with the camera's `frame` counter; MetaMorph STK: per plane `delta_t_s`, `time_local`, stage positions); CZI `images[].extra.time_stamps_s` has the per-T time stamps.

**Whole-slide or other huge images (planes of GBs).** → Never read full resolution whole. `info` → `images[].resolution_levels` gives each level's size, downsample factor (pixel size at level L = `physical_size × downsample`) and tile size. Look with `preview FILE --json` (picks a small level), then zoom: `preview FILE --region X,Y,W,H` (full-resolution pixels; reads only the tiles needed). Numbers of a window: `stats FILE --level N --region X,Y,W,H --json` (region in the pixels of that level); raw pixels: `check FILE --planes --level N --region ... --dump-dir DIR`. Cut out a field: `export FILE --region ... -o field.ome.tiff`. In Python: `openreadout.File(p).read_plane(0, level=N, region=(x, y, w, h))`, lazy tiles with `to_dask(0, level=N)`.

**"How many wells / which channels / is this screening plate complete?"** (a Harmony measurement folder or `Index.idx.xml`, a Columbus `ImageIndex.ColumbusIDX.xml`, an ImageXpress `.HTD` or plate folder, a CellVoyager folder or `MeasurementData.mlf`) → open the folder or index, never one TIFF: `info PLATE --json` → `data.plate` (`id` = barcode, `plate_type`, `rows`, `columns`, `wells[]` with the `images` of each well, `field_count`, `planes_missing`, `complete`); each image is one field of view (`images[i].extra.well`, `field`). Missing files of a partial copy: `check` (per well, exit 4). Intensities per well: `stats PLATE --per well --select c=N` (never-acquired planes are left out, missing files skipped and counted); one field: `stats --image I`. Convert: `export PLATE --format ome-zarr` (OME-NGFF HCS plate; `--skip-incomplete` for partial copies, `--well C05`), `--format ome-tiff --per-image` (one file per field).

**"Show me what it looks like."** → `preview FILE -o FILE.png` (then view the PNG). Multi-channel images: `--composite` (optionally `--mip z` for a stack); one channel: `--select c=N`; faint or saturated: `--contrast percentile:1,99.5` or `min-max`. Traces, spectra and plates get plots and heat maps from the same command. Over MCP, `openreadout_preview` returns the picture as image content (≤ 750 kB) so you can see it directly. Describe only what you see and what `--json` reports (contrast limits are display choices, not data).

**Did the conversion change anything? / Are these two files the same?** → `check A --against B --json`: `identical`, `planes.mismatched`, and `metadata.differences[]` (expected ones after a format change, e.g. vendor-only fields, are worth naming, not alarming). `--tolerance 1` for lossy or rescaled data; `--no-pixels` for a quick metadata/geometry check.

**"What is the area / height / purity of a peak? At what time does m/z X elute?"** (any chromatography or MS file) → `analyze peaks FILE --json` integrates the default chromatogram (first detector trace, else the TIC); pick the signal with `--trace N`, `--mz M --ppm 10` (XIC), `--transition Q1>Q3` (SRM) or `--tic`. Read `peaks[]` (`rt_min`, `area`, `height`, `area_percent`, `snr`, `tailing_factor`) and `main_peak_area_percent`; say the method (`method.baseline`, `area_unit`: signal×min by default, `--area-seconds` for what vendor reports show). `--rt 5.3 --window 0.2` returns the peak near an expected time; `--targets compounds.csv -o results.csv` quantifies a compound list over many files (one row per compound per file). `analyze chromatogram FILE --mz M --json` gives the trace itself (`apex_rt_min`). The default `--baseline auto` ends peaks where they meet a sloped background (solvent tail, drift) and gives `baseline_reason` per peak; if a vendor report still differs, compare `--baseline drop|valley` and state the difference.

**"Is it saturated / what intensity range / is this channel empty?"** → `stats FILE --json --select c=N`: `saturated_fraction` > 0 means clipped pixels (at `saturation_level`: 2^bits − 1 when the file records the detector's bit depth, e.g. 16383 for 14-bit data in uint16, else the type's maximum; `saturation_basis` says which), `zero_fraction` near 1 an empty channel; `percentiles.p1`/`p99` give a display range; `histogram` the distribution. For signals (ABF, NMR, chromatograms) use `trace` statistics instead.

**"How many / which files in this share …?"** (questions across many files) → build a catalog once: `openreadout index SHARE -o IDX` (MCP: `openreadout_index`, call again while `complete` is false), then `openreadout search IDX "format=nd2 objective=60x" --json` and read `total` (or list `results[].path`). Fields: `format`, `family`, `sample`, `instrument`, `operator`, `technique`, `acquired` (dates: `acquired<2020`), `objective` (`63x`), `channel`, `x/y/z/c/t`, `images`, `events`, `scans`, `rate`, `size` (units: `1GB`, `20kHz`, `0.2um`), `status`, `pii`, `param.<name>`; [lab-shares guide](https://openreadout.github.io/openreadout/guides/lab-shares.html) has the rest. Damaged files: `search IDX "status=truncated|corrupt|unreadable"`; the full picture: `search IDX --health`.

**"Compare conditions / per-group numbers across a folder, with a sample sheet or plate map."** (mean intensity per condition, median FITC-A of the treated group, % CD4+ per donor, absorbance per dose) → `stats|trace|table|analyze gate DIR -r --sample-sheet SHEET --by condition --json` (MCP: `openreadout_batch` with `measure`, `sample_sheets`, `by`). Rows: `stats` image × channel (`mean`, `median`, …); `trace` sweep × channel; `table` FCS parameter (`median`, `mean`, `sd`; narrow with `--where parameter=FITC-A`) or plate well (`value`); `analyze gate --workspace W.wsp [--median Comp-FITC-A]` population (`count`, `percent_of_parent`, `median:…`). Check `joins[]` first: the key it chose, `unmatched_datasets`, `unmatched_sheet_rows`, `ambiguous` (fix with `--key COLUMN=file|stem|sample_id|well|barcode`). `summary.table` has n, mean, sd, median, CV % per group (channels/parameters kept apart; `--replicate well` averages replicates first; `--test welch --control ctrl` adds p-values). Rows with `error` failed; say so. Big folders: `-o rows.parquet` (JSON then omits rows) and `batch summarize rows.parquet --by …`. Files of the same sample across instruments: `link DIR --json` (evidence + confidence per link; report low-confidence links as uncertain; a raw run and its conversion that records no start time, such as an mzXML, are paired by `same_scan_series`: the scan count and the retention times and stored TICs of three spectra). Events of one FCS file meeting a condition: `table FILE --filter 'FITC-A > 1000' --count` (add `--compensate`, `--transform`; conditions on the values `table` returns; `filter.matched_rows` of `total_rows`); `--where` is only the batch-table row filter.

**"Is the acquisition still running / what has been acquired so far?"** → `info FILE --json` on a file the instrument is still writing (OME-TIFF, OME-Zarr, ND2, CZI) returns the complete planes plus `data.acquisition` = `{state: "in_progress", complete_planes, expected_planes?, missing, evidence}`, exit 0: it is not corrupt, do not tell the user it is. `check --planes` reads only the complete planes; `check` says `acquisition_in_progress` and `ok` covers the complete part only (check again when it ends). `state: "interrupted"` = the same unfinished structure but unchanged for longer than the live window (300 s, `--live-window`): an acquisition or copy that stopped. Thermo `.raw` cannot be read while growing (exit 4, the message says it was just modified). To follow a run: `watch DIR` (MCP: poll `openreadout_watch` with the returned `cursor`).

## Limits

- Read-only: no writing of vendor formats, by design (raw data is the primary record).
- Growing files: an ND2 copy cut short looks `in_progress` until the live window passes (only the file time tells them apart); a time-lapse slower than the window looks `interrupted` between frames. OME-TIFFs read as plain Z stacks until their OME-XML is written at the end.
- `index` flags personal data by field (operator names, e-mails, phone numbers, patient-like ids, dates of birth, free-text comments) but never stores values; the rules favour precision, so a name in an innocuously named field can be missed.
- Zeiss CZI: 12-bit JPEG, JPEG-lossless (id 3) and chunked-compressed subblocks are not decoded; lossy JPEG subblocks may differ from ZEN/libjpeg by a grey level or two; pyramid levels and regions are read per plane (`--level`, `--region`), `export` keeps the pyramid; multi-file support is inferred (no public sample). Super-resolved (PALM) renderings are their own image at the stored size with the rendering's pixel size (`extra.rendering_scale`); scenes whose subblocks vary along H, I, R, V or B (SIM phases, multi-track) are one image per coordinate (`extra.dimension_index`; channels absent at that coordinate read as 0 and are listed in `extra.absent_channels`).
- Nikon ND2: lossy-compressed frames (rare; no public sample) are not decoded (exit 6, metadata still readable). Legacy JPEG 2000 files (NIS-Elements 2.x) are read.
- Leica LIF: tile scans are stitched from stage positions (no registration or blending; later tiles overwrite overlaps), so they can differ from LAS X "Merged" images; per-tile offsets are in `info` `extra.tiles`. Lambda scans are exposed as channels (name carries the wavelength). FALCON FLIM raw photon data is detected but not decoded (exit 6; read the derived Intensity/Fast Flim child images instead). LOF/XLIF/XLEF/XLCF/XLLF are read: XLIF frames from .lof files and from single-page TIFF images (LAS X "export with metadata": open the .xllf or .xlif in the LeicaMetadata folder, keep the images one folder up); JPEG/PNG frames are decoded by the same rule unvalidated; BMP frames exit 6. `.lifext` sidecars are opened directly.
- Olympus OIR: open the `.oir`; continuation files `<name>_00001`, … next to it are read automatically and `check` names a missing one (exit 4). Lambda scans are exposed as channels (name carries the wavelength); the reference image is image 1. RGB and line-scan OIR files are unvalidated.
- Olympus VSI: open the `.vsi`; the pixels are in the `_<name>_/stack*/` folder next to it, which must be copied along (without it only metadata is available and `check` fails). Each stack (label, overview, each scan) is an image; whole slides are pyramids: read `--level N` (sizes in `info` `resolution_levels`); full-resolution planes over 4 GiB are read by `--region` only. The `.vsi` metadata was derived without a specification (confidence high: 11 datasets from 9 depositors): names, pixel size, Z step, channels (names, wavelengths, exposure), objective, camera, microscope and times are read; the rest is in `info --view full` `vendor.records` under numeric tags. `images[].extra.size_source` says where the image size came from (`tile_grid` = no size recorded: may include background padding).
- qPCR: Bio-Rad `.pcrd` is encrypted and refused (export RDML from CFX Maestro); LightCycler 480 `.ixo` gives the vendor's Cp and positive/negative call per well (`cq`, `amp_status`) for its absolute-quantification analysis only (Tm calling, genotyping are not read) and raw fluorescence in instrument units; a channel without a target name is its own target (`498-640`); `.lc` is not read. LightCycler 96 `.lc96p` reads as RDML plus the software's calls and replicate Cq mean/SD; wells it calls Negative have no Cq (`cq_stored` keeps the number the file writes). `.eds` files that keep only raw optical images (no multicomponent data) have no curves; Rotor-Gene `.rex` files store no Cq (use `analyze qpcr --cq`). Our `--cq` is a threshold method: close to, not identical with, the vendor's algorithm (the vendor's `cq` is what to report unless asked to recompute).
- Screening plates: standalone Opera `.flex` files are read (open the measurement folder for the plate, or one `.flex` for its well); Harmony `Index.ref.xml` with `.tiff.gz` planes is not read; tiled CellVoyager fields are not stitched; an ImageXpress folder without its HTD cannot say which planes are missing.
- OME-Zarr: pass the `.zarr` directory or a `.zip` of it; plates give one image per field, bioformats2raw collections one per series; label images are listed by `info --view structure`, not returned as images; Blosc bit-shuffle, int64 and float16 arrays exit 6; remote (http/s3) stores are not opened.
- Olympus OIB/OIF: open the `.oib`, or the `.oif` with its `<name>.oif.files` folder next to it (without the folder only metadata is available and `check` fails). Lambda scans are exposed as channels (emission band in `emission_range_nm`); line scans (XT) are planes whose rows are lines in time, and their reference images are image 1.
- Zeiss ZVI: derived without a specification (confidence high: 16 files from 12 depositors); 16-bit grey and 48-bit colour validated (8-bit and time series inferred: a note says so); uncalibrated axes have no pixel size; `acquired_at` is the first plane's time (Bio-Formats reports the second plane's).
- Imaris `.ims`: HDF5 (Imaris 5+) only; resolution levels via `check --planes --level N`; surfaces, spots and other Scene objects are listed, not decoded. HDF5 files of other kinds: `info --view structure` lists their structure; NWB files expose TimeSeries, ElectricalSeries (with each channel's electrode) and SpatialSeries under `acquisition/` and `processing/` as traces, and electrodes, units (plus a `units/spike_times` table), trials and SpikeEventSeries as tables; text columns are codes into `columns[].extra.categories`; PatchClampSeries and ImageSeries are listed only.
- FCS: histogram data sets (`$MODE` C/U) and bit-packed integers are described but not decoded (exit 6); `export` events are raw (no compensation or scaling applied; `table --compensate/--transform` applies them). FlowJo workspaces: transforms other than linear, log, logicle, biex and ArcSinh, derived parameters and non-OLS spectral unmixing exit 6 when a gate needs them.
- TIFF family: JPEG 2000 (Aperio 33003/33005), JPEG XL, WebP and old-style JPEG tiles are decoded (LERC is not: exit 6); lossy JPEG 2000 is within 1 grey level of OpenJPEG, not bit-exact. Planes larger than 4 GiB (whole-slide level 0) are not read into memory, and pyramid levels are listed, not read. A plain TIFF without microscopy metadata shows its pages as Z (a note says so). Multi-file OME-TIFF siblings must be in the same folder.
- MetaMorph: open the `.nd` to read a whole series (stage positions are images, wavelengths channels, time points T, STK planes Z); its STK/TIFF files must sit next to it with their original names (`<stem>_w1<wave>_s1_t1.TIF`), and `check` names missing ones. `acquired_at` is the `.nd` start time in the acquisition PC's local time (no zone). Only uncompressed STK stacks are read. A single STK or MetaSeries TIFF can also be opened on its own.
- Nikon NIS-Elements TIFF exports (`…xy01c1.tif`): opening one file reads every file of the export in that folder (one image per `xy` position; `c`, `z`, `t` from the name tokens; channels are named `c1`, `c2`, …); the pixel size comes from a private tag whose meaning is inferred; channel names and objective in the LV metadata blocks are not decoded.
- Hamamatsu DCIMG: one file is one image with frames as T (sibling `_000_001.dcimg` files are not merged into Z); rows come in stored order (Bio-Formats flips them); the four pixels ORCA-Flash cameras overwrite in the centre row are replaced by their stored values; `info --view full --all-frames` gives each frame's camera counter and UTC time, and `check` flags dropped frames (`frame_counter_gap`).
- Electron microscopy: MRC complex (FFT) modes, DM complex/RGB images, SER complex elements and NCEM/Berkeley EMD are described but not decoded (exit 6); Velox EDS spectra are traces (`trace`, energy in keV) and EDS spectrum images are an image with one channel per energy channel (`stats --select c=N`, `preview --select c=N` for a map); Velox STEM-EELS spectrum images likewise, one channel per energy-loss channel (eV in `extra.energy_axis`, counts as stored). MRC planes are returned in file order (MAPC/MAPR/MAPS not applied); ISPG 0 files are image stacks (T) except `.map`/`.rec`, which are volumes (Z). SER pixel sizes assume metre calibrations (the `.ser` stores no unit).
- Electrophysiology: pass a recording directory to read it as one data set — a Neuralynx session folder (channels on one sample grid become one multi-channel trace; events and spikes are tables), a SpikeGLX run folder (one trace per stream: AP, LF, NI), a Blackrock NSx + NEV folder, an Intan `info.rhd`/`info.rhs` + `.dat` folder. Every file keeps its own clock (`extra.source_file(s)` names it); streams are not resampled or aligned on sync pulses. A folder with any other kind of file in it is walked file by file instead. Plexon PL2 is decoded from our own hex-dump analysis (no independent reader exists), so treat PL2 values as lower confidence than PLX. ABF command waveforms are reported as epoch tables, not synthesized.
- mzML/mzXML/imzML: arrays other than m/z and intensity (ion mobility, charge, noise) are listed, not returned; byte-shuffled/dictionary zstd and the truncation+prediction encodings exit 6. `.mzML.gz`/`.mzXML.gz` (as PRIDE/MetaboLights serve them) are read directly — do not decompress them first; each open decompresses the file once in memory (`info` on a 100 MB `.gz` takes about a second), so batch several questions into one command where you can. mzMLb (`.mzMLb`, HDF5) is format `mzmlb` and behaves like mzML. Chromatograms are `traces[]` (`sample_rate_hz` 0, a `time` channel in seconds): `trace FILE --trace N`, `export FILE --format csv --trace N`.
- Bruker timsTOF `.d`: TDF compression types 1 (LZF) and 2 (zstd), TSF line and profile spectra, MALDI spots (`extra.maldi_*`); m/z and 1/K0 apply the file's MzCalibration and TimsCalibration per frame (temperature-compensated; validated to 0.065 ppm and 5e-13 against vendor-library conversions; `info` says `mz_conversion`), and a model type never validated falls back to the acquisition-range approximation with a note and a `check` warning; spectra are raw sums of TOF bins per MS1 frame, DDA-PASEF precursor or DIA-PASEF window (`native_id` says which), not centroided; prm-PASEF frames are summed whole.
- Bruker NMR: 4D+ processed files are listed, not read; non-uniformly sampled `ser` rows are returned as acquired (no reconstruction); the 2^NC time-domain scaling is inferred, not documented.
- Varian/Agilent NMR: `datdir` processed data (phasefile) are listed, not decoded; block scale factors are reported, not applied; int16 FIDs are covered by synthetic tests only.
- JEOL NMR: 3D+ and small-submatrix layouts, TPPI and envelope axes exit 6; string parameters are cut at 16 characters in the file (`sample_id`).
- JCAMP-DX: peak assignments and JCAMP-CS structure blocks are listed, not decoded.
- FT-IR/Raman: OPUS 3D series are unvalidated and report blocks are listed; OMNIC `.srs` series exit 6; WiRE property-set keys the file does not name appear as `#<number>` in `info --view full`, and `laser_power_percent` is the ND-filter transmission, not mW; PerkinElmer `.sp` UV-Vis files are unvalidated.
- Chromatography: ChemStation `.ch` versions other than 30/81/130/179/181, `.REG` registers and method files are listed, not decoded; a `.D` directory's own peak report (`Report.TXT`, MSD `RESULTS.CSV`) is `table PATH` (`vendor_peaks`: the vendor's RT, area, height, area %) — quote it for "what did ChemStation integrate", use `analyze peaks` for our own integration; Waters MRM/SIR functions are tables/traces (spectra only for scanning functions); Shimadzu LC-MS (TLM) data are not decoded; ANDI/MS MS level is always 1.
- Agilent OpenLab CDS: open the injection's `.dx` (a `.rx` opens its `.dx`; a `.rslt` result-set folder is not one data set: `batch 'set.rslt/*.dx'`). `traces[]` = detector signals (`FID2B`, `DAD1D,Sig=228,4 Ref=360,100`), then instrument curves (pump pressure, flow, solvent ratios, temperatures; `extra.axis.quantity` `time`); `extra` has `sample_name`, `vial`, `injection_volume` (µL), `method`, `operator`, `acquired_at`. When the `.rx` of the same name is beside it, `tables[0]` `vendor_peaks` is the vendor's own integration (RT, area in `pA·s`/`mAU·s`, height, area %, limits, baseline code, `signal`, `trace`): report these for "what did the software integrate"; `analyze peaks` re-integrates (its default `auto` baseline matches OpenLab on GC runs whose peaks ride a solvent tail: median area 0.5 %). DAD spectra parts (`.UV`), compound amounts and calibration are not read.
- Shimadzu LabSolutions `.lcd`: chromatograms, status traces and the PDA field (`PDA max plot`, `PDA spectra` one channel per wavelength, mAU) are `traces[]`; LabSolutions' own peak tables are `table PATH` (`vendor_peaks`). LC-MS data: MRM and SIM records are spectra run 0 (`analyze chromatogram --transition Q1>Q3`, `spectra`), polarity `unknown`; full-scan and product-ion-scan spectra are refused (exit 6: convert with msconvert), their TIC and retention times still in `spectra`/`analyze chromatogram --tic`.
- Thermo Chromeleon 7 `.cmbx` archive: `traces[]` = every injection's signals (`<injection> / GC_1`, `ED_1`, `Pump_1_Pressure`; unit, device and recorded range from the sequence file; calibration standards a processing method holds have `extra.fixed_injection`); pick an injection by `extra.injection` / `injection_index`. Chromeleon's own stored peaks are `tables[0]` `vendor_peaks` (retention time, area, height, limits, component; `injections` is the next table: position, volume, inject time); 3D PDA fields are traces with one channel per wavelength; audit trails and methods are attachments. MS data is an embedded Thermo `.raw` (the note names the member to extract). A damaged member is exit 4 on that trace and a `bad_member` finding in `check`.
- Waters Empower `.arw` ASCII export: one trace (`<SampleName> / <Channel>`), the exported header fields in `extra.fields`; no unit in the export; 3D PDA exports exit 6 (export AIA/netCDF instead, read as `andi-chrom`).
- Thermo `.raw`: file versions 63, 64 and 66 are validated (LTQ Orbitrap, Orbitrap Velos, Exactive, Q Exactive family, Orbitrap Fusion Lumos, TSQ Vantage SRM); LC detectors recorded in the same file are `traces[]` (file versions 63/64/66): DAD/UV channels (`UV_VIS_1`, mAU, `channels[0].extra.wavelength_nm`; an Accela PDA's channels are one trace `Accela PDA Detector` with channels `Channel A`/`B`/`C` and their wavelengths), the PDA field (`3DFIELD spectra` / `Accela PDA Detector spectra`: one channel per wavelength; `trace --first K --count 1` = the UV spectrum at sample K; `analyze chromatogram`/`analyze peaks --trace T --channel C` = the chromatogram at that wavelength; the absorbance maximum at 280 nm: `trace FILE --trace T --channel <index of 280 nm>` → `argmax_axis_value`), charged-aerosol (`CAD_1`), and pump pressure/temperature logs (irregular, `time` channel). Units are inferred (mAU); the Accela PDA values and times equal an independent msconvert conversion exactly, the Vanquish DAD is checked by internal consistency only (see `self formats`); a converter's `UV 1` chromatogram may be timed one sample later than our channel A; scan filters cover the common tokens only (no SIM windows, multiplexing or FAIMS); ion-trap profile scans have not been validated. Centroid lists keep the reference/lock-mass peaks the file flags, as current vendor-library conversions do; an mzML made before about 2021 left them out, so its peak counts can be lower: that is not a reading error. Precursor charge is reported only when the file records one (not on LTQ ion-trap or TSQ SRM scans).
- Agilent MassHunter `.d`: scan-index layouts 5 and 6 and the 6560 ion-mobility layout are validated (6410 QQQ MRM, dynamic MRM, full, product-ion, neutral-loss scans and quadrupole profiles; 6200 TOF; 6540/6550 and B.08 Q-TOF; IM-MS drift-bin spectra with `extra.drift_time_ms`, `extra.frame`, `extra.drift_bin`); an MRM scan is a spectrum of its transitions (Q1 = `precursor_mz`, Q3s = its m/z); neutral-loss scans give the loss as `extra.neutral_loss_mz`, not a precursor; `precursor_mz` is each MS/MS scan's own value (msconvert averages scans that share a precursor); Q-TOF LZF profiles are checked against the index only; traces are TIC, BPC (per frame in IM-MS data), then each DAD/pump/oven signal; `DAD1.sd/.sp` spectra and `MSPeriodicActuals.bin` are listed, not decoded.
- Waters MassLynx `.raw`: TOF and quadrupole full-scan spectra are validated (12-, 8- and 6-byte layouts, centroid and continuum; SYNAPT G2/G2-Si/XS, Synapt MS, Xevo, ACQUITY SQD; DDA, MSe with `extra.mse_high_energy`, product-ion scans with precursors); all functions' scans are merged by retention time into one run (`native_id` `function=F process=0 scan=S`; `--scan N` counts within the first scanning function); the lock-spray `REFERENCE` function is returned as MS1 with `extra.lock_mass_reference` and its flagged peak as `extra.lock_mass_peak_mz`, lock-mass correction is not applied (files MassLynx already corrected read as stored); ion-mobility and SONAR drift bins (`.cdt`) are not read (their drift-summed spectra are); PDA functions are traces.
- Sciex `.wiff`: needs the `.wiff.scan` beside it for spectra; `.wiff2` exits 6 (encrypted); MRM cycles are one spectrum per precursor (`precursor_mz` = Q1, m/z = Q3, `transition=K` in the native id; scheduled and older Analyst unscheduled methods); LC device channels (pressure, flow) are traces named `LC device K: …`; TripleTOF spectra are the stored TDC profiles (not the vendor's peak-picked centroids an msconvert export holds); scan types other than MRM, TOF MS and TOF product ion are listed, not decoded.
