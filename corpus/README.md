# Test corpus

The corpus is the durable asset of this project: public instrument files with recorded provenance and licenses, plus ground truth produced by independent readers, so every parser change is checked against reality.

- `manifest.toml` — one `[[file]]` per test file: `id`, `format`, `tier`, `url`, `size`, `sha256`/`md5` when the source publishes one, `license`, `source`, `attribution`, `notes`, and `oracle_skip` when the oracle is known to disagree and why. `pixel_tolerance = N` (lossy codecs) lets a plane pass when every sample is within N of the oracle's decoded plane, stored raw next to the file as `<id>.oracle/image<i>_c<c>_z<z>_t<t>.bin`. `role = "part"` marks the following parts of a multi-file document (read through their master, not on their own). `filename` may contain a sub-directory (multi-file OME-TIFF sets keep their original names so their cross-references resolve). A zip with `unpack = true` is extracted into the corpus directory after download; entries with `bundle = "<zip id>"` are members of it (not downloaded themselves, but checked and recorded). `lossy = true` marks JPEG-compressed files, whose planes may differ from the oracle's decoder by IDCT rounding; the harness then compares plane means (within 0.05) when a hash differs.
- Synthetic fixtures (`source = "synthetic (pylibCZIrw)"`, ids `synthetic-*`) have no `url` and no `sha256`: `cd oracle && uv run python make_czi_fixtures.py --out <corpus dir> --oracle` regenerates them, their oracle JSONs and the tolerance sidecars (pylibCZIrw writes fresh GUIDs each run, so file hashes change; pixel hashes do not). `cargo xtask corpus fetch` reports them as present or missing instead of downloading.
- `oracle/flow/<id>.json` — flow-analysis ground truth from `oracle/flow.py` (FlowKit/flowutils): population counts for each gating file (`role = "analysis"`: FlowJo workspaces and Gating-ML documents, paired with FCS inputs there, not data sets themselves) and compensated/transformed values (`<fcs id>.comp.json`). Checked by `tests/flow.rs`. Committed.
- `oracle/<id>.json` — ground truth from `oracle/gen.py` (czifile, liffile, nd2, tifffile; Bio-Formats as arbiter): geometry, pixel type, physical sizes, channel names, per-plane xxh3-128 hashes, and for pyramidal CZIs the hashes of each downsampled level (`images[].levels[]`). For mass-spectrometry files (Thermo `.raw`) no third-party reader of the raw file is run: the manifest pairs each input with the depositing lab's own mzML/mzXML (`role = "oracle-export"`, same `id`), and the oracle records every scan of that export (scan number, MS level, polarity, retention time, filter, precursor, charge, activation, point count, xxh3-128 of m/z as f64 LE and intensity as f32 LE, first points); when the export holds no spectra (SRM runs), it records every chromatogram instead (kind, Q1/Q3, point count, hashes of times and intensities, all and non-zero only). Committed.
- `files/` — the downloads. Gitignored. `OPENREADOUT_CORPUS_DIR` overrides the location.
- Bundles: an entry with `role = "bundle"` is a zip that `corpus fetch` extracts into `files/<id>/` (dropping `strip` leading path components); entries with `bundle = "<id>"` are files or directories inside it (Bruker experiment directories). Their oracle JSON is named after the entry id (`oracle/gen.py --id ID PATH`, or `oracle/gen_manifest.py FORMAT…`).

Tiers (cumulative): `smoke` (~1 GB, runs in CI), `standard` (~20 GB), `full` (~65 GB; multi-GB stress files); exact sizes on the project-health page (`cargo xtask health`). `hold` entries are never fetched automatically.

Held-out set: entries on the `heldout` tier (inputs `role = "heldout"`, with their paired exports, companions and bundles on the same tier; `license_checked` says where each licence was read) come from sources the development corpus does not use and measure whether the readers generalize. They are fetched only with `cargo xtask corpus fetch --tier heldout` (into `files/heldout/`), their ground truth is `oracle/heldout/<id>.json` (`ORACLE_OUT=../corpus/oracle/heldout uv run python gen.py --id <id> <path>`), and they must never be used to develop or debug a reader: no provenance log may cite them, and no development file may come from the same source record (`cargo xtask heldout-check`). Rules and how to add files: `docs/benchmark/heldout.md`.

```bash
cargo xtask corpus fetch --tier standard      # resumable, checksum-verified
cargo xtask corpus status
cd oracle && uv run python gen.py ../corpus/files/<file>      # (re)generate ground truth
cargo test -p openreadout-corpus-tests --features corpus --profile corpus -- --nocapture
```

Adding a file: only with a recorded, redistribution-compatible license (CC0, CC-BY, BSD, EMBL-EBI terms) or explicit written permission; nothing medical or patient-identifiable; never a vendor demo dataset. Sources used today: MetaboLights and PRIDE (EMBL-EBI terms; Thermo `.raw` with the depositors' conversions), OpenSlide test data (CC0), Zenodo records (CC-BY-4.0), OME sample images (CC-BY-4.0 per directory), Allen Institute aicsimageio test resources (BSD-3), EMBL-EBI BioStudies/BioImage Archive (EMBL-EBI terms), the `nd2` package's test bundle (BSD-3), pyABF sample data (MIT), NeuralEnsemble ephy_testing_data on G-Node GIN (database ODbL-1.0, contents CC-BY-SA-4.0; clinical folders excluded), nmrXiv studies (CC0-1.0 / CC-BY-4.0 per project), the nmrglue test archive (BSD-3), R. J. Lancashire's public-domain JCAMP-DX test files. NIST WebBook JCAMP-DX spectra are **not** used: their files state "Collection (C) copyright by the U.S. Secretary of Commerce on behalf of the United States of America. All rights reserved." Plate-reader exports come from allotropy's test fixtures (MIT, pinned to tag v0.1.146) and two public repositories (MIT, CC0); their entries may carry `plate_counts_only = "<reason>"`, which makes the harness compare value and well counts per detection mode but not the value hash.

Electrophysiology formats that span files keep them side by side under one stem: a SpikeGLX `.bin` with its `.meta` (`role = "companion"`), a Blackrock `.ns2` with the `.nev` that scales it. Their oracle JSON is named after the entry `id` (the file name with dots replaced by dashes), which the corpus test looks up before the file stem.
